# 持仓面板 —— 杠杆 / 未实现盈亏 显示口径 & Tooltip 方案
> 决策文档。2026-07-02。范围:持仓面板(`Positions.tsx`)的 **Leverage 徽标**、**Unrealized PnL (ROE %)**、以及配套 tooltip。 **结论先行:算法保持不变,仅新增 tooltip 说明。** 下面给出三方对比、我们现状、以及待新增的 tooltip 文案与落点。
---
## 1. 背景:一次差点改错的排查
起因:MSOL SHORT 面板显示 **161.48x**,但用户实际是用 `$200 名义 / 2 USDC 保证金 = 100x` 开的。核对后发现杠杆分母**扣了待结算 funding**:`200 / (2 − 0.7615) = 161.48x`。于是产生疑问:杠杆该不该扣 funding?该不该含未实现 PnL?调研了 GMX 与 Hyperliquid 后**决定维持现状**,理由见 §4。
---
## 2. 三方口径对比(GMX / Hyperliquid / FX100)
### 2.1 杠杆(Leverage)
|  | 杠杆 = | 随价格动? | 随 funding 动? | 本质 |
|---|---|---|---|---|
| **Hyperliquid** | **用户设定值**(1~max 的整数,开仓锁定) | ❌ | ❌ | margin-first:先选杠杆 → 派生所需保证金 `margin = notional / leverage` |
| **FX100(现状)** | `sizeInUsd / (collateral − pendingFunding)` | ❌ | ✅ 慢漂 | collateral-first:先有抵押 → 派生杠杆 |
| **GMX** | `sizeInUsd / (collateral + unrealizedPnL − funding − borrow)` | ✅ | ✅ | 全动态净权益;PnL 是否计入有设置开关 |
- **Hyperliquid**:杠杆是**输入**、开仓即固定,不随价格/时间抖动;风险变化只体现在 **Liq Price / 保证金占用**上(Cross 且余额充裕时 Liq Price 显示 **N/A**)。源:HL 文档 *Margining*、*Liquidations* —— "Leverage can be set by a user to any integer between 1 and the max leverage… Leverage is only checked upon opening a position."
- **GMX**:前端 `getLeverage`(`gmx-interface .../positions/utils.ts`)= `sizeInUsd / (collateralUsd + (pnl ?? 0) − pendingFundingFeesUsd − pendingBorrowingFeesUsd)`。**funding/borrow 无条件扣;PnL 通过 "Include PnL in Leverage" 开关可含可不含**。合约侧清算判定(`gmx-synthetics/PositionUtils.sol:406`)用的净抵押 = `collateral + pnl + priceImpact − 所有费`。
- **FX100**:`getPositionDisplayLeverage`(`_position/liqPriceUtils.ts:59`)取链上 `leverage` bps(= `size/(col−pendingFunding)`)。**扣 funding、不含 PnL、与实时价无关**。介于 HL(最稳)与 GMX(最动)之间。
### 2.2 未实现盈亏(Unrealized PnL)
|  | Unrealized PnL = | 含 funding? | 含平仓 impact / 费? |
|---|---|---|---|
| **Hyperliquid** | `side × (mark − entry) × size` | ❌ | ❌ |
| **FX100(现状)** | LONG `sizeTokens×oracle − sizeUsd` / SHORT 反向(正盈利再按池 PnL 上限 cap) | ❌ | ❌ |
| **GMX** | 纯价格 PnL(`getPositionPnlUsd`) | ❌ | ❌ |
→ **三家完全一致**:Unrealized PnL 都是**纯价格盈亏**,funding 单列、平仓 impact/费只在平仓实现。FX100 这块无需任何改动。
### 2.3 PnL 百分比(ROE %)
|  | 分母 |
|---|---|
| **Hyperliquid** | 初始保证金(ROE) |
| **FX100(现状)** | 初始/毛保证金 `collateral`(`−0.27 / 2 = −13.5%`) |
| **GMX** | 初始 collateral |
→ **三家一致**(都用初始保证金,不用净权益)。FX100 这块也无需改动。

## 3. FX100 现状(精确公式 + 代码落点)
| 面板项 | 公式 | 代码 |
|---|---|---|
| **Leverage 徽标** | `sizeInUsd / (collateral − pendingFunding)`,扣 funding、不含 PnL、价格无关 | `_position/liqPriceUtils.ts:59` `getPositionDisplayLeverage`(链上 `leverage` bps) |
| **Unrealized PnL** | 纯价格 PnL(见 2.2);正盈利按池 PnL 上限 cap | `state/derived/positions.ts`(§FRONTEND_VERIFICATION §2.9c) |
| **PnL %** | `PnL / 毛保证金` | `formatPnlPercent` |
| **Est. Liq Price / Prot.** | SDK `getLiquidationPrice` 非同币分支(net collateral 含 impact、扣 funding+闭仓费) | 已有 tooltip `renderLiquidationProtectionTooltip` |
| **Funding** | 待结算资金费,自动结算进保证金,无 claimable | 已有 tooltip `marketData.tooltipFunding` |
**关键现象(务必在 tooltip 讲清)**:高杠杆 + 小保证金时,funding 占抵押比例大 → 显示杠杆会明显 **高于开仓杠杆**。示例:开仓 100x(200/2),funding 吃掉 2 的 38% → 显示 **161x**。这不是 bug,是"当前净抵押下的真实杠杆",但会让用户困惑,需要 tooltip 解释。
---
## 4. 决策:维持算法不变,仅加 tooltip
**为什么不改成 GMX 式(加 PnL 全动态)**:
- Hyperliquid(头部 DEX)刻意让仓位杠杆**固定=用户设定值**,对散户更直观、少困惑;风险信号交给 **Liq Price**。加 PnL 会让 FX100 偏离 HL 体验、且在真 feed 市场引入每块抖动。
- FX100 现状(扣 funding、不含 PnL)已经是"价格无关"的稳定杠杆,精神上更接近 HL,而非 GMX。
- 纯显示口径,**不涉及资金安全**(链上清算引擎有独立的净抵押数学,与面板数字无关),没有必须对齐 GMX 的硬理由。
**因此**:Leverage 与 Unrealized PnL 的**计算保持现状**。唯一动作 = **补 tooltip**,把口径讲清楚,消除"100x 怎么显示成 161x""浮盈亏为什么 ≠ 平仓能拿回多少"这类困惑。

## 5. 待新增 Tooltip(文案 + 落点)
现状:**Funding、Liq Price/Prot. 已有 tooltip;Leverage、Unrealized PnL 没有。** 需补后两者,风格对齐现有(`SimpleTooltip` + `CircleHelp` 图标 + `locales/*.ts` 文案 key)。
### 5.1 Leverage tooltip(新增)
**挂载点**:市场徽标旁的杠杆数字(`Positions.tsx` 徽标渲染处;桌面表格 + 移动卡片两套布局都要加)。
**建议文案 key**:`marketData.tooltipLeverage`
```plain text
EN: Leverage = position size ÷ net collateral (your margin minus pending funding).
    It shows your current standing leverage, not necessarily the leverage you opened
    at — as funding accrues it is deducted from margin, so the number can rise over
    time (most visible on small margins). Unrealized PnL is not included, so this figure
    does not move with price. Your actual liquidation risk is reflected in the Liq. Price.
```
```plain text
ZH: 杠杆 = 仓位名义 ÷ 净抵押(保证金 − 待结算资金费)。显示的是当前净抵押下的杠杆,
    不一定等于你开仓时选的杠杆——资金费会从保证金里扣除,所以该数字可能随时间升高
    (保证金越小越明显)。不含未实现盈亏,因此不随价格抖动。真实清算风险请看清算价。
```
### 5.2 Unrealized PnL tooltip(新增)
**挂载点**:PnL (ROE %) 列表头 / 移动卡片 PnL 区块(`Positions.tsx:1049` 附近的 `unrealizedPnl` 标签旁)。
**建议文案 key**:`marketData.tooltipUnrealizedPnl`
```plain text
EN: Unrealized PnL is the pure price gain/loss (oracle price vs entry) on your position
    size. It excludes funding, closing fees and price impact — funding is shown in its
    own column, the rest apply only when you close. What you'd actually receive on close
    ≈ margin + this PnL + close price impact − closing fee − pending funding, so it can
    differ from the PnL shown here. The % is this PnL relative to your initial margin (ROE).
```
```plain text
ZH: 未实现盈亏 = 仅按价格算的浮动盈亏(oracle 价 vs 开仓价),不含资金费、平仓费与
    价格冲击——资金费在它自己那一列显示,其余只在平仓时实现。真正平仓能拿回 ≈ 保证金
    + 该盈亏 + 平仓冲击 − 平仓费 − 待结算资金费,因此可能与这里显示的浮盈亏不同。
    百分比 = 该盈亏 ÷ 初始保证金(ROE)。
```
### 5.3 已有 tooltip(仅登记,不改)
- **Funding**:`marketData.tooltipFunding` — "This position's funding settles automatically into margin…"
- **Liq Price / Prot.**:`renderLiquidationProtectionTooltip(...)` + `orderRecords.liquidationProtectionTooltip`
