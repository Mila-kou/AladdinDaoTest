## 一、Oracle 体系架构总览
### 1.1 三种 Provider 及各自角色
FX100 实现了三种 `IOracleProvider`，每个 token **同时只启用一种**作为主 oracle，存储在 `DataStore` 的 `ORACLE_PROVIDER_FOR_TOKEN` 键中。

**关键设计约定**：Pyth 在 FX100 中扮演**双重角色**：
1. 作为参考价格用于 2% 偏差校验（`PythPriceFeedUtils`，与主 provider 无关）
2. 可被升格为主 provider（治理操作，需时间锁）
### 1.2 正常流程（Data Streams 为主）
```plain text
Keeper 拉取 Chainlink Data Streams 签名报价
        ↓
Oracle.setPrices()
        ↓
_validatePrices() per token：
  1. 价格新鲜度检查（MAX_ORACLE_PRICE_AGE）
  2. 时间戳调整（仅 Data Streams，shouldAdjustTimestamp=true）
  3. Pyth 参考价偏差校验（MAX_ORACLE_REF_PRICE_DEVIATION_FACTOR）
  4. 多 token 时间戳跨度检查（MAX_ORACLE_TIMESTAMP_RANGE）
        ↓
价格写入 Oracle 状态，可供订单/清算/ADL 使用
```
### 1.3 Pyth 参考价偏差校验逻辑
```solidity
// Oracle.sol:293
if (!provider.isPythOnChainProvider()) {         // Data Streams → true，Pyth 主 → false（跳过）
    (bool hasRefPrice, uint256 refPrice) =
        PythPriceFeedUtils.getPriceFeedPrice(dataStore, token);
    if (hasRefPrice) {                            // 未配置 Pyth feed → false（跳过）
        _validateRefPrice(token, price.min, refPrice, maxDeviation);
        _validateRefPrice(token, price.max, refPrice, maxDeviation);
    }
}

// _validateRefPrice
diff       = |DataStreamsPrice - PythPrice|
diffFactor = diff × 1e30 / PythPrice            // Precision.toFactor
if (diffFactor > MAX_ORACLE_REF_PRICE_DEVIATION_FACTOR) → revert
```

## 二、Provider 切换机制详解
### 2.1 切换流程与时间锁真实行为
**没有自动 fallback。** 切换需要 `CONFIG_KEEPER` 角色手动调用 `Config.setOracleProviderForToken()`，Oracle.sol 严格校验提交时使用的 provider 必须与 DataStore 中配置的一致（`Oracle.sol:270`），否则 revert `InvalidOracleProviderForToken`。
时间锁检查逻辑（`Config.sol:125-130`）：
```solidity
if (
    block.timestamp - store.getUint(FX100Keys.oracleProviderUpdatedAt(token, newProvider))
        < store.getUint(FX100Keys.ORACLE_PROVIDER_MIN_CHANGE_DELAY)
) { revert OracleProviderMinChangeDelayNotYetPassed(token, newProvider); }
```
**关键细节**：延迟检查的 key 是 `oracleProviderUpdatedAt(token, newProvider)`——即「上次把 \*newProvider\* 设为该 token 主 oracle 的时间」，而非「上次切换的时间」。

**实际含义**：时间锁防止的是**来回反复横跳**（A→B→A→B），不是首次紧急切换。只要提前把 ChainlinkPriceFeedProvider 部署并 enable（但不激活），紧急时可以立即切换，无需等待。
### 2.2 切换步骤（Config Keeper 侧）
```plain text
步骤 1：确认 ChainlinkPriceFeedProvider 已被 enable
  Config.setOracleProviderEnabled(chainlinkPriceFeedProvider, true)
  → 要求 CONFIG_KEEPER，应在部署时预先完成

步骤 2：切换主 oracle
  Config.setOracleProviderForToken(oracle, WNT, chainlinkPriceFeedProvider)
  → 若 ChainlinkPriceFeedProvider 从未被激活：立即生效
  → 若此前激活过且在 DELAY 窗口内：revert，必须等待

步骤 3：Keeper 侧同步更新提交参数
  params.providers[i] = chainlinkPriceFeedProvider
  （Oracle.sol:270 严格校验：提交的 provider ≠ 配置值 → revert）
```
**无紧急绕过路径**：代码中不存在 guardian 角色或 pause 机制可以绕过时间锁。`CONFIG_KEEPER` 是唯一切换权限，时间锁检查无例外分支。
### 2.3 没有自动 fallback
**这是当前最核心的架构约束。**
`Oracle.sol:279` 对 `getOraclePrice()` 的调用是**裸调用，无 try/catch**：
```solidity
OracleUtils.ValidatedPrice memory validatedPrice = provider.getOraclePrice(token, data);
```
若主 provider 失败，整个 `setPrices()` 直接 revert，不会尝试备用 provider。

### 2.4 宕机期间协议完全冻结
宕机分两种触发方式：
- **情况 A**：Data Streams 停止更新，价格超过 `MAX_ORACLE_PRICE_AGE` → `MaxPriceAgeExceeded`
- **情况 B**：Data Streams 价格异常，与 Pyth 偏差 \> 2% → `MaxRefPriceDeviationExceeded`
两种情况均导致：
```plain text
开仓 / 加仓                     → ❌ revert（oracle 错误不被 try/catch 捕获，直接透传）
平仓 / 减仓                     → ❌ revert
清算（LiquidationHandler）       → ❌ revert（最危险，见 §2.4）
ADL（AdlUtils）                  → ❌ revert
LP 存取款（若含 oracle 校验）    → ❌ revert
限价单/止损单执行               → ❌ revert（非 freeze，是 revert，需 keeper 重试）
```
注意：oracle 错误在 `OrderHandler.validateNonKeeperError()` 中被识别为**非用户错误**，直接 revert 而非 freeze 订单。订单本身不受影响，等恢复后可以继续执行。
### 2.5 切换至 Pyth 主 oracle 后 2% 校验消失
```plain text
正常状态：
  Data Streams（isPythOnChainProvider=false）→ 触发 Pyth 参考价校验 ✅

切换后：
  Pyth 主（isPythOnChainProvider=true）→ 跳过参考价校验 ❌
```
此时 Pyth 价格本身成为唯一信任源，无任何链上交叉验证。Pyth 是 pull 模型，若 Keeper 不提交新价格，链上 Pyth 价格同样会过期。
**最优备用策略**：切换至 `ChainlinkPriceFeedProvider`（链上聚合，无 Keeper 依赖，`isPythOnChainProvider=false`），Pyth 参考价校验仍然生效，形成双链上 oracle 交叉验证。
### 2.6 清算冻结风险（最高优先级）
极端行情往往与 oracle 故障同时发生（高负载、网络拥堵、价格剧烈波动均可触发 Data Streams 异常）。
```plain text
场景：ETH 暴跌 25%
  ├─ 大量仓位资不抵债
  ├─ Data Streams 同期出现故障（情况 A 或 B）
  ├─ 清算 Keeper 无法执行清算（revert）
  ├─ 仓位继续亏损，账面损失扩大
  └─ Data Streams 恢复后，仓位若已严重资不抵债：
       └─ 清算所得 < LP 应承担损失 → LP 净值受损
```
当前无任何链上 circuit breaker 在 oracle 故障期间保护 LP。

## 三、Pyth 参考 Feed 未配置场景
### 3.1 行为
```solidity
// PythPriceFeedUtils.sol:20
bytes32 priceFeedKey = dataStore.getBytes32(Keys.pythPriceFeedKey(token));
if (priceFeedKey == bytes32(0)) {
    return (false, 0);  // hasRefPrice = false → 校验跳过
}
```
若某 token 未配置 `pythPriceFeedKey`，Data Streams 价格**无任何偏差校验**，仅凭 Keeper 签名授权通过。

## 六、测试用例
### 6.1 集成测试（INT-ORACLE，扩展现有 09 之后）
### INT-ORACLE-10：无 Pyth feed 配置 → 2% 校验跳过，任意价格被接受
- **前置条件**：Token C 未配置 `pythPriceFeedKey`
- **操作**：提交偏差 50% 的 Data Streams 价格（通常会被 2% 校验拦截）
- **期望**：价格被接受，无 revert
- **验证目标**：`R-ORA-05`
### INT-ORACLE-11：Pyth feed 存在但已过期（超过 heartbeat）→ 2% 校验跳过
- **前置条件**：Token A 配置了 Pyth feed，但 `publishTime + heartbeat < block.timestamp`
- **操作**：提交偏差 50% 的 Data Streams 价格
- **期望**：`getPriceNoOlderThan` 抛错被 try/catch 捕获 → `hasRefPrice=false` → 价格被接受
- **验证目标**：`R-ORA-06`
### INT-ORACLE-12：切换至 Pyth 主 oracle → `isPythOnChainProvider=true` → 2% 校验完全消失
- **前置条件**：将 Token A 的 provider 切换为 `PythPriceFeedProvider`（mock）
- **操作**：Pyth 主 oracle 提交任意价格（无 Data Streams 参与）
- **期望**：价格被接受，偏差校验不触发
- **验证目标**：`R-ORA-04`
### INT-ORACLE-13：价格恰好在 2% 边界上 → 被接受
- **前置条件**：Pyth 参考价 = 100，MAX_DEVIATION = 2%
- **操作**：提交价格 = 102（偏差恰好 2%）
- **期望**：接受（`diffFactor == maxFactor` 时不 revert）
- **验证目标**：边界值测试
### INT-ORACLE-14：价格超出 2% 边界 1 wei → 被拒绝
- **前置条件**：Pyth 参考价 = 100，MAX_DEVIATION = 2%
- **操作**：提交价格使 `diffFactor = maxFactor + 1`
- **期望**：`revert MaxRefPriceDeviationExceeded`
- **验证目标**：边界值测试，精度验证
### INT-ORACLE-15：Chainlink Price Feed 主 oracle → 2% 校验仍有效
- **前置条件**：将 Token A 的 provider 切换为 `ChainlinkPriceFeedProvider`（mock），配置 Pyth feed
- **操作**：提交偏差 10% 的价格
- **期望**：`revert MaxRefPriceDeviationExceeded`（校验未因切换而消失）
- **验证目标**：`R-ORA-04` 的改进方案验证
### INT-ORACLE-16：多 token 中部分 token 无 Pyth feed → 仅无 feed 的 token 跳过校验
- **前置条件**：Token A 有 Pyth feed，Token C 无 Pyth feed
- **操作**：同时提交两个 token 价格，Token A 偏差 50%，Token C 偏差 50%
- **期望**：Token A 的价格触发 `MaxRefPriceDeviationExceeded`，整体 revert
- **验证目标**：多 token 场景下 per-token 独立校验

### 6.1.B 集成测试 — Provider 切换机制（INT-ORACLE-17～21）
> 验证目标：§二（切换机制）的当前代码行为，**不含新方案**。
### INT-ORACLE-17：提交时 provider 与 DataStore 配置不一致 → revert
- **前置条件**：Token A 配置的 provider = `mockProviderA`
- **操作**：调用 `oracle.setPrices(params)`，但 `params.providers[0] = mockProviderB`（不同于配置）
- **期望**：`revert InvalidOracleProviderForToken(TOKEN_A, mockProviderB, mockProviderA)`
- **验证目标**：`R-ORA-09`，切换后 Keeper 未同步更新导致的失败
### INT-ORACLE-18：`initOracleProviderForToken` 只能调用一次 → 重复调用 revert
- **前置条件**：Token A 已通过 `initOracleProviderForToken` 初始化为 `mockProviderA`
- **操作**：再次调用 `initOracleProviderForToken(oracle, TOKEN_A, mockProviderB)`
- **期望**：`revert OracleProviderAlreadyExistsForToken(TOKEN_A)`
- **验证目标**：init 与 set 两个函数的职责边界
### INT-ORACLE-19：首次切换到从未激活的 provider → 无时间锁，立即生效
- **前置条件**：
- Token A 当前 provider = `mockProviderA`（通过 init 设置）
- `mockProviderB` 已 enable，但 `oracleProviderUpdatedAt(TOKEN_A, mockProviderB) == 0`（从未激活）
- `ORACLE_PROVIDER_MIN_CHANGE_DELAY = 3600`
- **操作**：立即调用 `Config.setOracleProviderForToken(oracle, TOKEN_A, mockProviderB)`（不等待任何时间）
- **期望**：切换成功，Token A 的 provider 变为 `mockProviderB`
- **进一步验证**：用 `mockProviderB` 提交价格 → 成功；用 `mockProviderA` 提交 → `InvalidOracleProviderForToken`
- **验证目标**：`R-ORA-11`，首次切换不受时间锁限制
### INT-ORACLE-20：切回最近激活过的 provider → 时间锁生效，revert
- **前置条件**：
- Token A 经历了 init→mockProviderA，然后切换→mockProviderB（记录了 `oracleProviderUpdatedAt(TOKEN_A, mockProviderA) = T`）
- `ORACLE_PROVIDER_MIN_CHANGE_DELAY = 3600`
- 当前时间 = T + 1800（仅过了 30 分钟）

## 八、v0.3.0 Secondary Price 体系（2026-07-15 新增）
### 8.1 机制
v0.3.0 的净债务风控（LP 提款 gate / ADL 全局状态机）与 Express relay 费折算需要"随时可读"的价格，但 keeper 签名喂价（primary price）只在订单执行的事务内存在、用完即清。为此引入 `oracle.getSecondaryPrice(token, isADLStart)` 三层取价：
```plain text
① token == address(0)        → 返回 (0,0)（relay 费路径的 WNT 占位约定）
② 配置了 priceFeedKey(token) → Chainlink feed 价：
     latestRoundData → 价格>0 → heartbeat 时效校验（超时 revert ChainlinkPriceFeedNotUpdated，不回退③）
     → multiplier 归一化 → 返回单价 (p,p)（min==max，零点差）
③ 无 feed → latestRecordedPrices[token] 缓存价：
     从未记录                            → revert EmptySecondaryPrice
     超过 MAX_RECORDED_PRICE_AGE 且 !isADLStart → revert MaxPriceAgeExceeded
     否则                                → 返回缓存价（保留原始 min/max 点差）
```
**缓存写入**：每次 keeper `setPrices` 通过全套校验（provider 匹配、enable 状态、MAX_ORACLE_PRICE_AGE、时间戳范围、Pyth ±2% 偏差）后，`_setPrimaryPrice` **按时间戳单调更新** `latestRecordedPrices`——旧时间戳的提交无法回滚已记录的新价；缓存不随 `clearAllPrices` 清除；模拟路径（timestamp=0）不污染缓存。
**isADLStart 语义**（1-D1 修复后）：所有"放松风控"的读取（LP 提款、ADL 关闭判断、executeAdl）要求严格时效；唯一容忍过期缓存的是"开启 ADL 保护"的判断（updateAdlState 未启用→启用方向）——失效模式永远朝保守方向倒。
**原子路径删除**：`setPricesForAtomicAction` / `IS_ATOMIC_ORACLE_PROVIDER` / `NonAtomicOracleProvider` 全部移除；`MAX_ATOMIC_ORACLE_PRICE_AGE` 改名 `MAX_RECORDED_PRICE_AGE`（默认 24h）。
### 8.2 refreshLatestRecordedPrices（1-D2 新增的运营接口）
```solidity
AdlHandler.refreshLatestRecordedPrices(OracleUtils.SetPricesParams calldata oracleParams)
    external globalNonReentrant onlyRole(Role.ADL_KEEPER) withOraclePrices(oracleParams) {}
```
- **权限**：`Role.ADL_KEEPER`（与 updateAdlState/executeAdl 同角色）。
- **效果**：函数体为空，唯一副作用是 `withOraclePrices` 修饰器内 `oracle.setPrices` 校验通过后单调写入 recorded 缓存，随后 `clearAllPrices`。不改任何业务状态。
- **信任边界**：喂价走与订单执行**完全相同**的校验链（provider-for-token 匹配、MAX_ORACLE_PRICE_AGE、Pyth ±2% 偏差、时间戳范围）——ADL keeper **无法**注入任意/过期价格污染缓存（E2E-ORACLE-11b 已验证）。
- **用途**：无交易时段保持缓存温热（提款 gate/ADL 严格路径依赖）；feed 故障摘除后的恢复手段（见 §九方案 c）。
- **运维要求**：ADL keeper 增加定时任务，按 `MAX_RECORDED_PRICE_AGE` 的 1/4\~1/2 周期对无 feed 资产刷新缓存，使方案 c 的切换近乎即时。
