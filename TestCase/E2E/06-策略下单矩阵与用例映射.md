状态：设计初稿，待评审 ｜ 2026-08-13 起草 ｜ 功能场景：**tx-fork 真实链路策略下单全矩阵**

## 为什么用矩阵文档而不是连续编号

策略下单矩阵的组合（市价/限价 × long/short × 开/加/减/关 × 盈/亏）落在 S02、S03、S07 的既有 SCN 上，编号天然不连续。SCN 编号被总控清单、需求追踪矩阵、看板覆盖层与历史运行结果全链路引用，**不重排编号**（工作区纪律：不创建脱离设计文档的新编号）。功能场景的"覆盖设计视图"由本文档承担——一张矩阵一眼看全：每格写死 `SCN 编号 + 数据集 ID + 自动化状态`，执行层再用看板按本清单建批次。

三层记录方式：

1. **本矩阵文档** = 设计视图与覆盖清单（对齐 04/05 文档惯例）；
2. **数据集 ID** = 同一 SCN 内的方向/盈亏变体，报告保留独立结果（SCN-070 的 8 数据集模式）；ID 规范：`<SCN>/<方向>-<动作>[-<盈亏>]`，如 `SCN-023/long-decrease-profit`；
3. **看板批次** = 按本清单勾选 SCN 一键执行（后续可加"功能场景"标签一键筛选）。

## 执行方式（一个 tx-fork 跑全）

- 全部用例 `targetProject=tx-fork`（差异经看板覆盖层调整，不改 md 基线）；**例外：SCN-010 钉死 oracle-fork**（`package.json` 的 `test:scn010` 与 spec 内 `test.skip(project !== 'oracle-fork')`，2026-08-13 PASS 证据 resolvedEnvironment=oracle-fork；在 tx-fork 批次里为 SKIP「本次未执行核对」，属声明式绑定不是故障）；市场资源统一 `default-mock`；
- 每数据集独立 `evm_snapshot`/`evm_revert`：推价用的 `setMockPrice` 也在快照内，回滚即自动复位价格；
- Inline Keeper（避免排队延迟触发 60s 价格年龄、避免第三方交易污染核对窗口）；
- 价格构造统一三步：开仓于 P（set min=max 精确单价）→ 推价 ±x% 构造盈/亏 → 减/平仓；限价触发组：挂单 → 推价至触发 → Keeper 执行（SCN-010 已验证）；
- 每数据集开始刷新 Oracle 时间戳（runner 已内置自愈）。
- 可选环境铺底：`npm run env:noise:trades` 用多 Trader 模拟交易做基线复杂化（双侧 OI/Skew/Funding 非零、多仓并存，交易不核验）；铺底在批次前完成，静态仓位不影响增量式核对（2026-08-14 实证：铺底后 SCN-009/023 照常全绿）。
