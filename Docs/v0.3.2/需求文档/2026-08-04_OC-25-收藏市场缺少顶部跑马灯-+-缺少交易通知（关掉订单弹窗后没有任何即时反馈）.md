## 描述（Text 属性）

两个相关需求：① 收藏的市场要有顶部跑马灯（对标 Hyperliquid 顶栏）；② 交易通知。两者建议一起做，原因见文末「与 OC-24 的强联动」。

════════ 一、跑马灯（收藏行情条）════════

【现状】收藏功能已经有了但只用在一个地方 —— MarketSelect 的 Favourites 页签筛选。收藏本身持久化在 favoriteMarketSymbolsAtom（src/state/base/user.ts:8，localStorage key 'fx100-favorite-markets'），toggle 逻辑在 src/hooks/trade/useFavoriteMarkets.ts。收藏之后在主界面上看不到任何东西，收藏这个动作目前几乎没有收益。

【好消息：数据链路已经齐了，这是组装工作不是新建】
- 收藏列表：favoriteMarketSymbolsAtom
- 实时价：pricesBySymbolMapAtom
- 24h 涨跌幅：prices24hBySymbolMapAtom
这三个 atom 已经在 MarketSelect.tsx:141-143 一起用了，跑马灯直接复用即可，不需要新增接口或新的轮询。

【建议放置位置】
交易页顶部那条 60px 的 symbol + market data bar 之上，新增一条独立的窄条（TradePage.tsx，MarketSelect 所在的那个 div 之前）。这样它横跨整个宽度、不挤压现有的 MarketSelect 和 MarketData。

【实现建议】
1. 空态处理：没有收藏时不要显示空条。建议回退到默认集合（BTC/ETH + 成交量前几名）或整条隐藏，二选一交产品定。HL 的顶栏永远有内容。
2. 用 CSS animation 做滚动，不要用 JS 逐帧改 transform —— 26 个市场 × 每次价格 tick 重渲染，JS 方案会明显掉帧。
3. 数字用 tabular-nums，否则滚动时数字宽度变化会抖。
4. hover 时暂停滚动，否则用户根本点不中想点的那一项。
5. 点击某一项直接切换到该市场（复用 MarketSelect 的选中逻辑）。
6. 涨跌用颜色区分时注意：text-warning / border-warning 在本项目里未定义（等于白色 no-op），琥珀色一律用 amber-500。

════════ 二、交易通知 ════════

【现状：下单路径上一个 toast 都没有】
全项目 23 处 toast 调用，全部集中在 OrderRecords.tsx（206/218/235 行，是订单记录列表里的操作反馈）。开仓/平仓的成功与失败**完全依赖 OrderTrackingModal 这一个弹窗**（OrderForm.tsx:717：if (showOrderTracking) setShowOrderModal(true)）。

【建议：分两类，优先级不同】
A 类 · 交易事件通知（必须做，优先级高于跑马灯）
   订单提交成功 / 成交 / 被取消 / 执行失败（含失败原因，如超出 slippage）/ 被清算。
   用 toast 而非 modal：非阻塞、不打断下一笔操作，这也是 HL 的做法。
   toaster 基础设施已存在（src/components/ui/toaster.tsx + hooks/ui/use-toast），直接复用。
   ⚠️ 失败通知尤其重要 —— 见下方与 OC-24 的联动。

B 类 · 收藏资产价格提醒（需要产品先定规则，可后置）
   例如收藏的资产 24h 涨跌超过 X% 时提醒。需要产品明确：阈值多少、能否 per-asset 自定义、要不要浏览器原生通知（Notification API，需用户授权）、页面不在前台时是否也提醒。
   这一类涉及权限申请和后台轮询，建议与 A 类拆开、单独排期。

════════ 三、与 OC-24 的强联动（务必一起考虑）════════

OC-24 建议把 Order Status 弹窗默认关闭以提升效率。但 OrderForm.tsx:717 表明弹窗是当前**唯一**的下单反馈渠道 —— 默认关掉之后，用户下单后不会收到任何成功或失败提示，只能自己去 Open Orders / Positions 表格里找。

失败场景尤其糟：keeper 未执行、超出 slippage 这类失败，用户完全不知道发生了什么（参见 OC-23，还叠加了保证金锁死无法取消）。

所以 A 类交易事件通知是 OC-24 的必要前置或同步项。建议顺序：先做 A 类 toast，再把 OC-24 的默认值切成关闭。若两者不同步上线，OC-24 会造成反馈真空。

## 复测（复测属性）

【已验证关闭 2026-08-06】两半都完成了。
一、跑马灯 —— develop e53fe5d2 + b5a14616 新增 MarketTicker.tsx，本单 5 条实现要点全部命中：CSS animation 而非 JS 逐帧（全文件 0 处 requestAnimationFrame）、hover 暂停（group-hover:[animation-play-state:paused]，还额外做了触屏暂停）、tabular-nums 防抖动、由 favoriteMarketSymbols 驱动、点击切换市场。
二、A 类交易事件通知 —— develop 1dc9ecde 完成，而且代码注释写的理由与本单分析一致：「The modal only shows when showOrderTracking is on — Flash relay submissions never go through runOrderTransaction's toast, so this is the only feedback channel when the modal is off.」
三条路径全覆盖：useCreateOrder（开仓）/ useCreateDecreaseOrder（平仓）/ usePositionAdjust（调仓）。
★ 失败路径也有（本单特别强调的一条）：useOrderLifecycleWatcher 用 toastOrderCancelled 且 tone='error'，并把 revert 原因解码进 cancelReasonCode / cancelReasonArgs。而且做了本单没要求的区分 —— 用户主动取消不报错，执行失败与 keeper 侧取消才报错，自动清理的 TP/SL 按成功呈现。
所以 OC-24 默认关闭弹窗后的反馈真空已不存在，两单同步落地。
★ B 类（收藏资产价格提醒）本单当初就标注为「需产品先定规则、可后置、建议单独排期」，不阻塞本单关闭。若产品要做（阈值、能否 per-asset 自定义、是否用浏览器原生通知需授权、页面不在前台是否提醒），请另开单。
测试分支 merge commit 929a2cef，457 个测试（54 文件）全过。

跑马灯：① 收藏若干市场后顶部出现跑马灯，含实时价与 24h 涨跌幅；② 取消收藏后该项从条上移除；③ 无收藏时按产品定的空态表现（回退默认集合或隐藏），不出现空白条；④ hover 暂停滚动，点击某项能切换市场；⑤ 长时间挂着观察是否掉帧（确认用的是 CSS animation）。
交易通知：⑥ 下单成功、成交、取消、执行失败（含原因）、被清算各自都有 toast；⑦ 关闭 Order Status 弹窗后仍能通过 toast 得知成功与失败 —— 这一条是 OC-24 能否安全默认关闭的验收标准；⑧ 连续下多单时 toast 不堆叠遮挡表单。
