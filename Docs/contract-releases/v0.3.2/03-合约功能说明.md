## 3. 模块说明

### 3.1 Data/Config

**职责**：DataStore 是全系统唯一的键值状态库 + 角色权限库（继承 `AccessControlEnumerableUpgradeable`，见 `src/data/DataStore.sol::DataStore`），订单、仓位、市场、配置、OI、资金费指数等全部落在其中；Config 系合约是参数治理入口；FX100Keys/Keys2 定义全部存储键。

**核心合约文件**：`src/data/DataStore.sol`、`src/data/Keys2.sol`、`src/config/Config.sol`、`src/config/ConfigSyncer.sol`、`src/config/ConfigUtils.sol`、`src/config/AutoCancelSyncer.sol`、`src/constants/FX100Keys.sol`、`src/constants/Role.sol`、`src/constants/Addresses.sol`。

**外部入口**（external/public）：

| 入口 | 锚点 | 权限 |
| --- | --- | --- |
| 初始化 admin | `src/data/DataStore.sol::initialize` | initializer |
| uint/int/address/bool/string/bytes32 及数组的 get/set/remove/applyDelta（getter 公开可读，setter 受控） | `src/data/DataStore.sol::getUint`、`setUint`、`applyDeltaToUint`、`applyBoundedDeltaToUint`、`setInt`、`setAddress`、`setBool`、`setBytes32`、`setUintArray` 等 | setter 全部 `onlyRole(Role.CONTROLLER)` |
| 集合操作（bytes32/address/uint set） | `src/data/DataStore.sol::addBytes32`、`removeBytes32`、`containsAddress`、`getAddressValuesAt` 等 | 写操作 `onlyRole(Role.CONTROLLER)` |
| 通用参数设置（带 baseKey 白名单与范围校验） | `src/config/Config.sol::setBool/setAddress/setBytes32/setUint/setInt` | `onlyKeeper`（CONFIG_KEEPER 或 LIMITED_CONFIG_KEEPER，见 `src/config/Config.sol::onlyKeeper`） |
| Oracle 相关初始化/绑定 | `src/config/Config.sol::initOracleConfig`、`initOracleProviderForToken`、`setOracleProviderForToken`、`setOracleProviderForFeeHandlerToken`、`setOracleProviderEnabled` | `onlyConfigKeeper` |
| 风险参数外部同步 | `src/config/ConfigSyncer.sol::sync`（对接 `src/config/IRiskOracle.sol`） | 合约内校验（LIMITED_CONFIG_KEEPER 路径） |
| AutoCancel 列表迁移/同步 | `src/config/AutoCancelSyncer.sol::syncAutoCancelOrderListForAccount`、`syncAutoCancelOrderListForPosition` | onlyConfigKeeper 路径（合约 `AccessStoreProxy`） |
| 参数范围校验 | `src/config/ConfigUtils.sol::validateRange`（public view） | 无 |

**主流程**：治理者通过 Config 的 setXxx(baseKey, data, value) 写入 `keccak256(abi.encode(baseKey, ...data))` 组合键；`ConfigUtils.validateRange` 拦截越界值；所有业务合约通过 `AccessStoreProxy`（`src/access-control/AccessStoreProxy.sol::onlyRole/onlyController/onlyConfigKeeper` 等 modifier）从同一个 DataStore 读写。

**状态变化**：DataStore 内 kv/集合的增删改；无独立状态机。

**事件**：Config 每次 set 通过 EventEmitter 发出通用 EventLog（锚点 `src/event/EventEmitter.sol::emitEventLog1`）；DataStore 本身不发业务事件。

**错误**：键不在白名单/越界由 `src/error/FxErrors.sol` 中 Config 相关错误抛出（如 `InvalidBaseKey` 系列）；`applyBoundedDeltaToUint` 负溢出按 0 处理（`src/data/DataStore.sol::applyBoundedDeltaToUint`）。

**角色权限**：CONTROLLER（业务合约）、CONFIG_KEEPER、LIMITED_CONFIG_KEEPER、TIMELOCK_ADMIN（角色常量锚点 `src/constants/Role.sol::CONFIG_KEEPER` 等）。

**与 v0.3.1 差异**：
- 新增全局键 `src/constants/FX100Keys.sol::COLLATERAL_TOKEN`（L66），Relay 手续费与建市校验依赖它（01 文档 §7）。
- 动态点差键改为按市场+方向、有符号：`src/constants/FX100Keys.sol::MIN_DYNAMIC_SPREAD`（L38）、`MAX_DYNAMIC_SPREAD`（L40）及组合键函数（L614、L622）（01 文档 §4.1）。
- 子账户槽位键新增：`src/constants/FX100Keys.sol::SUBACCOUNT_SLOT`、`SUBACCOUNT_SLOT_SUBACCOUNT`、`SUBACCOUNT_SLOT_ACTIVE`（L268–270）（01 文档 §5.1）。
- claimable collateral 相关键与配置接口被移除（01 文档 §6.3）。
- `src/data/Keys2.sol` 仅注释精度说明变化（明确 FeeDistributor 各 factor 用 `1e30 = 100%`，diff 证据：Keys2.sol +12/−5 全为注释行）；`src/data/DataStore.sol` 本版本无变化（diff 文件清单不含该文件）。

### 3.2 Market

**职责**：市场创建与市场级账本——OI（USD 与 token 双口径）、累计开仓成本、PnL 封顶、储备校验、净债务率（global net obligation ratio）、资金费指数（见 3.6）。

**核心合约文件**：`src/market/MarketFactory.sol`、`src/market/Market.sol`、`src/market/MarketToken.sol`、`src/market/MarketUtils.sol`、`src/market/MarketStoreUtils.sol`、`src/market/MarketEventUtils.sol`、`src/market/PositionImpactPoolUtils.sol`、`src/market/MarketPoolValueInfo.sol`。

**外部入口**：

| 入口 | 锚点 | 权限 |
| --- | --- | --- |
| 创建市场 | `src/market/MarketFactory.sol::createMarket` | `onlyRole(Role.MARKET_KEEPER)` |
| MarketToken 铸/销 | `src/market/MarketToken.sol::mint`、`burn` | `onlyController` |
| 市场校验/读取（external/public 库函数，供 Handler 与 Reader 调用） | `src/market/MarketUtils.sol::validateEnabledMarket`、`getEnabledMarket`、`validateOpenInterest`、`validateOpenInterestReserve`、`getPnl`、`getCappedPnl`、`getNetPnl`、`getNetObligation`、`getGlobalNetObligationRatio`、`isGlobalNetObligationRatioExceeded`、`getOpenInterestWithPnl`、`setUiFeeFactor` 等 | 库函数，权限由调用方合约承担 |

**主流程**：`createMarket` 读取全局 `COLLATERAL_TOKEN` 并校验非零、且必须等于 `vault.asset()`，随后 `marketIndex = 市场计数 + 1` 递增分配，写入 `Market.Props{marketIndex, vault, indexToken, collateralToken}`（结构体锚点 `src/market/Market.sol::Props`）。市场本身不部署新资金池合约，共用 LPVault（`market.vault`）。

**状态变化**：MarketStoreUtils 维护市场列表与计数；OI/累计成本等在订单执行路径中经 `MarketUtils.applyDeltaToOpenInterestInTokens`、`applyDeltaToCumulativeOpenCosts` 更新。

**事件**：`src/market/MarketEventUtils.sol::emitOpenInterestUpdated`、`emitOpenInterestInTokensUpdated`、`emitFunding`、`emitNegativeFundingFeePerSizeUpdated`、`emitPositiveFundingFeePerSizeUpdated`、`emitPositionImpactPoolAmountUpdated` 等。

**错误**：市场禁用/OI 超限等经 `FxErrors`（如 `MarketUtils.validateOpenInterest` 抛 OI 超限错误）。

**角色权限**：MARKET_KEEPER 建市；CONTROLLER 更新账本。

**与 v0.3.1 差异**（diff 涉及 MarketFactory、MarketUtils、MarketStoreUtils、MarketEventUtils）：
- `createMarket` 新增 `COLLATERAL_TOKEN` 非零 + 与 `vault.asset()` 一致性校验，不一致抛 `FxErrors.InvalidCollateralTokenForVault`（diff 证据：`src/market/MarketFactory.sol::createMarket` +12 行）。
- `MarketUtils.settleFundingFees` 为新增的逐仓资金费结算入口；`updateFundingState` 不再触发 LP 现金流（见 3.6 与 4.3；01 文档 §6）。
- claimable collateral 的存储与领取逻辑自 MarketUtils/MarketEventUtils 移除（`MarketEventUtils.sol` −52 行；01 文档 §6.3）。

### 3.3 Order

**职责**：订单对象定义、创建/更新/取消/冻结、Keeper 执行调度、自动撤单（AutoCancel）。

**核心合约文件**：`src/order/Order.sol`、`src/order/OrderUtils.sol`、`src/order/BaseOrderUtils.sol`、`src/order/ExecuteOrderUtils.sol`、`src/order/IncreaseOrderUtils.sol`、`src/order/DecreaseOrderUtils.sol`、`src/order/IncreaseOrderExecutor.sol`、`src/order/DecreaseOrderExecutor.sol`、`src/order/AutoCancelUtils.sol`、`src/order/OrderStoreUtils.sol`、`src/order/OrderEventUtils.sol`、`src/exchange/OrderHandler.sol`、`src/exchange/BaseOrderHandler.sol`。

**订单类型**：`src/order/Order.sol::OrderType` 共 7 种——MarketIncrease、LimitIncrease、MarketDecrease、LimitDecrease、StopLossDecrease、Liquidation、StopIncrease；`SecondaryOrderType`：None/Adl。订单标志 `src/order/Order.sol::Flags`：`isLong`、`isFrozen`、`autoCancel`、`isSizeDeltaUsd`（`sizeDelta` 的 USD/Token 语义见字段规则第 4 章）。

**外部入口**：

| 入口 | 锚点 | 权限 |
| --- | --- | --- |
| 创建订单 | `src/exchange/OrderHandler.sol::createOrder` | `globalNonReentrant onlyController`（由 Router 系代理用户调用） |
| 更新订单 | `src/exchange/OrderHandler.sol::updateOrder` | `globalNonReentrant onlyController`；市价单不可更新（函数内 `Order.isMarketOrder` 分支） |
| 取消订单 | `src/exchange/OrderHandler.sol::cancelOrder` | `globalNonReentrant onlyController` |
| 执行订单 | `src/exchange/OrderHandler.sol::executeOrder` | `onlyOrderKeeper` + `withOraclePrices`（modifier 锚点 `src/oracle/OracleModule.sol::withOraclePrices`） |
| 模拟执行 | `src/exchange/OrderHandler.sol::simulateExecuteOrder` | `withSimulatedOraclePrices` + `globalNonReentrant` |
| 内部再入口（try/catch 边界） | `src/exchange/OrderHandler.sol::doExecuteOrder` | `onlySelfOrController` |
| 订单落库/取消/冻结（库入口） | `src/order/OrderUtils.sol::createOrder`、`cancelOrder`、`freezeOrder`、`clearAutoCancelOrders` | 由 Handler 调用 |

**主流程**（创建）：`OrderUtils.createOrder` 先 `AccountUtils.validateAccount` 并落推荐码（`ReferralUtils.setTraderReferralCode`）；加仓类订单的 `initialCollateralDeltaAmount` 以 `orderVault.recordTransferIn(market.collateralToken)` 实收为准，减仓类订单按入参；只允许上述 6 种用户可建类型，否则抛 `FxErrors.OrderTypeCannotBeCreated`；执行费以 `orderVault.recordTransferIn(Addresses.WNT)` 实收计并经 `GasUtils.validateExecutionFee`/`validateAndCapExecutionFee` 校验（锚点 `src/gas/GasUtils.sol::validateExecutionFee`、`validateAndCapExecutionFee`）。

**主流程**（执行）：`executeOrder` 估算并校验 gas（`src/gas/GasUtils.sol::estimateExecuteOrderGasLimit`、`validateExecutionGas`）→ `try doExecuteOrder`；成功路径 `doExecuteOrder` 校验冻结单执行人（`src/exchange/OrderHandler.sol::_validateFrozenOrderKeeper`，要求 `Role.FROZEN_ORDER_KEEPER`）、Feature 开关（`src/feature/FeatureUtils.sol::validateFeature`），再按订单类型分派 `IncreaseOrderExecutor/DecreaseOrderExecutor`（`src/exchange/OrderHandler.sol::getOrderExecutor`）；统一执行框架 `src/order/ExecuteOrderUtils.sol::executeOrder` 先 `PositionUtils.updateFundingState` 更新资金费指数，再 `orderExecutor.processOrder`，最后触发订单事件、支付执行费（`src/gas/GasUtils.sol::payExecutionFee`）。失败路径见 4.1 订单生命周期。

**触发价/成交价校验**：`src/order/BaseOrderUtils.sol::validateOrderTriggerPrice`、`validateOrderValidFromTime`、`getExecutionPriceForIncrease`、`getExecutionPriceForDecrease`（acceptablePrice 越界抛错并被 `_handleOrderError` 归类）。

**减仓专属校验**：`src/order/DecreaseOrderUtils.sol::_validateOutputAmount` 把 `minOutputAmount` 作为 USD 价值校验（`outputAmount × 输出 token 主价 min < minOutputAmount` 则抛 `FxErrors.InsufficientOutputAmount`）；`validateOracleTimestamp` 防止用早于最近加仓时间的价格执行减仓。

**状态变化**：订单经 OrderStoreUtils 存入 DataStore（订单集合 + 账户订单集合）；AutoCancel 单进入按 positionKey 索引的自动撤单列表（`src/order/AutoCancelUtils.sol::addAutoCancelOrderKey`），全平后由 `OrderUtils.clearAutoCancelOrders` 批量撤销。

**事件**：`src/order/OrderEventUtils.sol::emitOrderCreated`、`emitOrderUpdated`、`emitOrderExecuted`、`emitOrderCancelled`、`emitOrderFrozen`、`emitOrderSizeDeltaAutoUpdated`、`emitOrderCollateralDeltaAmountAutoUpdated`、`emitPositionCollateralUsedForExecutionFee`。

**错误**：`FxErrors.OrderTypeCannotBeCreated`、`EmptyOrder`、`EmptyPosition`、`InvalidOrderPrices`、`OrderValidFromTimeNotReached`、`InvalidKeeperForFrozenOrder`、`UnsupportedOrderType`、`InsufficientOutputAmount`、`UnexpectedValidFromTime`（锚点均在 `src/error/FxErrors.sol`，使用处见上述函数）。

**角色权限**：CONTROLLER（Router→Handler 链）、ORDER_KEEPER（执行）、FROZEN_ORDER_KEEPER（冻结单执行）。

**与 v0.3.1 差异**（diff 涉及 Order.sol、OrderUtils、ExecuteOrderUtils、DecreaseOrderUtils、OrderHandler）：
- 减仓 `minOutputAmount` 现在被实际校验（`DecreaseOrderUtils::_validateOutputAmount`；01 文档 §8.1）。
- `ExecuteOrderUtils.executeOrder` 中 `updateFundingState` 调用去掉 `positionVault` 参数——资金费指数更新不再伴随 LP 现金流（diff 证据：`src/order/ExecuteOrderUtils.sol` −4 参数行；01 文档 §6.2）。
- 减仓输出结构删除 secondary output token/amount 字段，`getOutputEventData` 仅保留单一 outputToken/outputAmount（01 文档 §8.5）。
- USD 减仓 token 取整触发的「归一为全平」在订单侧发出 `emitOrderSizeDeltaAutoUpdated`（见 3.4 与 01 文档 §8.2）。

### 3.4 Position

**职责**：仓位对象与加/减仓核心账务：保证金、PnL 实现、费用扣付瀑布、清算判定、OI 联动。

**核心合约文件**：`src/position/Position.sol`、`src/position/PositionUtils.sol`、`src/position/IncreasePositionUtils.sol`、`src/position/DecreasePositionUtils.sol`、`src/position/DecreasePositionCollateralUtils.sol`、`src/position/PositionStoreUtils.sol`、`src/position/PositionEventUtils.sol`。

**外部入口**：本模块没有直接面向 EOA 的入口，全部经 Order 执行路径进入：
- `src/order/IncreaseOrderExecutor.sol::processOrder` → `src/order/IncreaseOrderUtils.sol::processOrder` → `src/position/IncreasePositionUtils.sol::increasePosition`；
- `src/order/DecreaseOrderExecutor.sol::processOrder` → `src/order/DecreaseOrderUtils.sol::processOrder` → `src/position/DecreasePositionUtils.sol::decreasePosition`。
供外部合约（Handler/Reader）调用的 external/public 库函数：`src/position/PositionUtils.sol::isPositionLiquidatable`、`validatePosition`、`willPositionCollateralBeSufficient`、`getPositionPnlUsdWithExecutionPrice`、`updateFundingState`、`getDecreaseOrderSize`、`getExecutionPriceForIncrease`、`getExecutionPriceForDecrease`。

**主流程（加仓）**：`IncreasePositionUtils.increasePosition`——新仓（`sizeInUsd == 0`）先快照双向 funding per size 指数（`setNegativeFundingFeePerSize/setPositiveFundingFeePerSize`）；取执行价（含动态点差，见 3.5）→ `processCollateral` 计费并结算资金费 → 保证金充足性检查（不足抛 `FxErrors.InsufficientCollateralAmount`）→ 更新 `sizeInUsd/sizeInTokens/increasedAtTime` 并 `PositionStoreUtils.set` → `updateOpenInterest` → 储备校验 `MarketUtils.validateOpenInterestReserve` → `willPositionCollateralBeSufficient`（不足抛 `FxErrors.InsufficientCollateralUsd`）→ `handleReferral` → `validatePosition`（含最小/最大仓位与可清算性校验）。首开仓的清算保护期在订单侧写入：`src/order/IncreaseOrderUtils.sol::processOrder` L51–55 按 `LIQUIDATION_GRACE_PERIOD_BASE × tierMultiplier` 设置 `position.graceEnd`（公式见字段规则第 14.1 节）。

**主流程（减仓）**：`DecreasePositionUtils.decreasePosition`——换算 `sizeDeltaUsd/sizeDeltaInTokens`（`PositionUtils.getDecreaseOrderSize`）；若 USD 口径减仓因 token 向上取整恰好耗尽 `sizeInTokens`，把订单归一为全平（`params.order.setSizeDelta(position.sizeInUsd())` 并发 `emitOrderSizeDeltaAutoUpdated`，使 PnL/费用/OI/事件同口径）；随后 `DecreasePositionCollateralUtils.processCollateral` 计算实现 PnL、执行费用扣付瀑布（`payForCost`，顺序与保证金/PnL 抵扣见字段规则第 8、10、14.5 章），并在其中调用 `MarketUtils.settleFundingFees`（L141）逐仓结算资金费净额；全平时 `PositionStoreUtils.remove`（`src/position/DecreasePositionUtils.sol` L283）删除仓位并清理 AutoCancel 列表；资不抵债走 `emitInsolventClose` 路径。

**状态变化**：仓位字段全集见字段规则第 3 章（`Position.Props` 锚点 `src/position/Position.sol::Props`，含 `graceStart/graceEnd`）；仓位键 `Position.getPositionKey(account, marketIndex, isLong)`——每账户每市场每方向至多一个仓位。

**事件**：`src/position/PositionEventUtils.sol::emitPositionIncrease`、`emitPositionDecrease`、`emitPositionFeesCollected`、`emitPositionFeesInfo`、`emitInsolventClose`、`emitInsufficientFundingFeePayment`。

**错误**：`FxErrors.InsufficientCollateralAmount`、`InsufficientCollateralUsd`、`EmptyPosition`、`PositionNotLiquidatable`、最小/最大仓位与 OI 校验类错误（使用处见 `PositionUtils.validatePosition`、`validateBasicPositionInfo`）。

**角色权限**：仅 CONTROLLER 链路（Executor 合约）可写。

**与 v0.3.1 差异**（diff 涉及本目录 5 个文件）：
- USD 减仓取整边界归一为全平（diff 证据：`src/position/DecreasePositionUtils.sol::decreasePosition` 新增 `isSizeDeltaUsd() && sizeDeltaInTokens == position.sizeInTokens()` 分支；01 文档 §8.2）。
- 剩余成本单位修复：token 数量乘抵押品价格后再记 USD（01 文档 §8.3；`DecreasePositionCollateralUtils` −41 行重构）。

### 3.6 Funding

**职责**：资金费率与累计 per-size 指数维护、仓位侧结算与 LP 现金流。费率与单仓结算公式见字段规则第 12 章。

### 3.11 Vault

**职责**：两类资金载体。(1) LPVault（ERC20 份额 + epoch 提款）承接 LP 资金，是所有市场共用的对手方资金池，可把资产配置给 Strategy 生息；(2) Bank 系（OrderVault/PositionVault）是订单保证金与仓位保证金的保管合约，只认 CONTROLLER 指令。

**核心合约文件**：`src/vault/VaultBase.sol`、`src/vault/LPVault.sol`、`src/vault/IVault.sol`、`src/bank/Bank.sol`、`src/bank/StrictBank.sol`、`src/bank/OrderVault.sol`、`src/bank/PositionVault.sol`、`src/interfaces/IStrategy.sol`。

**外部入口**：

| 入口 | 锚点 | 权限 |
| --- | --- | --- |
| LP 入金 | `src/vault/LPVault.sol::deposit(assets, receiver)` | 公开，nonReentrant |
| 发起提款请求 | `src/vault/LPVault.sol::initiateWithdrawRequest(shares)` | 持份人 |
| 领取提款 | `src/vault/LPVault.sol::claimWithdrawRequest`、`claimWithdrawRequests` | 请求人，受 `withdrawDelaySeconds` 与 `_validateWithdrawalsAllowed`（全局净债务率超 `MAX_PNL_FACTOR_FOR_WITHDRAWALS` 时禁提，抛 `WithdrawGlobalNetObligationRatioExceeded`）约束 |
| 查询 | `src/vault/LPVault.sol::getWithdrawRequests`；`src/vault/VaultBase.sol::totalAssets`、`nav`、`convertToAssets`、`convertToShares` | view |
| 管理 | `src/vault/LPVault.sol::updateEpochDuration`、`updateWithdrawDelaySeconds`、`updateOracle`；`src/vault/VaultBase.sol::updateStrategy` | `DEFAULT_ADMIN_ROLE` |
| 协议侧划转（资金费/亏损结算用） | `src/vault/VaultBase.sol::transferOut(token, to, amount)` | `CONTROLLER_ROLE` |
| 保证金库划转 | `src/bank/Bank.sol::transferOut`（两个重载）、`transferOutNativeToken`；`src/bank/StrictBank.sol::recordTransferIn`、`syncTokenBalance` | `onlyController` |

**主流程**：deposit 后按 nav 折算份额并尝试把超配比部分转入 Strategy（`VaultBase::_tryAllocateAssets`，按 `strategyInfo.allocationPercentage` 精度 PRECISION）；提款走请求-延迟-领取三段（epoch 推进 `LPVault::_advanceEpoch`）；出金时 Vault 自持不足则触发 Strategy 补差：先把本地余额转给接收方，再向 Strategy 提取差额，**对比接收方前后余额，实际到账 ≠ 差额则整笔回退 `ErrorStrategyWithdrawalMismatch(expectedAssets, receivedAssets)`**（`src/vault/VaultBase.sol::_withdrawAssets` L238 起，错误定义 L43）。

**状态变化**：份额 ERC20；withdraw request 列表；epoch 数据；strategy 配置。

**事件**：`VaultBase::StrategyUpdated` 系、`LPVault::EpochDurationUpdated`、`WithdrawDelaySecondsUpdated`、`OracleUpdated` 等（合约自有 event，非 EventEmitter 通道）。

**错误**：`ErrorStrategyWithdrawalMismatch`、`ErrorZeroAddress`、`WithdrawGlobalNetObligationRatioExceeded`。

**角色权限**：DEFAULT_ADMIN_ROLE（参数）、CONTROLLER_ROLE（transferOut，授予核心账务合约）。

**与 v0.3.1 差异**：`src/vault/VaultBase.sol` 新增 Strategy 提款到账校验（diff 证据：+error 定义与 `_withdrawAssets` 内余额差校验块；01 文档 §9）。`src/vault/LPVault.sol` 与 `src/bank/` 全部文件不在 diff 清单——**无变化（diff 证据）**。

### 3.12 Reader

### 3.13 Event / Error

**核心合约文件**：`src/event/EventEmitter.sol`、`src/event/EventUtils.sol`、`src/error/FxErrors.sol`、`src/error/ErrorUtils.sol`。

**外部入口**：`src/event/EventEmitter.sol::emitEventLog`、`emitEventLog1`、`emitEventLog2`、`emitDataLog1`～`emitDataLog4`，全部 `onlyController`。

**主流程**：各模块 XxxEventUtils 组装 EventLogData → EventEmitter 以 `eventName` + topic 发链上日志；索引器按 eventName 订阅。错误处理上，OrderHandler 用 `ErrorUtils.getErrorSelectorFromData` 解析 catch 到的 revert data 决定订单冻结/取消/透传（见 4.1）。

## 4. 关键状态转换

### 4.1 订单生命周期：创建 → 执行 / 取消 / 冻结

```text
用户/子账户/Relayer
  └─ ExchangeRouter / SubaccountRouter / RelayRouter / SubaccountRelayRouter
       └─ OrderHandler.createOrder（onlyController）
            └─ OrderUtils.createOrder：实收保证金与 WNT 执行费入 OrderVault → 订单落库
                 状态：Created（isFrozen = false）

Created ──ORDER_KEEPER: OrderHandler.executeOrder──▶ try doExecuteOrder
  ├─ 成功 ⇒ Executed：ExecuteOrderUtils.executeOrder
  │        （updateFundingState → Increase/DecreaseOrderExecutor.processOrder
  │          → 订单从存储删除 → emitOrderExecuted → payExecutionFee）
  └─ 失败 ⇒ _handleOrderError 分类（src/exchange/OrderHandler.sol::_handleOrderError）：
       ① 直接回退（保持 Created）：已冻结单、EmptyOrder、限价/触发单的 EmptyPosition、
          InvalidOrderPrices（触发价未满足）、OrderValidFromTimeNotReached、
          InvalidKeeperForFrozenOrder、UnsupportedOrderType
       ② 市价单失败 ⇒ Cancelled：OrderUtils.cancelOrder（退回保证金与执行费余额，
          emitOrderCancelled）
       ③ 非市价单其他失败 ⇒ Frozen：OrderUtils.freezeOrder（isFrozen = true，
          emitOrderFrozen；此后仅 FROZEN_ORDER_KEEPER 可执行，见
          OrderHandler.doExecuteOrder::_validateFrozenOrderKeeper）

Created/Frozen ──用户: Router.cancelOrder 或 AutoCancel──▶ Cancelled
  · 市价单有最小存活时间限制（OrderHandler.cancelOrder 内 MarketOrderCannotBeCancelled 路径）
  · autoCancel = true 的挂单在其仓位全平时被 OrderUtils.clearAutoCancelOrders 批量撤销
Created ──用户: updateOrder──▶ Created（参数更新；市价单不可更新，冻结单不可更新）
```

### 4.2 仓位生命周期：开 → 加/减 → 平 / 强平 / ADL

```text
（无仓）──MarketIncrease/LimitIncrease/StopIncrease 执行──▶ Open
   · 首开仓：快照双向 fundingFeePerSize（IncreasePositionUtils.increasePosition）
     并设置清算保护期 graceEnd = block.timestamp + gracePeriodBase × tierMultiplier
     （IncreaseOrderUtils.processOrder L51–55；公式见字段规则第 14.1 节）
   · 每账户×市场×方向唯一仓位（Position.getPositionKey）

Open ──加仓单──▶ Open（sizeInUsd/sizeInTokens 增加，先逐仓结算资金费再更新快照）
Open ──部分减仓──▶ Open（实现比例 PnL，见字段规则第 7 章；提取 collateralDelta）
   · USD 减仓 token 向上取整恰好耗尽 sizeInTokens ⇒ 自动归一为全平
     （DecreasePositionUtils.decreasePosition + emitOrderSizeDeltaAutoUpdated，v0.3.2 新增）
Open ──全平（sizeDeltaUsd == sizeInUsd）──▶ Closed
   · PositionStoreUtils.remove（DecreasePositionUtils L283）+ 清理 AutoCancel 挂单
   · minOutputAmount 按 USD 校验（DecreaseOrderUtils._validateOutputAmount，v0.3.2 生效）

Open ──LIQUIDATION_KEEPER: executeLiquidation──▶ Liquidated（全平）
   · 前置：block.timestamp ≥ graceEnd（LiquidationUtils.createLiquidationOrder）
     且 PositionUtils.isPositionLiquidatable 满足（字段规则第 14.3 节；判定不计清算费，
     第 14.4 节）
   · 追加清算费（字段规则第 11、14.5 章）；负点差被禁止（按 0 处理）
   · 资不抵债 ⇒ emitInsolventClose 路径

Open ──ADL_KEEPER: executeAdl──▶ Open(减少) 或 Closed
   · 前置：updateAdlState 已置 ADL enabled，全局净债务率超限且该仓 PnL > 0
   · 执行后全局净债务率必须严格下降（AdlHandler.executeAdl 尾部校验，否则 InvalidAdl 回退）
   · 与强平同走 DecreaseOrderExecutor 账务路径（SecondaryOrderType.Adl），禁止负点差
```

### 4.3 资金费结算路径（v0.3.2 逐仓结算新行为）

```text
① 指数累计（每次订单执行，无现金流）
   ExecuteOrderUtils.executeOrder
     └─ PositionUtils.updateFundingState → MarketUtils.updateFundingState
          · getNextFundingAmountPerSize：按 skew 计算双向费率（字段规则第 12.1 节）
          · 四个累计指数 applyDelta（多/空 × 应付/应收 per size）
          · 写 fundingUpdatedAt、skew EMA；emitFunding（positionPaysLp 仅观察值）
          · v0.3.2：此处不再动任何 Vault 资金（v0.3.1 在此按全局预估处理 LP 现金流）

② 逐仓结算（仅在仓位实际操作时：加仓 / 减仓 / 全平 / 强平 / ADL）
   PositionPricingUtils.getFundingFees：
       仓位应付 = sizeInTokens × Δ负向指数（抵押品 min 价，向上取整）
       仓位应收 = sizeInTokens × Δ正向指数（抵押品 max 价，向下取整）
       （字段规则第 12.2 节）
   IncreasePositionUtils（L219）/ DecreasePositionCollateralUtils（L141）
     └─ MarketUtils.settleFundingFees(positionVault, ..., negativeAmt, positiveAmt)
          ├─ negative > positive：净额记入 LP 可领取费
          │    FeeUtils.incrementClaimableFeeAmount(marketIndex, collateralToken,
          │      差额, FUNDING_FEE_TYPE)   ← 资金留在 PositionVault，仅记账
          └─ positive > negative：LP 实际出资
               IVault(market.vault).transferOut(collateralToken, PositionVault, 差额)
   结算后仓位快照更新为最新指数（setNegative/PositiveFundingFeePerSize）

核对要点：现金流金额 = 逐仓实际应用金额的净额，而非全局预估值；
「仓位付 LP」只产生 claimable 记账，「LP 付仓位」才发生 LPVault → PositionVault 转账。
```
