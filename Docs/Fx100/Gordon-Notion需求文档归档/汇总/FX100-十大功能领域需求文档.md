## 二、储备金与风控体系改造

**权威文档**: 07-22 实施版（`release/v0.3.0`，2026-07-16 核对收官）
**涉及模块**: `MarketUtils.sol`, `LPVault.sol`, `AdlUtils.sol`, `Oracle.sol`, `FX100Keys.sol`

### 2.1 核心公式

```
per-market 净义务: net_i = max(0, longPnl_i) + max(0, shortPnl_i)
全局净义务比:      pnlRatio = Σ_i net_i / poolUsd
poolUsd = vault.totalAssets() × USDC 价
```

- 侧内盈亏互抵（同侧 +100/-60 → 该侧 PnL = +40）
- 跨侧不互抵（max(0,·) 分别取正后相加）

### 2.2 参数体系

| 参数 | 键维度 | 建议值 | 作用 |
|------|--------|--------|------|
| `RESERVE_FACTOR` | per-market（不分 isLong） | 1.0~1.5 起步→3.0 成熟 | 市场容量上限 |
| `MAX_PNL_FACTOR_FOR_ADL` | 全局单键 | 0.75 | ADL 触发门槛 |
| `MIN_PNL_FACTOR_AFTER_ADL` | 全局单键 | 0.50 | ADL 退出水位 |
| `MAX_PNL_FACTOR_FOR_WITHDRAWALS` | 全局单键 | 0.65 | LP 提款封锁门槛 |
| `MAX_PNL_FACTOR_FOR_TRADERS` | per-market × isLong | 0.90 | 结算 PnL 硬上限 |

**水位关系**: AFTER_ADL(0.50) < WITHDRAWALS(0.65) < ADL(0.75) < TRADERS(0.90)

### 2.3 状态机（全局 pnlRatio 驱动）

| 状态 | 条件 | LP 存款 | LP 提款 | ADL |
|------|------|---------|---------|-----|
| Safe | ≤ 0.65 | ✅ | ✅ | 不触发 |
| Danger | 0.65~0.75 | ✅ | ❌ | 不触发 |
| ADL | > 0.75 | ✅ | ❌ | 触发 |
| Buffer | ADL 后 0.50~0.75 | ✅ | ❌ 直到 < 0.65 | 不触发 |

## 五-A、Dynamic Spread 允许负值（07-29 最新方案）

**权威文档**：07-29《Dynamic Spread 允许为负 + 清算 / ADL 隔离实施方案》  
**状态**：待评审实施，尚不能视为 v0.3.1 已上线行为。

### 最新目标口径

```plain
raw = constantSpread + depthSpread + skewImpact

普通自愿交易：
dynamicSpread = clamp(MIN_DYNAMIC_SPREAD[market][isLong],
                      MAX_DYNAMIC_SPREAD[market][isLong],
                      raw)

清算 / ADL / 仓位安全校验：
dynamicSpread = max(0, raw)
```

关键变化：

1. `dynamicSpread` 从 `uint256` 改为 `int256`。
2. 普通开平仓改善平衡时可出现负 spread，成交价可优于 oracle。
3. 清算、ADL、开仓/减仓后的安全校验继续 floor-at-0。
4. 新增每市场 × 多空方向的 `MIN_DYNAMIC_SPREAD` / `MAX_DYNAMIC_SPREAD`。
5. ADL 需接入 `SecondaryOrderType.Adl`，不能继续与普通 MarketDecrease 无法区分。
6. Reader、事件、Indexer、SDK 和前端必须同步支持有符号值。
7. 前端需删除两处把负 spread 显示为 0 的旧逻辑。

### 新增验收重点

- 普通交易负 spread / rebate。
- 清算判定与执行不受 rebate 美化。
- 100x 极薄保证金安全校验仍按保守口径。
- ADL floor-at-0。
- 两层 clamp（skew clamp 与 dynamic clamp）谁更紧谁生效。
- Event / Reader / Indexer 对负值的解析。
- 新配置逐市场逐方向非零初始化。

## 六、Flash 1CT 安全

**权威文档**: 07-26 安全评审 + 07-28 同意与风险披露
**涉及模块**: 前端(SDK/hooks/components) + 合约(SubaccountRelayRouter/SubaccountUtils)

### 6.1 Session Key 生命周期

**生成(Generation)**
- 私钥 = `keccak256(personal_sign(SUBACCOUNT_MESSAGE))` — 确定性派生
- 消息为固定字符串，不含 origin/chainId/nonce/时间戳
- 加密存储使用 `AES.encrypt(pk, ownerAddress)` — 口令为公开钱包地址（混淆非加密）

| 需求编号 | 描述 |
|----------|------|
| REQ-GEN-01 | 同一主钱包多次执行 generate 产生相同的 subaccount 地址 |
| REQ-GEN-02 | 不同域名上同一主钱包派生的 subaccount 地址相同 |
| REQ-GEN-03 | 存储 key 结构为 makeSubaccountKey(chainId, address)，无 URL 维度 |
| REQ-GEN-04 | 浏览器存储按 origin 隔离 |
| REQ-GEN-05 | 改为随机 key 后产生不同地址 |

**授权(Authorization)**
- EIP-712 SubaccountApproval: expiresAt = 当前+24h, maxAllowedCount = 90, nonce 严格递增

| 需求编号 | 描述 |
|----------|------|
| REQ-AUTH-01 | 首次 setup 需签两次(generate + approval) |
| REQ-AUTH-02 | 首笔交易额外一次性 USDC permit 签名 |
| REQ-AUTH-03 | nonce 严格递增 |
| REQ-AUTH-04 | 合约校验 desChainId == block.chainid |
| REQ-AUTH-05 | 合约校验 deadline 未过期 |
| REQ-AUTH-06 | digest 一次性防重放 |

**过期(Expiration)**

| 需求编号 | 描述 |
|----------|------|
| REQ-EXP-01 | 超过 24h 后下单被拒 |
| REQ-EXP-02 | 累计 90 次后下单被拒 |
| REQ-EXP-03 | 距过期 < 4h 显示黄字但仍可下单 |
| REQ-EXP-04 | 剩余 ≤ 10 单标记 isLowOrders |
| REQ-EXP-05 | 过期后显示 Renew 按钮 |

**锁定(Locking)**

| 需求编号 | 描述 |
|----------|------|
| REQ-LOCK-01 | 隐藏累计 < 1h 不锁 |
| REQ-LOCK-02 | 隐藏累计 ≥ 1h 锁定 |
| REQ-LOCK-03 | 锁定后 getSigner() 返回空 |
| REQ-LOCK-04 | 重签 approval 后自动解锁 |
| REQ-LOCK-05 | sessionLockedAtom 仅存内存 |
| REQ-LOCK-06 | 隐藏时间戳存 sessionStorage |

## 九、前端数据精度

**来源**: 06-01 BTC 精度修复(SDK) + 06-04 USDC/USD 计价说明

### 9.1 BTC 精度问题

**根因**: SDK 继承自 GMX v2 使用 `token.decimals`（BTC=8），但 FX100 存储所有 position size 为 18 位精度。

**核心规则**: 链上交互使用 `POSITION_SIZE_DECIMALS=18`；用户输入使用 `indexToken.decimals`

**修复涉及 6 个文件**:
- `orderTransactions.ts` — sizeDeltaUsd 计算
- `positionPrecision.ts` — position size 显示
- `markets.ts` — market 数据解析
- `orders.ts` — order 数据解析
- `increase.ts` — 开仓/加仓参数
- `derived/orders.ts` — 派生订单数据

**测试要点**:
| 场景 | 正确值 | 错误值（修复前） |
|------|--------|----------------|
| Size 显示 | ~0.0014 BTC | 13,770,000 BTC |
| 清算价 | ~$64,000 | $641,000,000,000,000 |

### 9.2 USDC/USD 计价规则

**核心区分**:
- `sizeInUsd` = 纯 USD（价格维度）
- `collateralAmount` = raw USDC count（6 decimals）
- USDC oracle ≈ $0.9998~$0.9999，不精确等于 $1
- USDC 脱锚直接触发清算（ETH 价格不变也可能被清算）

**min/max 价格使用规则**:

| 场景 | 使用 | 理由 |
|------|------|------|
| 保证金价值 | min | 保守估值 |
| fee 扣除 | min | 多扣 USDC |
| funding 付款 | min | 多扣 USDC |
| 盈利折算 | max | 少给 USDC |
| 亏损折算 | min | 多扣 USDC |

**测试清单（12 项）**:
1. USDC 价格偏差时保证金变化
2. fee 随 USDC 价格反向变化
3. min != max 时 stablePrice 机制
4. USDC 脱锚 → 清算
5. 中英文标注一致性（Pay 栏=USDC, Size 栏=USD）
