## 5. 为什么 tx-fork 浏览器里看不到交易 · 两种跑法

- **2026-09-03 起 tests/B 默认持久**（看板批次 `2026-09-03T071039-781Z` 只见两条 set balance 记录后改的：那是 applyCaseTrader 在快照之前给专属 trader 注资的 cheatcode，开仓/全平在快照内被回滚）。快照模式改为显式 `E2E_TRADE_PERSIST=false`（`npm run test:trade:B1`）：spec 外壳对每条用例 `evm_snapshot` → 跑 → `evm_revert`，fork 上不留区块与交易，orderKey/tx 哈希在用例间重复，证据只在批次目录的 JSON。适合迭代与并行开发。
- 持久模式（默认；`npm run test:trade:B1:persist` 或看板直接跑）：原子开仓→全平真实上链、可在 Tenderly 浏览器按 tx 哈希查（2026-09-03 验证：createOpen block 46296803 / executeOpen 46296804 可查）；L_max 的二分探测仍逐次回滚，只有最终 minFeasible 那笔开仓→全平留在链上。
- 陷阱：`.env.local` 写着 `E2E_PERSIST_FORK_STATE="false"`，`loadRuntimeConfig` 以 override 方式加载，会在 spec 读到之前把 shell 里的 `true` 覆盖掉；所以 spec 改用独立键 `E2E_TRADE_PERSIST`（缺省 true）判定，判定为持久后再写回 `E2E_PERSIST_FORK_STATE=true` 让 runner 证据的 resetMode 一致。SCN 场景仍按原约定用 `E2E_ENV_PRIORITY_KEYS` 保护。
- 持久模式的代价：每次批次给 per-case trader 注资、开平仓费用与 OI 历史累积在 fork 上；因为默认已按用例分配专属 trader，互不串扰。正式批次建议用持久模式，证据可在链上复核。
