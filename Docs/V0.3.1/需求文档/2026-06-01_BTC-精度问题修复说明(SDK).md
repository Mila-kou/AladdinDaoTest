## 背景
FX100 合约（v0.2.0）的 oracle 对**所有 index token 统一使用 ****`USD × 10^12`**** 格式**存储价格，不区分 token 自身的小数位数：
<table header-row="true">
<tr>
<td>Token</td>
<td>链上小数位</td>
<td>FX100 oracle 价格格式</td>
<td>例子</td>
</tr>
<tr>
<td>ETH</td>
<td>18</td>
<td>USD × 10\^12</td>
<td>\$1981 → `1981e12`</td>
</tr>
<tr>
<td>BTC</td>
<td>8</td>
<td>USD × 10\^12</td>
<td>\$72272 → `72272e12`</td>
</tr>
<tr>
<td>USDC</td>
<td>6</td>
<td>USD × 10\^24</td>
<td>\$1 → `1e24`</td>
</tr>
</table>
合约内部所有 token 数量（`sizeInTokens`、`claimableAmount` 等）也统一用 **18 位精度**存储，不论 token 原生小数位。
SDK 原有代码从 GMX v2 继承，使用 `token.decimals`（BTC = 8）做格式转换，导致 BTC 相关计算偏差 **10\^(18-8) = 10\^10 倍**。ETH 碰巧正确，因为 `token.decimals == 18 == POSITION_SIZE_DECIMALS`。

## Commits（分支 feat/gordon1-fork-e2e-testing）
### `2ce64b8` — BTC short/long 下单被合约取消
**文件：** `packages/sdk/src/utils/orderTransactions.ts`
**现象：** BTC 下单后全部被合约 cancel，错误信息 `OrderNotFulfillableAtAcceptablePrice`。
**原因：** `convertToContractPrice(price, indexToken.decimals=8)` 对 BTC 除以 `10^8`，得到 `USD×10^22`，合约执行价格格式是 `USD×10^12`，偏差 `10^10`，订单永远无法成交。
**修复：**
```diff
- acceptablePrice = convertToContractPrice(p.acceptablePrice, indexToken.decimals)
+ const ORACLE_PRICE_DECIMALS = 18;
+ acceptablePrice = convertToContractPrice(p.acceptablePrice, ORACLE_PRICE_DECIMALS)
```
适用：`buildIncreaseOrderPayload`、`buildDecreaseOrderPayload`。

### `4f5aa9c` — BTC 仓位 Size 显示 \~1377万 BTC
**文件：** `packages/sdk/src/utils/positionPrecision.ts`
**现象：** Positions 列表 BTC Size 显示 \~1377万 BTC（应为 0.0014 BTC）。
**原因：** `getPositionSizeDecimals()` 返回 `token.decimals=8`，链上 `sizeInTokens` 是 18 位精度，`1.377e15 / 10^8 = 13,770,000 BTC`。
**修复：**
```diff
- return token.decimals + POSITION_SIZE_EXTRA_DECIMALS;
+ export const POSITION_SIZE_DECIMALS = 18;
+ return POSITION_SIZE_DECIMALS;
```
该函数被多处引用（`positions.ts`、`derived/positions.ts`、`PositionTPSLDialog.tsx` 等），修一处全局生效。

### `ddc5aab` — BTC 仓位 PnL/Funding/清算价显示天文数字（如 -\$578M）
**文件：** `packages/sdk/src/utils/markets.ts`、`fees/priceImpact.ts`、`modules/positions/positions.ts`
**现象：** Size/Value 正确后，PnL、Funding、清算价仍显示亿级错误值。
**原因（核心）：** `getContractMarketPrices()` 给 Reader 合约传入错误 BTC 价格（`72272e22` 而非 `72272e12`），Reader 用错误价格计算 `basePnlUsd`、fees 等并直接返回。
```javascript
- indexTokenPrice: convertToContractTokenPrices(indexToken.prices, indexToken.decimals)
+ indexTokenPrice: convertToContractTokenPrices(indexToken.prices, POSITION_SIZE_DECIMALS)
```
同文件中 `getReservedUsd`、`getMarketPnl`、`capPositionImpactUsdByMaxImpactPool`、claimable funding 也做了相同替换。

### `07add79` — Limit Order Token Size 错误 / Trigger 价格显示 `0.000007` / Order Status 清算价 \$641T
**文件：** `packages/sdk/src/utils/orders.ts`、`tradeHistory.ts`、`trade/increase.ts`、`prices.ts`
**现象：**
- Open Orders 中 BTC Token Size 显示 14M BTC（应为 0.0014）
- Trigger 条件显示 `Oracle ≤ 0.000007`（应为 `≤ $70,000`）
- Order Status 弹窗清算价显示 \$641T（应为 \~\$64K）
**原因：**
- `orders.ts`：`parseContractPrice(contractTriggerPrice, 8)` = `price × 10^8`，应为 `× 10^18`
- `increase.ts`：`sizeDeltaInTokens = convertToTokenAmount(sizeDeltaUsd, 8, price)` 产生 8 位格式，影响清算价
**修复：** `orders.ts`、`tradeHistory.ts`、`prices.ts` 及 `increase.ts` 中**推算路径**改用 `POSITION_SIZE_DECIMALS=18`。
> ⚠️ 注意：`increase.ts` 中 `leverageBySize` / `independent` 路径接收**用户原生 BTC 输入（8位小数）**，这两处**保留 ****`indexToken.decimals`**（见下一条 commit）。

### `460b6c1` — 新建 BTC Limit/Stop Limit 订单 Size 显示 \$0
**文件：** `packages/sdk/src/utils/trade/increase.ts`
**现象：** 新建 BTC Limit 订单后，Open Orders 中 Size 列显示 `$0`，Token Size 显示 `0 BTC`。
**原因：** 上一 commit 使用 `replace_all` 把 `leverageBySize` / `independent` 路径也一并改成了 18 位。这两处的 `indexTokenAmount` 是**用户输入的原生 BTC 格式（8位）**，改成 18 后结果 `≈ $0`。
**修复：** 仅 revert 用户输入路径：
```javascript
// ✗ 用户原生输入路径（revert 回 indexToken.decimals）
values.sizeDeltaUsd = convertToUsd(indexTokenAmount, indexToken.decimals, indexPrice)

// ✓ SDK 内部推算路径（保留 POSITION_SIZE_DECIMALS）
values.indexTokenAmount  = convertToTokenAmount(sizeDeltaUsd, POSITION_SIZE_DECIMALS, indexPrice)
values.sizeDeltaInTokens = convertToTokenAmount(sizeDeltaUsd, POSITION_SIZE_DECIMALS, indexPrice)
```

### `5c1c0b2` — 关仓订单 Token Size 显示 14M BTC
**文件：**
- `apps/fx-base-app/src/state/derived/orders.ts`
- `apps/fx-base-app/src/state/derived/tradeHistory.ts`
- `apps/fx-base-app/src/state/derived/orderHistory.ts`
- `apps/fx-base-app/src/components/features/trade/OrderForm.tsx`
**现象：** Open Orders 列表中关仓（Close Short/Long）Market 订单 Token Size 显示 \~14M BTC。
**原因：** 显示层用 `indexToken.decimals=8` 格式化 18 位精度的 `sizeInTokens`：
```javascript
// orders.ts（decrease 路径）
const tokensRaw = (matched.sizeInTokens * sizeDeltaUsd) / matched.sizeInUsd;
formatUnits(tokensRaw, indexToken.decimals)  // 1.4e15 / 10^8 = 14M BTC ✗
// 修复：
formatUnits(tokensRaw, POSITION_SIZE_DECIMALS)  // 1.4e15 / 10^18 = 0.0014 BTC ✓
```
同类问题：`tradeHistory.ts`（Trade History token size）、`orderHistory.ts`（Orders History 价格）、`OrderForm.tsx`（下单确认框 Token Size）。
> ℹ️ `orders.ts` 中 limit/stop-limit 的 increase 路径使用自消除公式：`(sizeDeltaUsd × 10^k / price)` 再 `formatUnits(result, k)`，等价于 `sizeDeltaUsd / price`，k 值无关，显示正确，保留原样。

## 排查规则
出现「**仅 BTC 等非18位小数 token 异常**」时，检查 `indexToken.decimals` 使用场景：
<table header-row="true">
<tr>
<td>场景</td>
<td>应用精度</td>
<td>原因</td>
</tr>
<tr>
<td>向合约发送/读取价格</td>
<td>`POSITION_SIZE_DECIMALS = 18`</td>
<td>FX100 oracle 统一 USD×10\^12</td>
</tr>
<tr>
<td>格式化链上 sizeInTokens</td>
<td>`POSITION_SIZE_DECIMALS = 18`</td>
<td>合约统一 18 位存储</td>
</tr>
<tr>
<td>用户输入 token 数量 → USD</td>
<td>`indexToken.decimals`</td>
<td>用户输入是原生精度</td>
</tr>
<tr>
<td>USDC collateral 价格/数量</td>
<td>`collateralToken.decimals = 6`</td>
<td>USDC oracle 格式 USD×10\^24</td>
</tr>
</table>
