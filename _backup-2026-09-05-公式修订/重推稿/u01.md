### 1.2 通用公式

```text
# ---- 无符号（Precision.sol） ----
applyFactor(uint value, uint factor)            = floor(value × factor / 1e30)
mulDiv(uint v, uint n, uint d)                  = floor(v × n / d)
mulDiv(uint v, uint n, uint d, roundUpMagnitude)= roundUpMagnitude ? ceil(v × n / d) : floor(v × n / d)
toFactor(uint value, uint divisor, roundUp)     = value == 0 ? 0
                                                : roundUp ? ceil(value × 1e30 / divisor)
                                                          : floor(value × 1e30 / divisor)
toFactor(uint value, uint divisor)              = toFactor(value, divisor, false)

# ---- 带符号：先取 |x| 计算、再补符号 ⇒ 语义是「向零截断」，不是 floor ----
applyFactor(uint value, int factor)             = sign(factor) × floor(value × |factor| / 1e30)
applyFactor(uint value, int factor, roundUp)    = sign(factor) × (roundUp ? ceil : floor)(value × |factor| / 1e30)
                                                  ← 转调下面的 mulDiv(uint,int,uint,bool)；v0.3.2 src 无调用点
mulDiv(uint v, int n, uint d)                   = sign(n) × floor(v × |n| / d)                        // L65-68
mulDiv(uint v, int n, uint d, roundUpMagnitude) = sign(n) × (roundUp ? ceil : floor)(v × |n| / d)     // L70-77
mulDiv(int v, uint n, uint d)                   = sign(v) × floor(|v| × n / d)   // L61-63，内部转调 L65 那式
mulDiv(int v, uint n, uint d, roundUpMagnitude) = sign(v) × (roundUp ? ceil : floor)(|v| × n / d)     // L91-98
toFactor(int value, uint divisor)               = sign(value) × floor(|value| × 1e30 / divisor)

# ---- 单位换算 ----
floatToWei(v)          = floor(v / 1e12)          // src 内仅 applyExponentFactor 使用
weiToFloat(v)          = v × 1e12
basisPointsToFloat(bp) = floor(bp × 1e30 / 10000)

# ---- 幂（v0.3.2 src 无调用点，列出以免误判分支） ----
applyExponentFactor(floatValue, exponentFactor)
  = 0                                                if floatValue < 1e30
  = floatValue                                       if exponentFactor == 1e30
  = weiToFloat(PRBMathUD60x18.pow(floatToWei(floatValue), floatToWei(exponentFactor)))   否则
```

源码锚点：`Precision.sol::applyFactor` / `::mulDiv` / `::toFactor` / `::floatToWei` / `::weiToFloat` / `::basisPointsToFloat` / `::applyExponentFactor`。

实现细节，复算时必须照做：

- `sign(x)` 在源码里写作 `x > 0 ? +result : -result`。`x == 0` 走负分支，但 `-0 == 0`，结果无差异。
- 全部 `mulDiv` 底层是 OpenZeppelin `Math.mulDiv`：乘积按 **512 位全精度**计算后再除，中间不溢出、不二次截断。BigInt 复算写 `(v * n) / d` 与之等价；ceil 写 `(v * n + d - 1n) / d`。`d == 0` 或结果超 uint256 时 revert。唯一的例外是 `basisPointsToFloat`，它写的是原生 `(bp * 1e30) / 10000`，乘法阶段会溢出——但 `bp` 来自返佣配置、量级极小，实际到不了。
- **拆分分母不会差 1 wei，重排乘除顺序才会。** 对正整数 m、n 有 `⌊⌊x/m⌋/n⌋ = ⌊x/(m·n)⌋`（ceil 同理 `⌈⌈x/m⌉/n⌉ = ⌈x/(m·n)⌉`），所以「先 `applyFactor` 除 1e30、再除 price」（如 `PositionPricingUtils::getPositionFeesAfterReferral`）与「一次性除 `1e30 × price`」（如 `MarketUtils::getFundingAmount`）在**同方向取整**下结果一致。真正会产生 1 wei 偏差的是：① 两次除法方向不同（floor 后再 ceil）；② 把「先乘后除」写成「先除后乘」。BigInt 复算按源码的乘除顺序照抄即可，不要自行合并或拆解。
- `toFactor` 的 `value == 0` 早退分支会**吞掉 divisor == 0**：`toFactor(0, 0) == 0` 而不是 revert。
- **向零截断 ≠ floor**（v0.3.1 文档完全没写这条）。验算：
  ```text
  applyFactor(10, factor = -0.25e30)
    |factor| = 25e28 → 10 × 25e28 = 25e29 → floor(25e29 / 1e30) = floor(2.5) = 2 → 补号 = -2
  按 floor 语义会得到 floor(-2.5) = -3，差 1。
  ```
  v0.3.2 走这条路径的典型字段是 `MarketUtils.sol::getNextFundingAmountPerSize` 里的 `positionPaysLp`（L581-587）：`applyFactor(uint openInterest, int factorPerSecond × dt)` 之和再 `/ int256(collateralTokenPrice.midPrice())`，后者是 Solidity 原生有符号除法，同样向零截断。该字段源码注释标明只用于 observability，不参与结算（§10）。

### 1.3 取整规则

- Solidity 无符号整数除法向下取整；**有符号整数除法向零截断**（`-7 / 2 == -3`，不是 `-4`）。JS `BigInt` 的 `/` 语义与之相同，可直接对齐；用 `Number` + `Math.floor` 复算负数会系统性差 1。
- `Calc.roundUpDivision(a, b) = (a + b - 1) / b`，等价 `ceil(a / b)`。边界要按 a、b 是否为 0 分四种，不能笼统写成「`b == 0` revert」（源码：`Calc.sol::roundUpDivision`）：`a == 0 && b > 0` → `(b - 1) / b == 0`；`a > 0 && b == 0` → `a - 1` 不下溢、随后除零 → **Panic 0x12**；`a == 0 && b == 0` → `0 + 0 - 1` 先下溢 → **Panic 0x11**；`a + b - 1` 超 uint256 → 加法溢出 Panic 0x11（这一点与 `Precision.mulDiv(..., true)` 的 512 位路径不同，后者不会中间溢出）。
- `Calc.roundUpMagnitudeDivision(int a, uint b)`：`a < 0` 时 `(a - b + 1) / b`，否则 `(a + b - 1) / b`，即「绝对值向上取整」。**v0.3.2 `src` 无调用点**——负数 PnL 的绝对值向上取整实际由 `Precision.mulDiv(int, uint, uint, roundUpMagnitude)` 完成（`PositionUtils.sol::_getPositionPnlUsd`），不要按这个函数名去找。

**仓位规模 / 执行价 / 仓位费用路径**内显式向上取整的全部调用点（方向一律偏向协议/LP，交易者吃亏的一侧）。本表不含 Relay Fee（§15）、执行费（§14）、LP 提现日对齐（§13）三条链路，它们各自的 ceil 见表下备注：

| 场景 | 表达式 | 源码锚点 |
| --- | --- | --- |
| 多头开仓执行价 | `ceil(index.max × (1e18 + spread) / 1e18)` | `PositionUtils.sol::getExecutionPriceForIncrease`（L631-636 / L645-650） |
| 空头开仓 `sizeDeltaInTokens` | `ceil(sizeDeltaUsd / executionPrice)` | `PositionUtils.sol::getExecutionPriceForIncrease`（L641） |
| 空头开仓预解析 tokens（喂点差用，非最终值） | `ceil(sizeDeltaUsd / index.min)` | `PositionUtils.sol::getIncreaseOrderSize`（L507） |
| 空头减仓执行价 | `ceil(index.max × (1e18 + spread) / 1e18)` | `PositionUtils.sol::getExecutionPriceForDecrease`（L722-727） |
| 多头部分减仓 `sizeDeltaInTokens` | `ceil(sizeInTokens × sizeDeltaUsd / sizeInUsd)` | `PositionUtils.sol::getDecreaseOrderSize`（L531） |

验算示例（负 PnL 拆分）：`totalPnl = -1000`、`sizeDeltaInTokens = 3`、`sizeInTokens = 7` → `-(ceil(1000 × 3 / 7)) = -(ceil(428.57…)) = -429`；若走**不带 `roundUpMagnitude` 的向零截断**分支会得到 `-428`，少扣 1。注意这里的对照项不是 floor：`floor(-3000 / 7) = -429`，与 `roundUpMagnitude = true` 结果相同，区分点是「向零截断 vs 绝对值向上取整」。

与之配对的显式向下取整（同样偏向协议）：

- 执行价：空头开仓、多头减仓都是 `floor(index.min × (1e18 - spread) / 1e18)`（`PositionUtils.sol` L639-640 / L653-654 / L719-720，源码写成原生 `*` 与 `/`，不走 `mulDiv`）。
- 仓位规模：多头开仓 `sizeDeltaInTokens = floor(sizeDeltaUsd / executionPrice)`（L637，仅 USD 计价分支；token 计价分支反过来是 `sizeDeltaUsd = sizeDeltaInTokens × executionPrice` 精确相乘、不取整）、空头部分减仓 `sizeDeltaInTokens = floor(sizeInTokens × sizeDeltaUsd / sizeInUsd)`（L535）、多头按 token 减仓的 `sizeDeltaUsd = floor(sizeInUsd × tokenDelta / sizeInTokens)`（L543）。
- 金额：正向资金费（交易者收）`floor(sizeInTokens × fundingDiffFactor / (1e30 × collateralTokenPrice.max))`、正 PnL 出金 `floor(pnlUsd / pnlTokenPrice.max)`、仓位费/UI 费 `floor(applyFactor(sizeDeltaUsd, factor) / collateralTokenPrice.min)`。

分支细节见 §3 / §4 / §6 / §10。E2E 一律用 `BigInt` 复算，不得用 JS `Number` 处理 1e30 量级。

### 1.4 Calc 库其余分支

⚠️ `clamp` 那一行的 `min > max` 语义是「参数配歪」类边界用例的直接取值依据：`fundingFactorPerSecond` 的两个界都是 DataStore 裸配置、调用前无归一，凡样本落在 `v >= min` 一侧，链上给的是 **max** 而不是 min；照「恒返回 min」取期望值会把正常行为报成缺陷。

`sumReturnUint256` 的全部调用点与各自的下溢行为（设计 OI 归零 / 抵押品扣光类用例时必须按这一列取期望，**不要一律按 Panic**）：

| 调用点 | 用途 | `a + b < 0` 时的实际行为 |
| --- | --- | --- |
| `DataStore.sol::applyDeltaToUint(key, int, errorMessage)`（L105） | 通用 uint 账本增减（OI、费用池等主力路径） | 调用前先判 `value < 0 && -value > currValue` → `revert(errorMessage)`，是**自定义字符串 revert**，不是 Panic 0x11 |
| `DataStore.sol::applyBoundedDeltaToUint(key, int)`（L133） | 允许被扣穿的账本项 | 先判同一条件 → **写 0 并正常返回 0**，不 revert |
| `IncreasePositionUtils.sol::increasePosition`（L107） | `collateralAmount` 叠加 `collateralDeltaAmount` | 调用前先判 `collateralDeltaAmount < 0 && collateralAmount < -collateralDeltaAmount`（L97-105）→ `revert FxErrors.InsufficientCollateralAmount(collateralAmount, collateralDeltaAmount)`，是**自定义错误、不是 Panic 0x11**；该守卫条件与下溢条件完全等价，L107 的 Panic 分支不可达 |
| `PositionPricingUtils.sol::getNextOpenInterestParams`（L329 long 分支 / L335 short 分支） | 计算点差用的 next OI | 先判 `usdDelta < 0 && -usdDelta > openInterest` → **next OI 置 0**，不 revert（源码注释：单 token 市场 OI 除二向下取整会让 usdDelta 超出 OI） |
| `MarketUtils.sol::getMinCollateralFactorForOpenInterest`（L878） | 累计开仓成本叠加 `openInterestDelta` | 无本地守卫，下溢 → **Panic 0x11** |
| `PositionUtils.sol::getExecutionPriceForIncrease`（L633/640/647/654）/ `::getExecutionPriceForDecrease`（L720/724） | 构造 `1e18 ± dynamicSpread` | 无本地守卫，下溢 → **Panic 0x11**（方向见下表） |

写 revert 类用例时记住：`src` 内真正抛 `Panic 0x11` 的只有最后两行这 3 个函数、7 处语句；前四行都会先抛各自的自定义错误或走「置 0 / 写 0」旁路。

执行价那两个函数里的下溢方向要分清（`dynamicSpread` 是**有符号**量，正值 = 价格朝对交易者不利的方向偏）：

| 语句形式 | 出现位置 | 下溢条件 |
| --- | --- | --- |
| `sumReturnUint256(1e18, dynamicSpread)` | 多头开仓执行价（L633/647）、空头减仓执行价（L724） | `dynamicSpread < -1e18`，即**负向**点差绝对值超过 100% |
| `sumReturnUint256(1e18, -dynamicSpread)` | 空头开仓执行价（L640/654）、多头减仓执行价（L720） | `dynamicSpread > 1e18`，即**正向**点差超过 100% |

两支下溢都是 Panic 0x11，而不是把执行价夹到 0。把点差限制在安全区间靠的是 `getDynamicSpread` 末尾的 `Calc.clamp(dynamicSpread, minDynamicSpread, maxDynamicSpread)`（`PositionPricingUtils.sol` L185）——两个界都是按 `marketIndex + isLong` 从 DataStore 读的配置项 `minDynamicSpreadKey` / `maxDynamicSpreadKey`，**不是库里的常量**（§4）。只要这两个配置项落在 ±1e18 内链上就到不了下溢；fork 上手动改参数越界是撞上 Panic 的现实来源。

## 2. Oracle 价格字段

> 版本对照：`src/price/Price.sol` 与 `src/oracle/` 下全部文件在 v0.3.1（`d9a7fd2`）与 v0.3.2（`13880f2`）**blob 完全一致**。本章相对 v0.3.1 文档的改动同样是修正与补全，不是版本变更。

### 2.1 中间价

```text
Price.midPrice(props) = floor((props.max + props.min) / 2)
```

源码：`Price.sol::midPrice`（先加后整除，`min + max` 为奇数时向下偏 0.5 个最小价格单位）。

### 2.3 Token 与 USD 换算

价格已按 token decimals 标度（见 §2.5），因此：

```text
usdValue        = tokenAmountRaw × price               // 结果是 1e30 精度的 USD
tokenAmountDown = floor(usdValue / price)
tokenAmountUp   = ceil(usdValue / price)               // Calc.roundUpDivision
```

选价侧与取整方向必须成对取用，v0.3.2 的实际调用点：

| 方向 | 选价侧 | 取整 | 源码锚点 |
| --- | --- | --- | --- |
| 交易者**支付**：仓位费 | `collateralTokenPrice.min` | floor | `PositionPricingUtils.sol::getPositionFeesAfterReferral`（L475，`applyFactor(sizeDeltaUsd, positionFeeFactor) / collateralTokenPrice.min`） |
| 交易者**支付**：UI 费 | `collateralTokenPrice.min` | floor | `PositionPricingUtils.sol::getUiFees`（L432） |
| 交易者**支付**：负向资金费 | `collateralTokenPrice.min` | **ceil** | `MarketUtils.sol::getFundingAmount(..., roundUpMagnitude = true)`，经 `PositionPricingUtils.sol::getFundingFees`（L399-405）写入 `negativeFundingFeeAmount`（§10） |
| 交易者**支付**：清算费 | `collateralTokenPrice.min` | **ceil** | `PositionPricingUtils.sol::getLiquidationFees`（L572-573） |
| 交易者**支付**：平仓瀑布待偿成本 | `collateralTokenPrice.min` | **ceil** | `DecreasePositionCollateralUtils.sol::payForCost`（L275） |
| 交易者**收取**：正向资金费 | `collateralTokenPrice.max` | floor | `MarketUtils.sol::getFundingAmount(..., roundUpMagnitude = false)` → `positiveFundingFeeAmount`（源码注释：claimable 金额应向下取整）（§10） |
| 交易者**收取**：正 PnL 从 LP 池出金 | `pnlTokenPrice.max`（`DecreasePositionUtils.sol` L244 直接赋成 `prices.collateralTokenPrice`） | floor | `DecreasePositionCollateralUtils.sol::processCollateral`（L114-115，源码注释：use pnlTokenPrice.max to minimize the tokens paid out） |

⚠️ 注意 `getFundingAmount` 的选价不是调用方指定的：函数内部 `uint256 price = roundUpMagnitude ? collateralTokenPrice.min : collateralTokenPrice.max;`，选价侧与取整方向被**硬绑定**在同一个 `roundUpMagnitude` 上，构造用例时不存在「min 价 + floor」这种组合。

口径小结（比 v0.3.1 文档的一句话准确）：**本表所列的仓位/费用调用点，付出侧一律用 `min` 价**（除以更小的价 ⇒ 需要交出的 token 更多），**收取侧一律用 `max` 价**（除以更大的价 ⇒ 池子付出的 token 更少）；取整方向则按调用点区分——仓位费/UI 费 floor，资金费与清算费、瀑布待偿按付/收方向分别 ceil / floor，出金 floor。不要把「用 min 价」和「向上取整」当成同一条规则。此结论限于本表，别的链路（如 §15 relay fee 的成本侧用 `nativeTokenPrice.max` 作乘数、`feeTokenPrice.min` 作除数）不套用。

`getFundingAmount` 的一个复算细节：源码写成 `Precision.mulDiv(positionSizeInTokens, fundingDiffFactor, Precision.FLOAT_PRECISION * price, roundUpMagnitude)`，分母是 `1e30 × price` 一次性相除（512 位全精度）。BigInt 建议照抄成 `(sizeInTokens * diffFactor) / (10n ** 30n * price)`（ceil 时 `+ 分母 - 1n`）；按 §1.2 的取整恒等式，拆成两次**同方向**整除结果相同，但拆成 floor + ceil 混用会差 1 wei。

### 2.4 Primary 价格与 Secondary 价格

两套价格来源不同、失效条件不同，必须分清；本文其余章节凡写 `prices.indexTokenPrice` / `prices.collateralTokenPrice` 的，一律指 **primary**。

**Primary price —— 本次交易随 oracle 报文写入、只在交易内有效**

- 写入链路：`OracleModule.sol::withOraclePrices` 修饰器 → `Oracle.sol::setPrices` → `_validatePrices` → `_setPrices` → `_setPrimaryPrice`；函数体执行完后修饰器调 `clearAllPrices()` 清空，因此 primary 不跨交易存活。
- 读取：`Oracle.sol::getPrimaryPrice(token)`（L148），三个分支——
  ```text
  token == address(0)      → 返回 Price.Props(0, 0)   // 不 revert
  price.isEmpty()          → revert EmptyPrimaryPrice(token)
                             // isEmpty 判定是 min == 0 || max == 0（Price.sol::isEmpty）
  否则                      → 返回 (min, max)
  ```
- `MarketUtils.sol::getMarketPrices(oracle, market)` = `MarketPrices(getPrimaryPrice(indexToken), getPrimaryPrice(collateralToken))`。
- 写入分支（`Oracle.sol::_setPrimaryPrice`，L322）：
  ```text
  price.min > price.max                       → revert InvalidMinMaxForPrice(token, min, max)
  primaryPrices[token] 非空（同一交易内重复写）  → revert PriceAlreadySet(token, existing.min, existing.max)
  写入 primaryPrices[token]，token 加入 tokensWithPrices
  若 timestamp > latestRecordedPrices[token].timestamp
      → 同步刷新 latestRecordedPrices[token] = {timestamp, price}   // 这就是 secondary 的回退数据源
  ```

**Secondary price —— 不随本次报文提供、需要「另一套价」的场景**

源码：`Oracle.sol::getSecondaryPrice(token, isADLStart)`（L161）→ `_getSecondaryPrice`（L165）：

```text
token == address(0)
    → 返回 Price.Props(0, 0)                       // 不 revert

ChainlinkPriceFeedUtils.getPriceFeedPrice(dataStore, token) 命中（该 token 登记了 PRICE_FEED）
    → 返回 Price.Props(p, p)                       // min == max，平价，无 bid/ask 点差

否则取 latestRecordedPrices[token]：
    price.isEmpty()                                → revert EmptySecondaryPrice(token)
    !isADLStart 且 timestamp + MAX_RECORDED_PRICE_AGE < block.timestamp
                                                   → revert MaxPriceAgeExceeded(timestamp, block.timestamp)
    否则                                            → 返回该 RecordedPrice 的 (min, max)
```

三个易错点：

1. 链上 Chainlink price feed 分支**优先于**历史记录，且返回 `min == max` 的平价 —— 用它算出来的 PnL、池子价值**不含任何点差**，与用 primary（bid/ask 张开）算出来的值天然不同。
2. `isADLStart == true` 时**跳过**陈旧检查，允许拿过期历史价开启 ADL 流程；`false` 时超出 `MAX_RECORDED_PRICE_AGE` 直接 revert。
3. `latestRecordedPrices` 只在 `_setPrimaryPrice` 内、且新 timestamp 更大时才更新，所以它永远是「某次历史交易写入过的 primary 价」，不是实时价；fork 环境上如果长时间没有交易写价，secondary 会停在很旧的一档。

v0.3.2 `src` 内 secondary 的全部调用点：

| 调用点 | `isADLStart` | 用途 |
| --- | --- | --- |
| `MarketUtils.sol::getNetObligation`（L175） | 由调用方透传 | ADL 风控的 index 价（§12） |
| `MarketUtils.sol::getGlobalNetObligationRatio`（L204） | 由调用方透传 | 全局池子 USD 的 collateral 价；只在循环的 `i == 0` 那一轮取一次（源码注释：所有市场共用同一 vault）（§12） |
| `BaseRelayRouter.sol::_payRelayFee`（L253、L254） | 固定 `false` | WNT 与 feeToken 的换算价（§15） |

### 2.5 价格来源、精度标度与写入校验

**精度标度**：链上价格是「1 个**最小单位** token 的 USD 价，按 1e30 精度表示」。

```text
priceScaled     = priceHuman × 10 ^ (30 - tokenDecimals)
usdValue(1e30)  = tokenAmountRaw × priceScaled
```

- 验算：USDC（6 位）$1 → `1 × 10^24`，`1 USDC = 1e6` raw × `1e24` = `1e30` = $1 ✓；18 位 token $2000 → `2000 × 10^12 = 2e15`，`1 token = 1e18` raw × `2e15` = `2e33` = $2000 ✓。
- feed 原始值 → priceScaled：`adjusted = Precision.mulDiv(feedPrice, multiplier, 1e30)`（floor），`multiplier` 位数 = `60 - feedDecimals - tokenDecimals`。源码与注释：`ChainlinkPriceFeedUtils.sol::getPriceFeedMultiplier`（键 `PRICE_FEED_MULTIPLIER`）、`PythPriceFeedUtils.sol::getPriceFeedMultiplier`（键 `PYTH_PRICE_FEED_MULTIPLIER`）、`ChainlinkDataStreamProvider.sol::_getDataStreamMultiplier`（键 `DATA_STREAM_MULTIPLIER`）。
- `multiplier == 0` → revert `EmptyChainlinkPriceFeedMultiplier` / `EmptyPythPriceFeedMultiplier` / `EmptyDataStreamMultiplier`。
- ⚠️ E2E 陷阱：multiplier 必须与该 token **链上登记的 decimals** 配对。index token **不保证 18 位**（合成 / mock token 常见 8 位或 18 位混用），改了 decimals 而 multiplier 没跟改，整条链路的价格会整体偏 `10^k`，**不 revert**，只表现为期望值全线对不上；同理，任何把 token 数量与 USD 互换的复算都必须按该市场 index / collateral token 各自登记的 decimals 走，不得写死 `/1e18`（主文档 §16.5 / §17.1 / §17.2 / §21 现文仍按 18 位写死，**以本节与 §1.1 为准**，待那几节改写时同步）。

**三个 provider 的 min/max 来源**（`IOracleProvider::getOraclePrice`）：

| Provider | min | max | timestamp | 标志位 |
| --- | --- | --- | --- | --- |
| `ChainlinkDataStreamProvider` | `bid`（买价，低） | `ask`（卖价，高） | `report.observationsTimestamp` | `shouldAdjustTimestamp() == true`、`isPythOnChainProvider() == false` |
| `ChainlinkPriceFeedProvider` | 见下 stablePrice 分支 | 同左 | `block.timestamp` | 两个标志位均 `false` |
| `PythPriceFeedProvider` | 见下 stablePrice 分支 | 同左 | `block.timestamp` | `shouldAdjustTimestamp() == false`、`isPythOnChainProvider() == true`（据此**跳过**参考价偏离校验） |

DataStream 分支（`ChainlinkDataStreamProvider.sol::getOraclePrice`）：

```text
登记 feedId == 0                       → revert EmptyDataStreamFeedId(token)
report.feedId != 登记 feedId            → revert InvalidDataStreamFeedId
report.bid <= 0 || report.ask <= 0     → revert InvalidDataStreamPrices
report.bid > report.ask                → revert InvalidDataStreamBidAsk
adjustedBid = floor(bid × multiplier / 1e30)
adjustedAsk = floor(ask × multiplier / 1e30)

spreadReductionFactor = DATA_STREAM_SPREAD_REDUCTION_FACTOR[token]
  > 1e30   → revert InvalidDataStreamSpreadReductionFactor
  == 0     → 不调整
  == 1e30  → adjustedBid = adjustedAsk = floor((adjustedAsk + adjustedBid) / 2)   // 完全收敛成平价
  其他      → halfSpread  = floor((adjustedAsk - adjustedBid) / 2)
             adjustedBid += floor(halfSpread × f / 1e30)
             adjustedAsk -= floor(halfSpread × f / 1e30)

min = adjustedBid，max = adjustedAsk
```

单价 feed 分支（`ChainlinkPriceFeedProvider.sol::getOraclePrice` 与 `PythPriceFeedProvider.sol::getOraclePrice` 同构）：

```text
未登记 priceFeed / pythPriceFeed        → revert EmptyChainlinkPriceFeed(token)
                                          // 注意 Pyth provider 复用的也是这个 Chainlink 命名的错误
Chainlink：feedPrice <= 0               → revert InvalidFeedPrice(token, price)
Chainlink：block.timestamp > feedTimestamp 且 差值 > PRICE_FEED_HEARTBEAT_DURATION[token]
                                        → revert ChainlinkPriceFeedNotUpdated
Pyth：getPriceNoOlderThan(id, heartbeatDuration) 由 Pyth 合约自行 revert
p = floor(feedPrice × multiplier / 1e30)

stablePrice = STABLE_PRICE[token]
  stablePrice > 0 → min = min(p, stablePrice)，max = max(p, stablePrice)
  否则             → min = max = p
```

即：稳定币可登记一个「锚价」，让 min/max 从平价张开成 `[min(p, anchor), max(p, anchor)]`。⚠️ E2E 陷阱：改 mock 稳定币价格时必须同步这个锚，否则 min/max 会意外张开（工作区已记录：`STABLE_PRICE` 锚未同步曾导致 SCN-070 失败）。

**写入路径的校验分支**（`Oracle.sol::_validatePrices` → `_setPrices`）：

```text
_validatePrices：
  tokens.length != providers.length              → revert InvalidOracleSetPricesProvidersParam
  tokens.length != data.length                   → revert InvalidOracleSetPricesDataParam
  tokens.length == 0                             → 返回空数组（后续 _setPrices 直接 return）
  逐 token：
    !isOracleProviderEnabled[provider]           → revert InvalidOracleProvider
    provider != oracleProviderForToken[oracle][token]
                                                 → revert InvalidOracleProviderForToken
    provider.shouldAdjustTimestamp()             → timestamp -= oracleTimestampAdjustment[provider][token]
    timestamp + MAX_ORACLE_PRICE_AGE < block.timestamp
                                                 → revert MaxPriceAgeExceeded
    !provider.isPythOnChainProvider() 且存在 Pyth 参考价 →
        对 min 与 max 各校验一次：
        floor(|price - refPrice| × 1e30 / refPrice) > MAX_ORACLE_REF_PRICE_DEVIATION_FACTOR
                                                 → revert MaxRefPriceDeviationExceeded

_setPrices：
  prices.length == 0                             → 直接 return（gasless relay 无需价格的场景）
  tokensWithPrices 非空                           → revert NonEmptyTokensWithPrices（防重入 / 防跨调用复用）
  逐条 _setPrimaryPrice 并 emit OraclePriceUpdate(token, minPrice, maxPrice, timestamp, provider)
  循环结束后再判 maxTimestamp - minTimestamp > MAX_ORACLE_TIMESTAMP_RANGE
                                                 → revert MaxOracleTimestampRangeExceeded
  写入 Oracle.minTimestamp / maxTimestamp
```

另有两条与价格同批的守卫：

- `Oracle.sol::validateSequencerUp`（L75）：`sequencerUptimeFeed == address(0)` 直接返回（本地 fork 常态）；`answer != 0` → revert `SequencerDown`；`block.timestamp - startedAt <= SEQUENCER_GRACE_DURATION` → revert `SequencerGraceDurationNotYetPassed(timeSinceUp, graceDuration)`。
- `OracleModule.sol::withSimulatedOraclePrices`：只用于 `simulate*` 预演。`primaryTokens.length != primaryPrices.length` → revert `InvalidPrimaryPricesForSimulation`；随后逐条调 `oracle.setPrimaryPrice(token, price, 0)`，再调 `oracle.setTimestamps(params.minTimestamp, params.maxTimestamp)`，函数体执行完**必定** revert `EndOfOracleSimulation`，因此不落状态。
  ⚠️ `OracleModule.sol` 的模块注释写着 “tokensWithPrices is not set in this function”，**与实现不符**：`Oracle.sol::setPrimaryPrice` 直接转调 `_setPrimaryPrice`，后者会执行 `primaryPrices[token] = price; tokensWithPrices.add(token);`，并且同样跑 `min > max → InvalidMinMaxForPrice`、重复写 → `PriceAlreadySet` 两个校验。模拟期与正式路径的唯一实质差别是 `timestamp` 传 `0`，`timestamp > latestRecordedPrice.timestamp` 恒不成立，**不会刷新 `latestRecordedPrices`**；以及末尾必定 revert 使全部写入回滚。这条注释↔实现分歧已记入差异台账。
