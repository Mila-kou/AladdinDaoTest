## 7. Proxy 结构与升级

### 7.1 Proxy 清单

| Proxy | 实现合约 | 初始化调用 | 锚点 |
| --- | --- | --- | --- |
| DataStoreProxy | DataStore | `initialize(bootstrapAdmin)` | `ignition/modules/Fx100Base.ts::dataStoreProxy` |
| LPVaultProxy | LPVault（构造参数 `_asset=usdc, _dataStore`） | `initialize(admin, withdrawDelay, epochDuration, epochStartTime, name, symbol, strategy, oracle)` | `ignition/modules/Fx100Base.ts::lpVaultProxy`、`src/vault/LPVault.sol::initialize` |
| ProtocolTreasuryProxy | ProtocolTreasury | `initialize(bootstrapAdmin)` | `ignition/modules/Fx100Fee.ts::protocolTreasuryProxy` |
| InsuranceTreasuryProxy | ProtocolTreasury（同一实现合约、独立实例） | `initialize(bootstrapAdmin)` | `ignition/modules/Fx100Fee.ts::insuranceTreasuryProxy` |

其余全部合约（handler、router、oracle provider、Reader、MarketFactory、RevenuePool、EventEmitter、Vault×2 等）**均为非代理直连部署**，升级 = 重部署 + 重新授权 + 引用切换。

### 7.2 Proxy 类型与升级机制（OZ 5.5.0）

`TransparentUpgradeableProxy` 解析自 `remappings.txt` 的 `@openzeppelin/contracts/` → OZ **5.5.0**（`lib/openzeppelin-contracts-upgradeable/lib/openzeppelin-contracts/contracts/proxy/transparent/TransparentUpgradeableProxy.sol`）。v5 语义要点（均为该文件源码证据）：

- 构造函数 `(logic, initialOwner, data)` 会**在内部 `new ProxyAdmin(initialOwner)`**，admin 地址为 immutable，不可更换；Ignition 传入的 `initialOwner` 是 `m.getAccount(0)` 即部署账户（`ignition/modules/Fx100Base.ts::bootstrapAdmin`）。
- 升级唯一入口：由 ProxyAdmin **owner** 调用 `ProxyAdmin.upgradeAndCall(proxy, newImplementation, data)`；不升级时无其他 admin 操作面（`_fallback` 只放行 `upgradeToAndCall` selector）。
- ProxyAdmin 地址获取：读各 Proxy 的 ERC-1967 admin slot（`0xb531...6103`，OZ 标准），或从部署日志/区块浏览器获取。仓库内无读取脚本——**待补**。

**仓库内无升级脚本**：`scripts/`、`ignition/` 已逐文件核对，不存在任何 `upgradeAndCall` 调用或升级模块——原位升级操作待补脚本，手工路径见 §13。

### 7.3 v0.3.1 → v0.3.2 各 Proxy 是否需要升级（diff 证据）

| 合约 | diff 结论 | 是否需要升级 |
| --- | --- | --- |
| DataStore | `src/data/DataStore.sol` 不在 61 个变更文件中；同目录 `src/data/Keys2.sol` 仅注释变化（diff 逐行核对，无代码变化） | **不需要** |
| ProtocolTreasury（两实例） | `src/fee-distribute/` 整目录在 diff 范围内无变化（`git diff --stat d9a7fd2..13880f2 -- src/fee-distribute` 为空） | **不需要** |
| LPVault | `src/vault/LPVault.sol` 本身未变，但父类 `src/vault/VaultBase.sol` 变化：新增 `ErrorStrategyWithdrawalMismatch` 错误 + `_transferAssetsOut` 缺口提款改为「先转自有余额，再向 Strategy 提缺口并校验实际到账 == 缺口，否则 revert」 | **需要**：部署新 LPVault 实现（构造参数不变：usdc、dataStore），由 LPVaultProxy 的 ProxyAdmin owner 执行 `upgradeAndCall(lpVaultProxy, newImpl, "0x")` |

LPVault 升级的存储布局安全性：`VaultBase.sol` 的 diff 仅新增 error 声明与函数内逻辑，**未新增/调整任何状态变量**（diff 逐行核对）——存储布局兼容。建议升级前用 forge 标准工具（`README.md` 列明 forge 工具链）对新旧实现各跑一次 storage-layout 输出比对，仓库内无固化脚本——待补。

| DataStore | `initialize(address admin)`：`__AccessControl_init` + `__AccessControlEnumerable_init` + 授 `DEFAULT_ADMIN_ROLE` | `initializer` | constructor 内 `_disableInitializers()` | `src/data/DataStore.sol::initialize` |
| LPVault | `initialize(admin, withdrawDelaySeconds, epochDuration, epochStartTime, name, symbol, strategy, oracle)`；要求 `epochStartTime < block.timestamp` 否则 `StartTimeInThePast` | `initializer` | constructor 内 `_disableInitializers()` | `src/vault/LPVault.sol::initialize` |
| ProtocolTreasury | `initialize(address admin)` | `initializer` | **无 constructor、无 `_disableInitializers()`**（连同父类 `src/fee-distribute/` 全目录 grep 核对）——裸实现合约上的 `initialize` 可被任意人抢先调用；因 Treasury 实现无危险 admin-only 资金逻辑受 impl 状态影响（资金都在 Proxy 侧），风险有限，但建议部署后对两个 Treasury 裸实现补一笔 `initialize` 占位或在下版加固——**观察项** | `src/fee-distribute/ProtocolTreasury.sol::initialize` |

- 仓库 `src/` 内 **无任何 `reinitializer(n)`**（全量 grep 证据：仅上述 3 处 `initializer`）。因此：
  - v0.3.2 LPVault 实现升级时 `upgradeAndCall` 的 `data` 必须传空（`"0x"`），**不得**再调 `initialize`（proxy 已初始化，重调必 revert `InvalidInitialization`）。
  - v0.3.2 没有需要随升级执行的存储迁移函数；子账户/动态点差等新状态全部走 DataStore 键值（§14），不依赖 reinitializer。
- diff 范围内三个 initialize 的签名与逻辑均无变化（`src/data/DataStore.sol`、`src/fee-distribute/` 不在变更清单；`src/vault/LPVault.sol` 未变），全新部署与 v0.3.1 行为一致。

### 11.1 Oracle 侧

### 13.2 原位升级的执行顺序建议（含停机窗口）

1. 冻结入口（可用 Config feature-disable 键或前端下线；具体开关键清单见 04-参数目录——待该材料展开）。

3. 重部署 13.0 表列的无状态层（含新 Config、全部 handler/router/reader、变化库并重链接）。
4. DataStore 角色切换：给新地址授 CONTROLLER/ROUTER_PLUGIN（§9.2 矩阵）、`revokeRole` 回收旧 handler/router/Config 的对应角色（OZ AccessControl 标准函数，DEFAULT_ADMIN_ROLE 持有者执行）；LPVault CONTROLLER_ROLE、ReferralStorage setHandler 同步换新。

每步失败处理：第 2 步失败（upgradeAndCall revert）→ 状态未变，排查后重试；第 3-4 步部分完成 → 旧合约仍持角色可继续服务，属可中断区间；第 5 步前 Relay 必须保持关闭（§14.3）。

## 14. 高风险专节：ABI / EIP-712 / 存储变化

### 14.1 子账户 4 槽位（存储模型重构）

- `src/subaccount/SubaccountUtils.sol::MAX_SUBACCOUNT_SLOTS = 4`；存储从地址集合改为 DataStore 三键槽位模型：`FX100Keys.sol::subaccountSlotKey / subaccountSlotSubaccountKey / subaccountSlotActiveKey`（`(SUBACCOUNT_SLOT*, account, index)` 哈希，index 0..3）。
- ABI 变化：`SubaccountRouter.addSubaccount(address subaccount, string slot)`（新增 slot 参数）；Reader 新增槽位读取（`src/reader/Reader.sol::MAX_SUBACCOUNT_SLOTS` 循环）。
- **不涉及 Proxy 存储布局**（数据在 DataStore 键值），但 v0.3.1 旧授权数据无迁移→自然失效；迁移/重授权方案待补（13.1 #5）。

### 14.2 动态点差 int256（符号翻转风险）

- 新配置键 `FX100Keys.sol::MIN_DYNAMIC_SPREAD / MAX_DYNAMIC_SPREAD`，维度 `(marketIndex, isLong)`，**int256**，经 `Config.setInt` 写入（§10.2）；1e18 精度；样例 clamp 范围 [−0.02, 1.0]，即原始值 [−20000000000000000, 1000000000000000000]。
- 消费方（SDK/keeper/索引）必须按有符号解码；无符号解码负值会得到巨大正数。
- 强平与 ADL 路径禁止负点差、普通订单允许（commit `7d639c9`）——keeper 判断与前端预览需分路径。
- v0.3.1 Config 无这两个 allowlist 键（§13.0）→ 原位升级必须先换 Config。

### 14.3 全局 COLLATERAL_TOKEN（漏配即 Relay 全挂）

- 键 `src/constants/FX100Keys.sol::COLLATERAL_TOKEN`（全局，无市场维度）；两条写入路径：Ignition `Fx100Role.ts::SetCollateralToken`（全新部署自动）与 `configureGeneral.ts`（幂等补写）。
- 消费点：`src/router/relay/BaseRelayRouter.sol` L198-204——`fee.feeToken != dataStore.getAddress(COLLATERAL_TOKEN)` 即 revert `UnexpectedRelayFeeToken`。**原位升级若漏写该键**，getAddress 返回零地址，所有携带非零 feeToken 的 relay 请求全部 revert。升级顺序必须「先写键、后开 Relay」（13.2 第 5 步）。

### 14.4 Relay EIP-712（旧签名全体失效）

- 域：name=`Fx100RelayRouter`、version=`1`、chainId、**verifyingContract**（`src/router/relay/RelayUtils.sol::getDomainSeparator`）。v0.3.2 重部署 RelayRouter/SubaccountRelayRouter → verifyingContract 变化 → 即便结构不变旧签名也全部失效。
- `SUBACCOUNT_APPROVAL_TYPEHASH` 结构变更为 `SubaccountApproval(address subaccount,string slot,bool shouldAdd,uint256 expiresAt,uint256 maxAllowedCount,bytes32 actionType,uint256 nonce,uint256 desChainId,uint256 deadline,bytes32 integrationId)`（`src/router/relay/RelayUtils.sol::SUBACCOUNT_APPROVAL_TYPEHASH`；struct 定义 `src/subaccount/SubaccountUtils.sol::SubaccountApproval`）；另有 `REMOVE_SUBACCOUNT_SLOT_TYPEHASH` 新类型。签名服务对接以链上 `getDomainSeparator()` 读值为准（13.1 #4）。
- 错误 selector 变化（如 `EmptyTokenTranferGasLimit`→`EmptyTokenTransferGasLimit`，01 文档 §10）——依赖 selector 解码错误的监控/前端需同步。

## 16. 失败处理

| 场景 | 处理 | 证据 |
| --- | --- | --- |
| Ignition 部署中断 | 部署状态记录于 `ignition/deployments/<id>/`（journal + artifacts + deployed_addresses.json，目录约定证据 `scripts/verifyTenderly.ts::resolveDeploymentPath`）；重跑同一 deploy 命令续跑未完成 future（插件标准行为，未实测） | — |

| `ensureMarket` 报 index 冲突 | 说明目标 token 已存在于其他 marketIndex——输入文件市场顺序与链上不一致，**不得强行创建**；核对 `MARKET_LIST` 后修正输入 | `scripts/config/writers.ts::ensureMarket` |
| configure 报 `missing required input` | 补 `FX100_*` 环境变量或 `--config` 等 argv | `scripts/config/runtime.ts::requireInput` |

| Tenderly verify 失败 | 脚本自带 already-verified 豁免、rate-limit 5s 重试、末尾失败清单；对失败项用 `--addresses` 精确重跑 | `scripts/verifyTenderly.ts::main` |
| `upgradeAndCall` revert | 检查调用者是否为该 Proxy 专属 ProxyAdmin 的 owner（每个 Proxy 一个独立 ProxyAdmin，勿混用）；data 是否为 `"0x"`（§8） | OZ `TransparentUpgradeableProxy.sol` |
