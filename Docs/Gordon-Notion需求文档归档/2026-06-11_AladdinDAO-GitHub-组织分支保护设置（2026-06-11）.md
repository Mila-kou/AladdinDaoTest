## 一、唯一的管理入口
**组织级 Ruleset：****`org-default-branch-protection`**（id `17529022`，状态 Active）
全组织的默认分支保护统一由这一条组织级 Ruleset 管理。原先散落在各 repo 的经典 Branch protection rules（73 条）和重复的 repo 级 ruleset（6 条）已全部清理，不再存在双轨规则。

## 五、规则叠加原理
GitHub 对同一分支命中的多条规则（组织级 + repo 级）**聚合取最严格**，不会互相覆盖或冲突。某条规则未设置的项不会放松其他规则的约束。注意：**bypass 名单各条规则独立**，互不继承。

## 七、运维说明
- **修改规则**：只需改组织级 Ruleset 这一处，全组织生效（如调整 approve 数量、增删 bypass）
- **API 管理**：需要 token 带 `admin:org` scope；只读/repo 级操作 `repo` scope 即可
- **未启用项**：「PR 合并前分支必须最新（up-to-date）」未开启——需要各 repo 先配置 CI status check 才有意义
- **fork repo**：如某个 fork 转为内部主导开发，需手动把它从 Ruleset 的排除名单中移除
