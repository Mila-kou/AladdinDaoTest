## 描述（Text 属性）

【现象】market 单因 keeper 未执行 / 超出 slippage 等原因停在 Pending 后，用户完全无法取消，保证金锁死在订单里。实测有 5 笔停留 2 天以上的 Pending market 单，Actions 列没有任何按钮可点。

【根因：合约允许，前端不给入口】
链上机制本来就是完整的，且正是「刚发出来不能取消、超时后可以取消」这套：
```text
  OrderHandler.sol:214-216
    if (Order.isMarketOrder(order.orderType())) {
        validateRequestCancellation(order.updatedAtTime(), 'Order');
    }
  BaseHandler.sol:33-39
    uint256 requestAge = block.timestamp - createdAtTime;
    if (requestAge < requestExpirationTime) revert RequestNotYetCancellable(...);
```
真链实测 REQUEST_EXPIRATION_TIME = 3600s（60 分钟）。即 market 单 60 分钟内不可取消（防止用户与 keeper 抢执行），超过就允许用户自己取消拿回保证金。限价单无此 gate，随时可取消。

前端把这条路堵死了，两处：
```text
  OpenOrders.tsx:248   if (order.type === 'MARKET') return MARKET_ORDER_CANCEL_DISABLED_REASON;
  OpenOrders.tsx:548   {data.type !== 'MARKET' && ( ...cancel 按钮... )}   ← 整个不渲染
```
所以 market 单连一个禁用态的按钮都看不到，用户无从得知「等一会就能取消」。

【建议改法】
1. market 单也渲染 cancel 按钮，去掉 type !== 'MARKET' 的整体隐藏；
2. 禁用条件改成按订单年龄算：requestAge < REQUEST_EXPIRATION_TIME 时禁用，tooltip 显示倒计时（例如「keeper 执行中，还需 12:34 后可取消」），到点自动变为可点；
3. REQUEST_EXPIRATION_TIME 必须从链上 DataStore 读，不要写死 —— 它是配置项，风控随时可能调整；
4. 倒计时基于链上 block.timestamp 而不是浏览器本地时间。fork 环境时钟会漂，用本地时间会算错。

【顺带提给风控：60 分钟这个值需要重新评估】
MAX_ORACLE_PRICE_AGE 只有 60 秒，意味着一笔 market 单若 60 秒内没被执行，之后永远不可能执行成功（oracle 报价必然已过期），却还要再等 59 分钟才允许取消 —— 这 59 分钟是纯粹的白等，用户体验上等同于资金被冻结一小时。建议评估调到 5~10 分钟：既留足 keeper 重试窗口，又不让用户干等。此项属链上参数，未改动。

## 复测（复测属性）

【已验证关闭 2026-08-04】develop 7846e2ee "fix: OC-23 cancel pending market order" 已修，本单提的 4 条实现要点逐条核对通过：
① Cancel 按钮已对 market 单渲染 —— 它在 type !== 'MARKET' 判断之外；那个判断现在只挡 Edit，这是对的（market 单没有价格可编辑）。
② 禁用态改为新增 hook useMarketOrderCancelGate 的四态机（pending / checking / locked+倒计时 / ready），不再是一句「market orders cannot be cancelled」。
③ REQUEST_EXPIRATION_TIME 从 DataStore 读（REQUEST_EXPIRATION_TIME_KEY），未写死，代码注释也写明「risk can retune it」。
④ 倒计时锚定链上观测到的 block.timestamp 而非浏览器本地时间 —— fork 上时钟会漂，这条很关键。
另外 validateMarketCancellation 还在点击时二次校验，未到时间的点击不会发出必然 revert RequestNotYetCancellable 的交易。
附带 marketOrderCancel.test.ts 单测 10 个，本地全部通过。
测试分支 merge commit 4d05423a。
★ 遗留（未阻塞关闭，属链上参数）：真链 REQUEST_EXPIRATION_TIME = 3600s，而 MAX_ORACLE_PRICE_AGE 仅 60s，意味着 market 单 60 秒未执行后就永远不可能成功，却仍要再等 59 分钟才允许取消。建议风控评估调到 5~10 分钟。此项需另行决策，不在前端范围。

① Pending 的 market 单能看到 cancel 按钮（新单为禁用态 + 倒计时 tooltip）；② 订单年龄超过链上 REQUEST_EXPIRATION_TIME 后按钮自动可点，点击成功取消并退回保证金；③ 未到时间点击应被拦在前端，不要发出必然 revert RequestNotYetCancellable 的交易；④ 把链上 REQUEST_EXPIRATION_TIME 调成较小值后前端倒计时应随之变化（验证是读链上而非写死）；⑤ 限价单行为不受影响，仍可随时取消。
