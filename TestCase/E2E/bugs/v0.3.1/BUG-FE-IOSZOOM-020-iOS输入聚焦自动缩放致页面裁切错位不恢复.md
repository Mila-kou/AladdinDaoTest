# BUG-FE-IOSZOOM-020 · iOS 输入聚焦自动缩放致页面裁切错位不恢复

## 现象

移动端（iOS，MetaMask 内置浏览器实测）在 **调整保证金** 等弹窗内点击金额输入框输入数值并确认后，页面发生**自动放大/平移且不自动恢复**：

- 视口只保留部分内容，另一部分超出屏幕被裁切，需要**手动捏合缩放/拖动**才能看全；
- 裁切方向不定（实测有右缘裁切与左缘裁切两种现场）；
- **偶发卡住**：缩放/平移状态无法通过滚动恢复，跨弹窗残留（关闭弹窗打开另一弹窗仍处于错位状态）。

执行人原话：「在 adjust margin 页面输入金额确认后会出现页面不能自适应的情况，页面只保留了一部分数据，另外一部分超出需要手动调整，有的时候会被卡住。」

## 复现步骤（执行人 iPhone 实测,2026-08-30 18:30 前后）

1. iOS MetaMask 内置浏览器打开 fx100-dev 交易页，连接钱包，持有任意仓位；
2. 持仓卡 → 调整保证金 → 点击金额输入框（iOS 软键盘弹起）→ 输入如 `10`；
3. 确认/收起键盘后观察页面。

## 实际结果（截图证据，见 manual-runs/2026-08-30-移动端smoke 会话记录截图 157/158/159）

- 截图 158（18:30，调整保证金·ENA + iOS 键盘）：弹窗**右缘裁切**——「可用余额 186.42 U…」「353.03 US…」「SHO…」右端截断，关闭按钮半个在屏外；
- 截图 157（18:29，持仓区）：页面右缘裁切——保证金/净值数值「361.4…」「347.2…」截断；
- 截图 159（18:31，LINK 止盈/止损弹窗）：**左缘裁切**——标题、「止盈价格」「LONG」徽标左端截断，说明错位状态**跨弹窗残留**。

## 期望结果

- 弹窗内输入、软键盘弹起/收起后，页面/弹窗布局应保持或恢复 100% 视口自适应，无需手动缩放；
- 任何时刻弹窗完整可见（E2E-TRD-053 验收标准：弹窗不超屏、键盘不遮挡当前输入与 CTA）。

## 初步定位（供前端参考,未看源码,待证）

症状符合 **iOS Safari/WKWebView 对 font-size < 16px 的输入框聚焦时自动放大**的已知行为：聚焦触发 viewport 缩放，收起键盘后不回弹，形成"页面比视口宽 + 停留在平移位置"的观感。候选修复：

1. 弹窗内 input 字号 ≥16px（推荐,无可访问性代价）；
2. 或 viewport meta 增加 `maximum-scale=1`（禁掉聚焦缩放,但牺牲用户手动缩放,谨慎）；
3. 键盘收起/弹窗关闭时校正 scroll/zoom 状态。

## 影响与定级理由

- 交易操作全程可完成（链上核对确认调整保证金/止盈止损等均正常发出与执行）,资金无影响；
- 但每次输入后需手动调整视口才能看全数据、偶发卡住,移动端核心操作路径体验受损明显 → **S3**（操作可恢复的前端交互缺陷；若后续确认"卡住"不可恢复需强刷,升 S2）。

## 备注

- 仅移动端复现;桌面 Chrome（web 轮 Round 1-3）无此问题。
- **2026-08-30 晚 Rabby 复测**：iOS Rabby 内置浏览器同样复现（截图 183 止盈止损弹窗左缘裁切、189/190 交易页左缘持续裁切态）→ 非 MetaMask 特有，**iOS WebKit 内核通用**。
- 记录员桌面移动仿真（Android UA）未观察到同症状,疑 iOS 特有;其他 iOS 浏览器（Safari 本体、其他钱包内置浏览器）待复测。
