# FX100 自动化框架与环境方案

## 1. 目标

将 `TestCase/E2E` 已设计的 80 条用户级场景自动化，同时保持三个真实性：

1. 页面/钱包类用例由 Trade 页面人工或浏览器自动化发起；
2. 协议交易类用例由 Trader/Keeper 私钥真实签名，不把前端可用性当成交易执行前置条件；
3. 交易经过真实协议合约、回执、事件和 Keeper，结果由 Reader/链上状态、事件/余额多源核对。

测试侧只控制在共享环境无法稳定构造的前置条件，例如 Oracle 极端价格、Funding/OI/EMA、时间推进和清算边界。

## 2. 环境拓扑

| 环境 | 主要任务 | 约束 |
|---|---|---|
| dev-readonly | 页面和公共数据可用性 | 不写链上状态 |
| tx-fork | Inline Keeper 普通交易 | default-mock 双 Mock Oracle；真实签名；每例恢复 baseline |
| oracle-fork | 可控价格和单市场极端价格 | default-mock 双 Mock Oracle；关闭运行期 State Sync；串行 |
| time-fork | Funding、EMA、保护期、超时、Funding-only 清算 | 可改 Oracle 和区块时间；串行 |
| base-sepolia | Service Keeper 专项和真实参数核对 | 标准 Market/Oracle；不部署 Mock；不改 Oracle/时间 |

单线程只能防止并发污染，不能防止顺序污染。任何写状态用例都必须在执行前恢复 baseline，执行后验证恢复结果。

只有 Service Keeper 专项使用链下 keeper。`evm_revert` 只回滚链上状态，不会回滚 Redis 事件游标、队列和 producer 内存游标；若将 Service Keeper 指向 Fork，回滚后必须停止 keeper、清理当前版本与 chainId 的 keeper 键并重启。普通 `tx-fork` 回归使用 Inline Keeper，不依赖这些外部游标。

## 3. 市场分层

### 已部署真实市场

用于常规市价/限价、仓位管理、保证金、费用和页面回归。参数只读，执行前后读取真实状态。

### Mock Market Bundle（默认别名 `default-mock`）

一个 Bundle 对应一套可直接被用例解析的 Market 资源：专属 Index Token + Index Mock Oracle、环境共享 USDC + USDC Mock Oracle、Synthetic Market、Vault 和参数 Profile。同一 Fork 可登记多个 Bundle Alias；现有用例默认使用 `default-mock`。复用真实核心协议，用于交易账本、极端价格、Funding Clamp、取整、OI 上限、清算和 ADL。

部署后必须同时被三层识别：

```text
协议 Market/DataStore/Oracle
        ↓
页面市场配置与交易入口
        ↓
Reader / Indexer / 历史数据
```

如果页面或 Indexer 不能识别新市场，不能仅凭“链上已注册”宣告 E2E 环境准备完成。

## 4. 单条用例生命周期

```text
恢复 baseline
→ 应用市场 Profile
→ 构造账户、仓位、OI、Oracle 或时间前置条件
→ 读取并保存 before 状态
→ 页面/钱包用例执行 UI 动作，协议交易用例发送真实签名交易
→ 等待创建交易 receipt/event
→ Keeper 执行系统动作
→ 等待执行交易 receipt/event
→ 读取 after 状态
→ 核对页面、Reader、事件与余额
→ 保存 Trace/截图/tx/区块/链上快照
→ 恢复 baseline
```

禁止用固定 sleep 代替 receipt、event、Reader 或页面状态等待。

## 5. Oracle 原则

- 测试 Oracle 自身：必须走真实签名、时间、偏差和验证路径；
- 测试订单/仓位/清算对价格的反应：允许通过 Mock Oracle 构造前置价格；
- 所有价格同时记录 `min/max/timestamp`；
- 修改 index price 时默认不改 collateral price；只有脱锚用例才改 collateral；
- 场景代码只调用 Oracle Driver，不能直接散落 storage slot。

## 6. 时间原则

- 浏览器时间只影响页面计时器；
- Funding、EMA、保护期和 validFrom 使用链上区块时间；
- 推进链上时间后必须产生新区块；
- 时间 Fork 固定起始区块并关闭运行期 State Sync；
- `0/1/3599/3600/3601s` 分别从相同 baseline 执行。

## 7. 数据证据

失败用例必须保存：页面 Trace/截图、RPC/console 错误、tx hash、orderKey、区块号和时间、Oracle min/max、Long/Short OI、Raw/EMA Skew、Funding 参数与 factor、市场/仓位 per-size、PositionFees、Reader、余额和关键事件。

最终报告按 `SCN-xxx` 输出 PASS/FAIL/BLOCKED/SKIP，但并行执行过程不直接修改原始 Markdown 清单。
