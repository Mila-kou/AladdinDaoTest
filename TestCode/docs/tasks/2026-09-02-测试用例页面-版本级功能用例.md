## 要求

1. **两类用例分开展示**：共享场景用例（SCN-001～080，现有逻辑不变）与版本功能用例（CT/XT/FT）各一个分区或页签；功能用例按矩阵的节（A 部署与交易基线、B1 MarketIncrease、B2 LimitIncrease、…）分组。
2. **版本维度**：功能用例挂在 `versions/<release>/` 下，页面按 CURRENT.json `primary.version` 默认显示当前版本，允许切换到有 `versions/` 目录的其它版本；共享场景用例显示"在当前版本的适用性/期望差异"来源链接即可，不必展开。
3. **编号识别**：功能用例 ID 正则 `^(?:CT|XT|FT)-[A-Z0-9]+(?:-[A-Z0-9]+)*-\d{3}$`；`src/reporting/schema.ts`（第 16、121 行 `^SCN-\d{3}$`）、`test-cases.ts`（第 61～64 行 7 列详情行规则）、`test-case-overrides.ts`、`playwright-reporter.ts` 的 ID 提取都只认 SCN，需要为功能用例另开一条解析/校验路径，**不要放宽 SCN 路径的校验**。
4. **每条功能用例至少显示**：ID、优先级、标题、本轮入口（RPC / 页面）、Trader 编号与地址（来自第 9 列或 case-traders.json）、按层状态（合约层 / 前端层 / 交叉一致）。状态来源 results.md；没有记录的显示 NOT_RUN；FT 行未走页面时前端层为 GAP。
5. **准入提示**：页面顶部显示 `admission` 总开关和 `admissionScope` 各项；tx-fork:contract 非 READY 时，功能用例区块标"当前环境不可开跑"。
6. **不引用 SCN 编号及相关内容**：功能用例的展示、分组、依据列不得出现 SCN 编号或 scenarios/设计索引链接（这是版本文档的既定规则，矩阵文件本身已不含 SCN）。
7. 现有 SCN 页面、看板 KPI、`rebuild-latest` 行为保持不变；`npm run dashboard:verify` 通过。
