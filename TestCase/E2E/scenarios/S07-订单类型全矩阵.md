# S07 订单类型全矩阵

**目标**：在不改动原 SCN-001～064 编号的前提下，补齐 7 种主订单类型的多空方向、精确触发边界、可接受价、失败恢复和关联单清理。

**阅读前置**：[订单类型说明与覆盖矩阵](../04-订单类型说明与覆盖矩阵.md)。

**主要依据**：`Order.OrderType`、`BaseOrderUtils.validateOrderTriggerPrice`、`getExecutionPriceForIncrease/Decrease`、autoCancel 清理逻辑和 Order 流程文档。

## 必须执行的数据矩阵

### A. 触发边界数据

设 `P = 建单时当前参考价`，`T = triggerPrice`，`δ = 当前市场合约价格的最小单位`。设置 Oracle 双价时必须同时保证 `min <= max`。

| 类型/方向 | 未触发 | 恰好触发 | 越过一单位 |
|---|---|---|---|
| `LimitIncrease` 多 | `max=T+δ` | `max=T` | `max=T-δ` |
| `LimitIncrease` 空 | `min=T-δ` | `min=T` | `min=T+δ` |
| `StopIncrease` 多 | `max=T-δ` | `max=T` | `max=T+δ` |
| `StopIncrease` 空 | `min=T+δ` | `min=T` | `min=T-δ` |
| `LimitDecrease` 多 | `min=T-δ` | `min=T` | `min=T+δ` |
| `LimitDecrease` 空 | `max=T+δ` | `max=T` | `max=T-δ` |
| `StopLossDecrease` 多 | `min=T+δ` | `min=T` | `min=T-δ` |
| `StopLossDecrease` 空 | `max=T-δ` | `max=T` | `max=T+δ` |

未触发组必须保持 Waiting，不创建/减少仓位且 OI 不变；等于和越过组必须可执行。每组都要记录 Oracle `min/max`，不能只保留 K 线截图。

### B. 市价可接受价数据

设 `A = acceptablePrice`。每个象限至少执行 `executionPrice=A` 和向不利方向越过 `δ` 两组。

| 象限 | 边界可成交 | 越界应取消 |
|---|---|---|
| 开多 `MarketIncrease long` | `executionPrice=A` | `executionPrice=A+δ` |
| 平空 `MarketDecrease short` | `executionPrice=A` | `executionPrice=A+δ` |
| 开空 `MarketIncrease short` | `executionPrice=A` | `executionPrice=A-δ` |
| 平多 `MarketDecrease long` | `executionPrice=A` | `executionPrice=A-δ` |

## 执行约束

- SCN-069 的 24 个数据集和 SCN-070 的 8 个数据集是必做子项，不得用一条代表数据将整个场景标 PASS。
- SCN-071 如果当前页面对触发单使用哨兵 `acceptablePrice`，无法仅从 UI 构造 Frozen，允许在可控环境注入冻结订单；页面 E2E 仍必须验证冻结显示、资金语义和恢复操作，并在证据中标注注入方式。
- 触发单的 `triggerPrice` 只决定能否执行；所有成交价断言都必须使用实际 `executionPrice`。
- 每个用例至少留存：页面关键状态、orderKey、tx hash、区块号、Oracle `min/max`、Reader/事件类型与方向。

## 套件退出条件

- 7 种主 `OrderType` 均有明确事件/页面证据，`Adl` 有二级类型证据；
- 4 类触发单的多空与三边界数据集全部完成；
- 市价四象限的边界成交和越界取消全部完成；
- Cancelled、Frozen、Oracle Revert 的订单和资金语义均有证据；
- 所有测试账户无仓位、无待执行订单、无孤儿 TP/SL，Oracle/风控参数已恢复。
