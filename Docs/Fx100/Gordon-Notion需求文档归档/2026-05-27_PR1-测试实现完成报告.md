## 实现中发现的重要事项
### 1. Oracle 价格精度（oracle-scale vs FLOAT_PRECISION）
- `_setMockPrice(token, 2000e30, 2000e30)` 设置的是 Chainlink raw 价格（FLOAT_PRECISION 单位）
- 经 `priceFeedMultiplier = 1e12` 转换后，合约内存储的执行价格单位为 `oracle-scale = 1e12`
- 集成测试中比较执行价格时需用 `ORACLE_PRICE = 2000 * 1e12`，而非 `2000 * FLOAT_PRECISION`
- Reader 函数 `getExecutionPrice` 接收 `MarketPrices` 时，`indexTokenPrice` 也须用 `1e12` scale
### 2. handleEarlyReturn("pnl") 只能通过清算触发
- 普通 MarketDecrease 订单在亏损超出抵押品时会被**静默取消**（订单 cancelled，头寸保留）
- `handleEarlyReturn("pnl")` 的代码路径需通过 `LiquidationHandler.executeLiquidation` 才能覆盖
- TC-DCP-02b 专门使用 liquidation 来验证该路径
### 3. 批量 claimWithdrawRequests 的 epoch 推进
- `_advanceEpoch` 每次调用只推进一个 epoch
- 多个不同 unlockAt 的请求需要多次 `claimWithdrawRequest` 调用来逐步推进 epoch
- 实际执行顺序：epoch\[0\]→\[1\]→\[2\]→\[3\]，每次 claim 推进一步
### 4. FIXME-001 说明（TC-TSO-06 vm.skip）
`ExecuteOrderUtils.sol:77` 中：
```solidity
if (params.order.sizeDelta() >= minOrderSize) { executionFee = 0; }
```
当 `isSizeDeltaUsd=false` 时，`sizeDelta` 单位为 token（如 `1e18`），而 `minOrderSize` 单位为 USD（如 `100e30`），两者直接比较导致逻辑错误。修复后应先将 token 量转换为 USD（乘以执行价格）再比较。TC-TSO-06 已使用 `vm.skip(true)` 标记，等待合约工程师修复后解除。
