> 代码版本：@v0.3.1 快照（`Github/fx100-contracts@release-v0.3.1` @d9a7fd2，CURRENT.json `comparison`）；主测基线见 `Docs/contract-releases/CURRENT.json`，`primary` 版本差异见 `Docs/contract-releases/v0.3.2/`
>
> 范围：整理下单、订单、仓位、保证金、价格、PnL、费用、Funding、清算、风控、LP Vault、执行费和 Relay Fee 的原始字段、派生字段与展示口径。公式用于前端实现、SDK 对账和 E2E 预期值计算；最终结果仍需遵循 Solidity 整数除法、向上取整、上下限裁剪和价格选择规则。

## 0. 文档使用规则

### 0.1 字段分层

| 层级 | 含义 | 测试取值来源 |
| --- | --- | --- |
| T0 原始字段 | 合约存储或 Reader 直接返回，如 `sizeInUsd`、`collateralAmount` | 同一区块的 Reader / DataStore |
| T1 合约派生字段 | 按当前合约路径计算，如执行价、费用、Funding、可清算性 | Reader 优先；本地 BigInt 复算 |
| T2 产品派生字段 | UI 为用户解释而计算，如 Entry Price、杠杆、ROE、预计可得 | 固定公式 + T0/T1 快照 |
| T3 展示字段 | 币种、符号、百分比、小数位、千分位和文案 | 页面 DOM / 截图 |

同一个断言必须记录区块号、Oracle `min/max`、市场参数和取整方向。T3 只允许显示舍入误差，不允许掩盖 T0/T1 的单位或符号错误。

### 0.2 来源优先级

1. CURRENT.json `primary.repoPath` 的 `src` 当前实现（本文锚点为 @v0.3.1 快照 `Github/fx100-contracts@release-v0.3.1/src`，引用前回 `primary` 复核）。
2. Reader 返回值与交易事件。
3. `Docs/Gordon-Notion需求文档归档/汇总/FX100-页面字段计算公式.md` 页面口径。
4. 其他归档需求、讨论稿和未来方案。

发生冲突时，以 1 → 4 的顺序判定；差异必须保留在本文“版本差异”中，不能静默选取。

## 1. 精度与通用运算

### 1.1 精度常量

| 名称 | 数值 | 用途 |
| --- | ---: | --- |
| `FLOAT_PRECISION` | `1e30` | USD、比例、费率、PnL factor、资金费率 |
| `WEI_PRECISION` | `1e18` | Token 数量、动态点差、Skew、LP NAV |
| `BASIS_POINTS_DIVISOR` | `10000` | 基点转换 |
| `FLOAT_TO_WEI_DIVISOR` | `1e12` | `1e30` 与 `1e18` 互转 |

### 1.2 通用公式

```text
applyFactor(value, factor) = value × factor / 1e30

toFactor(value, divisor) = value × 1e30 / divisor

floatToWei(value) = value / 1e12

weiToFloat(value) = value × 1e12

basisPointsToFloat(bp) = bp × 1e30 / 10000
```

### 1.3 取整规则

- Solidity 普通整数除法向下取整。
- `Calc.roundUpDivision(a, b)` 等价于 `ceil(a / b)`。
- 多头加仓价格、多头减仓 Token 数量、空头减仓 USD 数量等场景会显式向上取整。
- 负数 PnL 在按比例拆分时可能使用“绝对值向上取整”，避免少扣损失。
- E2E 不能直接使用 JavaScript `Number` 计算 `1e30` 数据，应使用 `BigInt`。

## 2. Oracle 价格字段

### 2.1 中间价

```text
midPrice = (minPrice + maxPrice) / 2
```

### 2.2 PnL 价格选择

| 仓位 | maximize=true | maximize=false |
| --- | --- | --- |
| Long | `maxPrice` | `minPrice` |
| Short | `minPrice` | `maxPrice` |

### 2.3 Token 与 USD 换算

在项目的价格精度已经适配 Token decimals 后：

```text
usdValue = tokenAmount × tokenPrice

tokenAmountDown = usdValue / tokenPrice

tokenAmountUp = ceil(usdValue / tokenPrice)
```

费用扣款通常使用 `collateralTokenPrice.min`，保证需要支付的 Token 数量不会被低估。

## 3. 订单数量转换

### 3.1 加仓订单

当 `isSizeDeltaUsd=true`：

```text
sizeDeltaUsd = rawSizeDelta

Long sizeDeltaInTokens = sizeDeltaUsd / indexPrice.max

Short sizeDeltaInTokens = ceil(sizeDeltaUsd / indexPrice.min)
```

当 `isSizeDeltaUsd=false`：

```text
sizeDeltaInTokens = rawSizeDelta

Long sizeDeltaUsd = sizeDeltaInTokens × indexPrice.max

Short sizeDeltaUsd = sizeDeltaInTokens × indexPrice.min
```

### 3.2 减仓订单

当 `isSizeDeltaUsd=true` 且不是全平：

```text
Long sizeDeltaInTokens
= ceil(position.sizeInTokens × sizeDeltaUsd / position.sizeInUsd)

Short sizeDeltaInTokens
= position.sizeInTokens × sizeDeltaUsd / position.sizeInUsd
```

当 `isSizeDeltaUsd=false` 且不是全平：

```text
Long sizeDeltaUsd
= position.sizeInUsd × sizeDeltaInTokens / position.sizeInTokens

Short sizeDeltaUsd
= ceil(position.sizeInUsd × sizeDeltaInTokens / position.sizeInTokens)
```

全平时直接使用仓位完整的 `sizeInUsd` 和 `sizeInTokens`，避免比例换算的尾差。

## 4. 动态点差与成交价格

### 4.1 动态点差

```text
dynamicSpread
= max(0, constantPriceSpread + priceImpactSpread + skewImpact)
```

`dynamicSpread` 使用 `1e18` 精度。

### 4.2 Price Impact Spread

```text
x = orderSize × priceImpactParameter / orderBookDepth

rawPriceImpactSpread
= max(exp(x) - 1e18, orderSize × 1e18 / orderBookDepth) / 100

priceImpactSpread
= min(rawPriceImpactSpread, MAX_PRICE_IMPACT_SPREAD)
```

Order Book Depth 选择：

| 操作 | Depth |
| --- | --- |
| Long 增加或 Short 减少 | Ask depth |
| Short 增加或 Long 减少 | Bid depth |

当 depth 或 `priceImpactParameter` 为 0 时，`priceImpactSpread=0`。

### 4.3 Skew Reference

```text
skewBefore
= abs(longOI - shortOI) × 1e18 / abs(longOI + shortOI)

skewAfter
= abs(nextLongOI - nextShortOI) × 1e18 / abs(nextLongOI + nextShortOI)

skewRef = (skewBefore + skewAfter) / 2
```

分母为 0 时，对应 skew 取 0。

### 4.4 Skew Impact

```text
rawSkewImpact = skewImpactFactor × skewRef / 1e18

如果操作改善多空平衡：
rawSkewImpact = -rawSkewImpact

skewImpact = clamp(rawSkewImpact, minSkewImpact, maxSkewImpact)
```

平衡是否改善：

```text
balanceWasImproved
= abs(nextLongOI - nextShortOI) < abs(currentLongOI - currentShortOI)
```

### 4.5 加仓成交价

```text
Long executionPrice
= ceil(indexPrice.max × (1e18 + dynamicSpread) / 1e18)

Short executionPrice
= indexPrice.min × (1e18 - dynamicSpread) / 1e18
```

### 4.6 减仓成交价

```text
Long executionPrice
= indexPrice.min × (1e18 - dynamicSpread) / 1e18

Short executionPrice
= ceil(indexPrice.max × (1e18 + dynamicSpread) / 1e18)
```

计算完成后还必须通过 `acceptablePrice` 校验；不满足时订单不能正常执行。

## 5. 仓位字段更新

### 5.1 加仓后规模

```text
nextSizeInUsd = oldSizeInUsd + sizeDeltaUsd

nextSizeInTokens = oldSizeInTokens + sizeDeltaInTokens
```

### 5.2 减仓后规模

```text
nextSizeInUsd = oldSizeInUsd - sizeDeltaUsd

nextSizeInTokens = oldSizeInTokens - sizeDeltaInTokens
```

### 5.3 加仓抵押品变化

```text
collateralDeltaAmount
= initialCollateralDeltaAmount
- totalCostAmount
+ positiveFundingFeeAmount

nextCollateralAmount
= oldCollateralAmount + collateralDeltaAmount
```

### 5.4 减仓抵押品与输出

减仓结算依次处理：正资金费、负资金费、负 PnL、仓位/清算/UI 费用、用户主动提取抵押品。

概念式：

```text
remainingCollateral
= oldCollateral
+ positiveFundingFeeAmount
- negativeFundingFeePaid
- negativePnlPaid
- tradingAndLiquidationFeesPaid
- requestedCollateralWithdrawal

outputAmount
= positivePnlTokenAmount
+ requestedCollateralWithdrawal
- costsPaidFromOutput
```

`PositionDecrease.collateralDeltaAmount` 在 v0.3.1 中是有符号字段（@v0.3.1 快照；`primary` 版本沿用与否待复核）：

```text
collateralDeltaAmount > 0：仓位抵押品净减少

collateralDeltaAmount < 0：仓位抵押品净增加
```

## 6. Position PnL

### 6.1 整仓市值

```text
positionValue = position.sizeInTokens × executionPrice
```

### 6.2 整仓 PnL

```text
Long totalPnl = positionValue - position.sizeInUsd

Short totalPnl = position.sizeInUsd - positionValue
```

### 6.3 部分减仓 PnL

```text
positionPnlUsd
= totalPnl × sizeDeltaInTokens / position.sizeInTokens
```

负 PnL 按绝对值向上取整。

### 6.4 盈利上限

只限制正 PnL：

```text
maxPnl = poolUsd × maxPnlFactor / 1e30

cappedPoolPnl = min(poolPnl, maxPnl)
```

如果池子总 PnL 被裁剪，单仓 PnL 按以下比例同步缩放：

```text
cappedPositionPnl
= originalPositionPnl × cappedPoolPnl / originalPoolPnl
```

## 7. 仓位费用

### 7.1 基础仓位费

```text
positionFeeAmount
= sizeDeltaUsd × positionFeeFactor / 1e30 / collateralTokenPrice.min
```

`positionFeeFactor` 根据 `balanceWasImproved` 选择，因此改善多空平衡的订单可以使用不同费率。

### 7.2 Pro 折扣

```text
proDiscountAmount
= positionFeeAmount × proDiscountFactor / 1e30
```

### 7.3 推荐返佣

```text
totalRebateFactor
= affiliateRewardFactor + traderDiscountFactor
```

当 Pro 折扣高于推荐的 Trader 折扣时：

```text
adjustedAffiliateRewardFactor
= max(
    minAffiliateRewardFactor,
    totalRebateFactor - proDiscountFactor
  )
```

若 `proDiscountFactor > totalRebateFactor`，候选值直接取 `minAffiliateRewardFactor`。

```text
affiliateRewardAmount
= positionFeeAmount × adjustedAffiliateRewardFactor / 1e30

referralTraderDiscountAmount
= positionFeeAmount × traderDiscountFactor / 1e30

totalRebateAmount
= affiliateRewardAmount + referralTraderDiscountAmount
```

### 7.4 最终折扣与协议费

```text
totalDiscountAmount
= max(proDiscountAmount, referralTraderDiscountAmount)

protocolFeeAmount
= positionFeeAmount
- affiliateRewardAmount
- totalDiscountAmount
```

### 7.5 协议与 LP 分成

```text
feeReceiverAmount
= protocolFeeAmount × positionFeeReceiverFactor / 1e30

positionFeeAmountForPool
= protocolFeeAmount - feeReceiverAmount
```

### 7.6 UI Fee

```text
uiFeeAmount
= sizeDeltaUsd × uiFeeReceiverFactor / 1e30
/ collateralTokenPrice.min
```

`uiFeeReceiver=0` 时，UI Fee 为 0。

## 8. 清算费

```text
liquidationFeeUsd
= sizeInUsd × liquidationFeeFactor / 1e30

liquidationFeeAmount
= ceil(liquidationFeeUsd / collateralTokenPrice.min)

liquidationFeeAmountForFeeReceiver
= liquidationFeeAmount × liquidationFeeReceiverFactor / 1e30

liquidationFeeAmountForPool
= liquidationFeeAmount - liquidationFeeAmountForFeeReceiver
```

组合费用字段：

```text
feeAmountForPool
= positionFeeAmountForPool
+ liquidationFeeAmount
- liquidationFeeAmountForFeeReceiver

feeReceiverAmount
= positionFeeReceiverAmount
+ liquidationFeeAmountForFeeReceiver
```

## 9. 费用总额

```text
totalCostAmountExcludingFunding
= positionFeeAmount
+ liquidationFeeAmount
+ uiFeeAmount
- totalDiscountAmount

totalCostAmount
= totalCostAmountExcludingFunding
+ negativeFundingFeeAmount
```

正资金费不进入 `totalCostAmount`，而是在仓位结算时增加抵押品。

## 10. Funding 资金费

### 10.1 市场 Open Interest USD

```text
longOIUsd = longOpenInterestInTokens × indexMidPrice

shortOIUsd = shortOpenInterestInTokens × indexMidPrice

totalOIUsd = longOIUsd + shortOIUsd
```

### 10.2 Skew

```text
skew
= (longOIUsd - shortOIUsd) × 1e18 / totalOIUsd
```

随后进入一小时采样间隔的 EMA；实际费率使用 EMA 后的 skew。

### 10.3 每秒费率

```text
longFundingFactorPerSecond
= clamp(
    fundingFloorFactor + fundingBaseFactor × skew / 1e18,
    minFundingFactorPerSecond,
    maxFundingFactorPerSecond
  )

shortFundingFactorPerSecond
= clamp(
    -fundingBaseFactor × skew / 1e18,
    minFundingFactorPerSecond,
    maxFundingFactorPerSecond
  )
```

### 10.4 市场累计 Funding

对于某一侧：

```text
sideFundingUsd
= sideOIUsd × sideFundingFactorPerSecond × duration / 1e30
```

- 费率为正：累计到 `negativeFundingFeePerSize`，该侧仓位支付。
- 费率为负：绝对值累计到 `positiveFundingFeePerSize`，该侧仓位获得。

概念上的每 Token 累计值：

```text
fundingFeePerSizeDelta
= sideFundingUsd × 1e30 / sideOpenInterestInTokens
```

### 10.5 单仓 Funding

```text
negativeFundingFeeAmount
= fundingAmount(
    latestNegativeFundingFeePerSize
    - position.negativeFundingFeePerSize,
    position.sizeInTokens,
    collateralPrice
  )

positiveFundingFeeAmount
= fundingAmount(
    latestPositiveFundingFeePerSize
    - position.positiveFundingFeePerSize,
    position.sizeInTokens,
    collateralPrice
  )
```

负资金费按需要支付的方向向上取整，正资金费按可领取方向向下取整。

### 10.6 LP Funding 净额

```text
positionPaysLp
= (
    longOIUsd × longRate × duration / 1e30
    + shortOIUsd × shortRate × duration / 1e30
  ) / collateralMidPrice
```

- `positionPaysLp > 0`：仓位侧净支付 LP。
- `positionPaysLp < 0`：LPVault 向 PositionVault 支付。

## 11. 清算判定

### 11.1 清算前剩余抵押品 USD

```text
collateralUsd
= position.collateralAmount × collateralTokenPrice.min

collateralCostUsd
= totalCostAmount × collateralTokenPrice.min

positiveFundingFeeUsd
= positiveFundingFeeAmount × collateralTokenPrice.min

remainingCollateralUsd
= collateralUsd
+ positionPnlUsd
+ positiveFundingFeeUsd
- collateralCostUsd
```

### 11.2 最低抵押品要求

```text
minCollateralUsdForLeverage
= position.sizeInUsd × minCollateralFactor / 1e30
```

判定为可清算的任一条件：

```text
remainingCollateralUsd < configuredMinCollateralUsd

或 remainingCollateralUsd <= 0

或 remainingCollateralUsd < minCollateralUsdForLeverage
```

正式清算使用 `MIN_COLLATERAL_FACTOR_FOR_LIQUIDATION`；正常仓位校验使用 `MIN_COLLATERAL_FACTOR`。

## 12. 市场与 ADL 风控字段

### 12.1 池子 USD

```text
poolUsdWithoutPnl
= LPVault.totalAssets × collateralTokenPrice
```

- maximize=true 使用 `collateralTokenPrice.max`。
- maximize=false 使用 `collateralTokenPrice.min`。

### 12.2 市场多空 PnL

```text
openInterestValue
= openInterestInTokens × selectedIndexPrice

longPnl = openInterestValue - cumulativeLongOpenCosts

shortPnl = cumulativeShortOpenCosts - openInterestValue

netPnl = longPnl + shortPnl
```

### 12.3 PnL / Pool Factor

```text
pnlToPoolFactor = pnl × 1e30 / poolUsd
```

### 12.4 Global Net Obligation

每个市场：

```text
marketNetObligation
= max(longPnl, 0) + max(shortPnl, 0)
```

全局：

```text
globalNetObligationRatio
= sum(marketNetObligation) × 1e30 / globalPoolUsd
```

当前市场共享同一 LPVault，所以全局池子价值只取共享池一次。

### 12.5 Open Interest 上限

同时满足硬上限和池子比例软上限：

```text
openInterest <= MAX_OPEN_INTEREST

openInterest <= poolUsd × MAX_OPEN_INTEREST_FACTOR / 1e30
```

## 13. LP Vault 字段

### 13.1 Total Assets

```text
totalAssets
= vault本地asset余额 + strategy.totalAssets
```

### 13.2 Scaled Assets

```text
totalAssetsScaled = totalAssets × assetScalar
```

`assetScalar` 用于把 USDC 等非 18 位资产归一到 18 位。

### 13.3 NAV

```text
totalSupply = 0 时：nav = 1e18

否则：
nav = totalAssetsScaled × 1e18 / totalSupply
```

### 13.4 Assets 与 Shares

```text
assets
= shares × nav / 1e18 / assetScalar

shares
= assets × assetScalar × 1e18 / nav
```

### 13.5 Strategy 分配

只有本地资产达到 `strategyMinDeposit` 且策略当前占比低于目标时才分配：

```text
targetStrategyAssets
= totalAssets × strategyAllocationPercentage / 1e18

newAllocation
= targetStrategyAssets - currentStrategyAssets
```

## 14. 执行费

### 14.1 预估 Gas Limit

```text
estimatedAdjustedGas
= estimatedGasFeeBaseAmount
+ estimatedGasFeePerOraclePrice × oraclePriceCount
+ estimatedGasLimit × estimatedGasFeeMultiplierFactor / 1e30

minExecutionFee
= estimatedAdjustedGas × tx.gasprice
```

订单默认估算的 Oracle price count：

```text
oraclePriceCount = 3 + swapsCount
```

### 14.2 Keeper 实际执行费

```text
adjustedGasUsed
= executionGasFeeBaseAmount
+ executionGasFeePerOraclePrice × oraclePriceCount
+ gasUsed × executionGasFeeMultiplierFactor / 1e30

keeperExecutionFee
= min(executionFee, adjustedGasUsed × tx.gasprice)

refundFeeAmount
= executionFee - keeperExecutionFee
```

### 14.3 最大执行费

```text
maxExecutionFee
= gasLimit × baseFee × maxExecutionFeeMultiplierFactor / 1e30
```

超过上限的部分：

```text
executionFeeDiff = executionFee - maxExecutionFee
```

该部分转入 `HOLDING_ADDRESS`，或在补贴/更新逻辑中按规则退款。

## 15. Relay Fee

### 15.1 Calldata Gas

```text
txCalldataGasUsed = calldataLength × 10

memoryWords = ceil(calldataLength / 32)

callMemoryGasUsed
= memoryWords² / 512 + memoryWords × 3

calldataGas
= txCalldataGasUsed + callMemoryGasUsed
```

`calldataLength > 50000` 时回滚。

### 15.2 Relay Gas 与原生币费用

```text
relayGasLimit
= gasUsed + relayFeeBaseGasLimit + calldataGas

nativeFee
= ceil(
    relayGasLimit × tx.gasprice × relayFeeMultiplierFactor / 1e30
  )
+ relayExecutionFee
```

当 `relayFeeMultiplierFactor=0` 时按 `1e30` 处理。

### 15.3 支付 Token 数量

```text
feeTokenAmount
= ceil(
    nativeFee × nativeTokenPrice.max
    / feeTokenPrice.min
  )
```

还需满足：

```text
nativeFee <= MAX_RELAY_SWAP_WNT_CAP（配置为0时不限制）

feeTokenAmount <= user.maxFeeAmount
```

## 16. 下单与订单字段字典

### 16.1 Order 原始字段

| 字段 | 单位 / 类型 | 页面含义与计算规则 |
| --- | --- | --- |
| `account` | address | 订单和目标仓位归属账户 |
| `receiver` | address | 减仓输出等 Token 的接收地址 |
| `cancellationReceiver` | address | 取消时抵押品 / 执行费退款地址 |
| `callbackContract` | address | 订单完成后的回调合约 |
| `uiFeeReceiver` | address | UI Fee 接收方；零地址表示不收 |
| `marketIndex` | uint256 | 市场标识 |
| `orderType` | enum | Market / Limit / Stop Increase，Market / Limit / Stop Loss Decrease，Liquidation |
| `sizeDelta` | USD 或 Token | 由 `isSizeDeltaUsd` 决定，不能仅凭数值猜单位 |
| `initialCollateralDeltaAmount` | collateral token | 加仓表示存入量；减仓表示申请提取的抵押品量 |
| `triggerPrice` | contract price | 非市价单触发价 |
| `acceptablePrice` | contract price | 成交价保护边界 |
| `executionFee` | native token | Keeper 预算；不属于仓位保证金 |
| `callbackGasLimit` | gas | 回调预算 |
| `minOutputAmount` | USD | 减仓时的最小输出校验值 |
| `updatedAtTime` | unix seconds | 最近更新时间 |
| `validFromTime` | unix seconds | 非市价单最早可执行时间 |
| `isLong` | bool | 仓位方向，不等同于“买 / 卖按钮文字” |
| `isFrozen` | bool | 冻结订单仍存在，资金不可按已取消处理 |
| `autoCancel` | bool | 与该仓位结束时的自动撤单逻辑关联 |
| `isSizeDeltaUsd` | bool | `sizeDelta` 的单位选择 |

### 16.2 Pay、Margin、Size 与 Leverage

前端根据用户输入生成订单，但合约不会从“杠杆倍数”反推订单规模；合约接收的是已经确定的 `sizeDelta` 和抵押品数量。

```text
inputMarginToken = 用户输入的 collateral token 数量

inputMarginUsd
= inputMarginToken × collateralPrice.min

targetSizeDeltaUsd
= inputMarginUsd × targetLeverage
```

开仓实际入仓的保证金必须扣除费用并结算已有仓位 Funding：

```text
storedCollateralTokenAfterOpen
= oldCollateralToken
+ inputMarginToken
- totalCostAmount
+ positiveFundingFeeAmount

storedCollateralUsd
= storedCollateralTokenAfterOpen × collateralPrice.min
```

因此：

- `inputMargin` 是用户提交值；
- `storedCollateral` 是链上仓位最终值；
- `effectiveMargin` 是计算当前风险时进一步计入待结算 Funding 的值；
- 三者不能在页面或测试报告中都写成“Margin”而不标明口径。

### 16.3 触发条件

| 订单 | Long | Short |
| --- | --- | --- |
| Limit Increase | `oracle.max <= triggerPrice` | `oracle.min >= triggerPrice` |
| Stop Increase | `oracle.max >= triggerPrice` | `oracle.min <= triggerPrice` |
| Limit Decrease / TP | `oracle.min >= triggerPrice` | `oracle.max <= triggerPrice` |
| Stop Loss Decrease | `oracle.min <= triggerPrice` | `oracle.max >= triggerPrice` |

触发价只决定“现在是否允许执行”，不等于最终成交价。成交仍要经过动态点差、价格边界和 `acceptablePrice` 校验。

### 16.4 Acceptable Price

| 操作 | 合约通过条件 | 字段语义 |
| --- | --- | --- |
| 开多 | `executionPrice <= acceptablePrice` | 用户允许的最高成交价 |
| 开空 | `executionPrice >= acceptablePrice` | 用户允许的最低成交价 |
| 平多 | `executionPrice >= acceptablePrice` | 用户允许的最低成交价 |
| 平空 | `executionPrice <= acceptablePrice` | 用户允许的最高成交价 |

市价预览可按以下方式生成边界：

```text
开多 / 平空：acceptablePrice = referenceExecutionPrice × (1 + slippage)
开空 / 平多：acceptablePrice = referenceExecutionPrice × (1 - slippage)
```

需求文档规定触发单使用方向哨兵值并隐藏滑点输入；测试仍应读取实际链上字段，不能只按 UI 假设哨兵已正确写入。

### 16.5 订单列表派生字段

| 页面字段 | 计算 |
| --- | --- |
| Size (USD) | `sizeDeltaUsd / 1e30` |
| Token Size | `sizeDeltaInTokens / 1e18` |
| Trigger | 按 16.3 的方向展示 `<=` 或 `>=` |
| Created / Updated | `updatedAtTime` 按当前 locale 格式化 |
| Earliest execution | `validFromTime` |
| Status: Pending | OrderStore 中存在且 `isFrozen=false` |
| Status: Frozen | OrderStore 中存在且 `isFrozen=true`；抵押品仍锁定 |
| Status: Executed | 订单已移除且存在执行事件 / 回执 |
| Status: Cancelled | 订单已移除且存在取消事件，并按规则退款 |

挂单期间不应增加仓位 OI，也不应把 OrderVault 中暂存的抵押品显示成 Position collateral。

## 17. 仓位全字段与保证金口径

### 17.1 Position 原始字段

```text
positionKey = keccak256(abi.encode(account, marketIndex, isLong))
```

同一账户、同一市场的 Long 与 Short 使用不同 key，可同时存在。

| 字段 | 单位 / 精度 | 含义 |
| --- | --- | --- |
| `account` | address | 仓位所有者 |
| `marketIndex` | uint256 | 市场 |
| `isLong` | bool | 多空方向 |
| `sizeInUsd` | USD × 1e30 | 名义仓位规模 / 开仓成本基数 |
| `sizeInTokens` | 标的 × 1e18 | 所有市场统一按 18 位仓位精度 |
| `collateralAmount` | collateral token 原生精度 | 已入仓抵押品数量 |
| `negativeFundingFeePerSize` | 累计值 | 该仓位上次结算的应付 Funding 基准 |
| `positiveFundingFeePerSize` | 累计值 | 该仓位上次结算的应收 Funding 基准 |
| `increasedAtTime` | unix seconds | 最近加仓时间 |
| `decreasedAtTime` | unix seconds | 最近减仓时间 |
| `graceStart` | unix seconds | 清算保护起点 |
| `graceEnd` | unix seconds | 清算保护终点 |

### 17.2 Entry Price、Mark Price 与仓位数量

```text
entryPrice = sizeInUsd / sizeInTokens

displaySizeUsd = sizeInUsd / 1e30
displaySizeToken = sizeInTokens / 1e18
```

`entryPrice` 是多次加仓后的加权结果，因为 `sizeInUsd` 与 `sizeInTokens` 都按增量累计。它包含实际开仓成交价影响，不是 Oracle 中间价。

“Mark Price”必须标注用途：

- 行情展示可用中间价；
- Long 的保守 PnL / 风险路径用较低边界；
- Short 的保守 PnL / 风险路径用较高边界；
- 精确 PnL 应使用 Reader 返回的平仓执行价，而不是单独拿 K 线价计算。

### 17.3 Margin 字段

```text
marginToken = collateralAmount

marginUsd
= collateralAmount × collateralPrice.min

pendingFundingNetToken
= negativeFundingFeeAmount - positiveFundingFeeAmount

effectiveMarginToken
= collateralAmount
- negativeFundingFeeAmount
+ positiveFundingFeeAmount

effectiveMarginUsd
= effectiveMarginToken × collateralPrice.min
```

页面如只显示一个 `Margin`，建议显示 `marginToken` 与按 `min` 价换算的 `marginUsd`；杠杆和风险提示应使用 `effectiveMarginUsd`。正 Funding 与负 Funding 要分列保留，避免先相减后丢失方向证据。

### 17.4 Position Leverage 与 Margin Ratio

```text
positionLeverage
= sizeInUsd / effectiveMarginUsd

maintenanceMarginUsd
= sizeInUsd × minCollateralFactorForLiquidation / 1e30

marginRatio
= remainingCollateralUsd / sizeInUsd
```

- 持仓杠杆不把未实现 PnL 放入分母，因此不应仅因价格刷新而抖动。
- Funding、加减抵押品和仓位更新会改变杠杆。
- 当 `effectiveMarginUsd <= 0` 时不得显示负杠杆或 Infinity，应显示风险态 / 不可用并走清算判断。
- 下单面板的目标杠杆与持仓面板的当前杠杆不是同一字段。

### 17.5 Unrealized PnL、ROE 与 PnL%

```text
Long  unrealizedPnlUsd = sizeInTokens × selectedPrice - sizeInUsd
Short unrealizedPnlUsd = sizeInUsd - sizeInTokens × selectedPrice

roe = unrealizedPnlUsd / roeMarginBasisUsd
```

`unrealizedPnlUsd` 是纯价格盈亏，不包含 Funding、平仓费和动态点差成本。`roeMarginBasisUsd` 在 Position 原始结构中不存在：

- 若产品定义为“初始保证金”，必须由成交历史 / indexer 维护；
- 若产品定义为“当前保证金”，则保证金调整后 ROE 会变化；
- 页面、SDK 和测试必须共用同一定义，禁止以 `collateralAmount` 临时代替但仍标注为“初始保证金”。

### 17.6 Est. Receive / Est. Pay

概念展示式：

```text
estimatedReceive
= collateral
+ positiveFunding
- negativeFunding
+ closePnl
- closePositionFee
- uiFee
- liquidationFee(仅清算)
```

实际减仓会按“抵押品支付 → PnL 输出 → 可请求提取 → minOutput 校验”的顺序结算，且可能发生 PnL cap、Token 取整或抵押品不足。因此精确值必须读取 Reader 的完整减仓预览；不能用 `collateral + unrealizedPnl` 作为到账断言。

### 17.7 调整保证金与目标杠杆

```text
加保证金：
nextCollateralAmount = currentCollateralAmount + depositAmount - 本次费用 + 本次正Funding

减保证金：
nextCollateralAmount = currentCollateralAmount - withdrawalAmount - 本次费用 ± Funding结算

保持抵押不变、调整到目标杠杆的产品估算：
targetSizeUsd = targetLeverage × effectiveMarginUsd
sizeChangeUsd = targetSizeUsd - currentSizeInUsd
```

`sizeChangeUsd > 0` 按加仓路径收费和计算点差；`sizeChangeUsd < 0` 按减仓路径计算 PnL、点差和输出。最终结果必须通过正常仓位的 `MIN_COLLATERAL_FACTOR` 校验。

## 18. 清算价格与风险展示

### 18.1 当前合约的精确清算边界

@v0.3.1 快照的可清算判断使用“整仓按当前减仓路径平掉”的结果（CURRENT 基线见 `Docs/contract-releases/CURRENT.json`；`primary` 版本强平判定修复见 `Docs/contract-releases/v0.3.2/01-代码变化分析.md` §8.4，复核前不改断言）：

```text
remainingCollateralUsd(price)
= collateralUsd
+ fullClosePnlUsd(price)
+ positiveFundingFeeUsd
- closeCostExcludingFundingUsd
- negativeFundingFeeUsd
```

其中 `closeCostExcludingFundingUsd` 是扣除适用折扣后的平仓位费；清算检查传入零 `uiFeeReceiver`。清算资格判断不计 `liquidationFee`；真正执行清算时才收取清算费。满足任一条件即可清算：

```text
remainingCollateralUsd < MIN_COLLATERAL_USD
或 remainingCollateralUsd <= 0
或 remainingCollateralUsd < sizeInUsd × minCollateralFactorForLiquidation / 1e30
```

其中第一条只在调用方要求校验 `MIN_COLLATERAL_USD` 时启用。等于杠杆维持阈值时按当前严格小于语义不触发。

### 18.2 页面闭式估算

忽略 Oracle 价差、动态点差随价格变化、折扣和 PnL cap 时，可用以下公式做初始估算：

```text
Q = sizeInTokens
S = sizeInUsd
C = collateralUsd + positiveFundingFeeUsd
F = discountedClosePositionFeeUsd + negativeFundingFeeUsd
M = max(
      S × minCollateralFactorForLiquidation / 1e30,
      configuredMinCollateralUsd（调用方启用该检查时）
    )

Long:
estimatedLiqExecutionPrice = (S + M + F - C) / Q

Short:
estimatedLiqExecutionPrice = (C + S - F - M) / Q
```

也可以将 `S / Q` 写成 Entry Price，但页面必须把结果标为“预计清算价”。

### 18.3 精确清算价算法

动态点差、Oracle `min/max`、Funding、手续费折扣和 PnL cap 会使闭式公式产生偏差。权威计算方式：

1. 固定同一份市场参数、仓位和 Funding 快照。
2. 给定候选 Oracle 价格，调用 Reader `isPositionLiquidatable`。
3. Long 从当前价向下、Short 从当前价向上做二分搜索。
4. 搜索到合约价格最小单位，记录“最后安全价”和“第一个可清算价”。
5. 页面展示值必须落在这两个边界的显示舍入区间内。

### 18.4 清算距离与保护期

```text
Long liquidationDistance
= (markPrice - liquidationPrice) / markPrice

Short liquidationDistance
= (liquidationPrice - markPrice) / markPrice

graceRemaining
= max(0, graceEnd - blockTimestamp)
```

保护状态应以链上 `graceStart/graceEnd` 和当前可清算判断组合推导。加仓或补保证金是否重置保护时间，必须以交易后仓位字段为准，不能只重启前端倒计时。

## 19. Funding 展示字段

### 19.1 市场费率

合约费率为每秒 `1e30` 精度。页面按小时百分比展示：

```text
hourlyRate = fundingFactorPerSecond × 3600
hourlyRatePercent = hourlyRate × 100 / 1e30
```

合约符号为“正数表示该侧支付，负数表示该侧收取”。若 UI 采用“负值 = 用户支付、正值 = 用户收取”，则：

```text
displayFundingRatePercent
= -fundingFactorPerSecond × 3600 × 100 / 1e30
```

符号翻转只发生在展示层，不得改变合约累计值的方向。

### 19.2 单仓应付 / 应收

精确 Token 公式：

```text
negativeFundingFeeAmount
= ceil(
    sizeInTokens
    × (latestNegativePerSize - positionNegativePerSize)
    / (1e30 × collateralPrice.min)
  )

positiveFundingFeeAmount
= floor(
    sizeInTokens
    × (latestPositivePerSize - positionPositivePerSize)
    / (1e30 × collateralPrice.max)
  )

displayFundingToken
= positiveFundingFeeAmount - negativeFundingFeeAmount
```

- 负 Funding 在下次仓位更新或平仓时扣入成本。
- 正 Funding 在下次仓位更新或平仓时增加保证金。
- 每次结算后仓位的正负 `fundingFeePerSize` 基准更新到市场最新值，防止重复计费。
- `positionPaysLp > 0` 时当前实现累加 `FUNDING_FEE_TYPE` 可领取账本；`positionPaysLp < 0` 时 LPVault 向 PositionVault 转账。

### 19.3 Funding 时间与零 OI

```text
fundingDuration
= blockTimestamp - fundingUpdatedAt
```

Long OI 与 Short OI 同时为 0 时 Funding 更新应为 no-op，不能除零。页面“下一次 Funding”倒计时如存在，必须明确它是刷新提示；合约仍按实际经过秒数累计。

## 20. 市场与风险展示字段

### 20.1 Open Interest 与 Skew

```text
longOIUsd = longOpenInterestInTokens × indexMidPrice
shortOIUsd = shortOpenInterestInTokens × indexMidPrice
totalOIUsd = longOIUsd + shortOIUsd

skew = (longOIUsd - shortOIUsd) / totalOIUsd
```

当 `totalOIUsd=0` 时 skew 展示为 0 / N/A，不能显示 NaN。

### 20.2 Reserve 与 Available Liquidity

当前储备约束使用多空 Token OI 合计：

```text
totalNominalOIUsd
= (longOpenInterestInTokens + shortOpenInterestInTokens)
× indexPrice.max

maxReservedUsd
= poolUsd × reserveFactor / 1e30

reserveHeadroomUsd
= max(0, maxReservedUsd - totalNominalOIUsd)

hardOiHeadroomUsd
= max(0, maxOpenInterestUsd - currentSideOrMarketOIUsd)

availableLiquidity
= min(reserveHeadroomUsd, hardOiHeadroomUsd, 其它启用的风控上限)
```

页面若没有纳入所有风控闸门，应标为“估算可用流动性”，提交前仍由合约最终校验。

### 20.3 Pool、PnL Obligation 与 ADL

```text
poolUsdWithoutPnl
= lpVaultTotalAssets × collateralPrice

marketNetObligation
= max(longPnl, 0) + max(shortPnl, 0)

globalNetObligationRatio
= sum(marketNetObligation) / sharedGlobalPoolUsd
```

多个市场共享同一 LPVault 时，分母只能计算一次，不能按市场重复相加。

## 23. E2E 预期值计算顺序

一条交易用例建议严格按以下顺序计算预期值：

1. 读取 Oracle `min/max` 价格。
2. 将订单数量解析为 `sizeDeltaUsd` 和 `sizeDeltaInTokens`。
3. 读取当前 Long/Short OI，计算 `balanceWasImproved`。
4. 计算 Price Impact、Skew Impact 和 `dynamicSpread`。
5. 计算并校验 `executionPrice`。
6. 计算 PnL。
7. 更新 Funding，并计算仓位应付/应收 Funding。
8. 计算 position、referral、Pro、UI、liquidation 费用。
9. 计算仓位抵押品和用户输出。
10. 更新 OI、PositionVault、LPVault 和 claimable 账本预期。
11. 单独计算 Keeper execution fee 与 refund。
12. 用余额、DataStore、仓位和事件四层断言核对。

## 25. 使用限制

- 本文是合约计算路径的测试摘要，不替代 Solidity 源码。
- 具体订单还会受触发价、acceptable price、Oracle 时间戳、功能开关、权限和最大/最小范围校验影响。
- 同一公式在 Long/Short、Increase/Decrease 下可能采用不同价格边界和取整方向。
- E2E 应从链上读取参数后计算，不应把本文示例值写死为长期预期。
- “所有字段”指需求、当前合约与页面测试涉及的业务计算字段，不包含地址常量、权限角色和纯配置元数据；这些内容见同目录配置参数总表。
