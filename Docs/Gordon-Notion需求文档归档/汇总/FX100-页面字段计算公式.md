## 零、精度基础表（一切计算的前提）

| 字段 | 单位 | 精度 | 说明 |
|---|---|---|---|
| `sizeInUsd` | **USD** | `× 10^30`（FLOAT_PRECISION） | 纯美元金额，与 USDC 价格无关 |
| `collateralAmount` | **USDC 原生数量** | `× 10^6` | 存的是 USDC token 数量，**不是 USD** |
| `sizeInTokens` | **标的原生数量** | `× 10^18`（**所有 token 统一**） | 不论 token 链上小数位 |
| oracle 价格（BTC/ETH/index） | USD | `USD × 10^12` | FX100 统一格式，**不按 token 小数位区分** |
| oracle 价格（USDC） | USD | `USD × 10^24`（= `10^(30-6)`） | |

### 0.1 SDK 精度选择规则（BTC 类非 18 位 token 的排查表）

> 出现「**仅 BTC 等非 18 位 token 异常**」时，先查 `indexToken.decimals` 用在了哪：

| 场景 | 应用精度 | 原因 |
|---|---|---|
| 向合约发送 / 读取价格 | `POSITION_SIZE_DECIMALS = 18` | FX100 oracle 统一 `USD × 10^12` |
| 格式化链上 `sizeInTokens` | `POSITION_SIZE_DECIMALS = 18` | 合约统一 18 位存储 |
| **用户输入** token 数量 → USD | `indexToken.decimals` | 用户输入是原生精度 |
| USDC collateral 价格 / 数量 | `collateralToken.decimals = 6` | USDC oracle 格式 `USD × 10^24` |

**历史故障样本**（`indexToken.decimals = 8` 误用导致 `10^10` 倍偏差）：

| 现象 | 根因 | 修复位置 |
|---|---|---|
| BTC 下单全部被 cancel（`OrderNotFulfillableAtAcceptablePrice`） | `convertToContractPrice(price, 8)` 得 `USD×10^22`，合约要 `USD×10^12` | `orderTransactions.ts` |
| BTC 仓位 Size 显示 ~1377 万 BTC | `getPositionSizeDecimals()` 返回 8，链上是 18 | `positionPrecision.ts` |
| PnL / Funding / 清算价显示 -\$578M | `getContractMarketPrices()` 给 Reader 传 `72272e22` 而非 `72272e12` | `markets.ts` / `priceImpact.ts` |
| Trigger 显示 `≤ 0.000007`（应为 `≤ $70,000`） | `parseContractPrice(p, 8)` 应为 18 | `orders.ts` |
| 新建 BTC Limit 订单 Size 显示 `$0` | 把**用户输入路径**也改成了 18（应保留 8） | `trade/increase.ts` |

> ⚠️ 这是最容易反复踩的坑：**SDK 内部推算路径用 18，用户原生输入路径用 `indexToken.decimals`**，两者不能一刀切。

### 0.2 min / max 选价规则（合约始终按对用户最不利方向取价）

| 场景 | 使用价格 | 原因 |
|---|---|---|
| 计算抵押物 USD 价值（开仓 / 清算检查） | `min` | 低估抵押物 → 保守 |
| 扣除费用（USD → USDC token 数量） | `min` | 除以更小的数 → 多扣 USDC |
| 清算剩余保证金计算 | `min` | 保守估值 |
| Funding fee **支付端**（trader 付钱） | `min` | 多付 |
| Funding fee **可取端**（trader 收钱） | `max` | 多给（对收款人有利） |
| Pool 价值计算（LP 侧 maximize） | `max` | 最大化池子估值，保护 LP |

**前端建议**：显示 `collateralUsd` 用 `minPrice`，与合约行为一致；显示「可用保证金」也用 `minPrice` 更保守。

## 一、下单面板（Order Form）

### 1.1 Margin、目标仓位规模与链上订单值

```plain
marginToken  = collateralAmountRaw / 10^collateralDecimals
marginUsdRaw = collateralAmountRaw × collateralPrice.min
marginUsd    = marginUsdRaw / 1e30
               ↑ 注意：用实时 oracle min 价，不是固定 $1

targetSizeUsd   = marginUsd × targetLeverage       // 页面目标值
sizeDeltaUsdRaw = parseUsd(targetSizeUsd, 30)      // USD 模式订单输入
```

这里必须区分两个层次：

- **页面目标值**：下单表单可以用 `marginUsd × targetLeverage` 推导 Size。
- **链上订单值**：合约不根据 Margin 或 Leverage 反推仓位规模；USD 模式直接把 `order.sizeDelta` 作为 `sizeDeltaUsd`。Leverage 不是仓位存储字段。

仓位费从抵押品中扣除，不会在合约里反向改写已提交的 `sizeDeltaUsd`：

```plain
positionFeeUsdRaw   = sizeDeltaUsdRaw × positionFeeFactor / 1e30
positionFeeTokenRaw = ceil(positionFeeUsdRaw / collateralPrice.min)

effectiveMarginTokenRaw
  = collateralAmountRaw
  - negativeFundingFeeAmount
  + positiveFundingFeeAmount

effectiveMarginUsdRaw = effectiveMarginTokenRaw × collateralPrice.min
```

**换算示例**（用户输入 10 USDC、USDC min 价为 $0.9998、目标 100x）：

```plain
marginUsd     = 10 × $0.9998 = $9.998
targetSizeUsd = $9.998 × 100 = $999.8
```

实际成交后应分别读取 `position.sizeInUsd`、`position.sizeInTokens` 和扣费后的 Margin；不要用“扣费后 Margin × 目标杠杆”覆盖合约仓位值。

> 🚨 **100x 高杠杆精度风险**：USDC 价格、点差、仓位费和方向性取整都会压缩安全空间，可能触发最小抵押率或最小仓位校验。
>
> **前端对策**：① 最大杠杆留 buffer；② Pay 栏同时展示 Margin USD 与 Target Size；③ 提交前用 SDK / Reader 预算成交价、费用和安全校验。

### 1.2 `sizeInUsd` / `sizeInTokens` 完整计算链

#### A. 开仓 / 加仓订单增量

```plain
USD 模式（isSizeDeltaUsd = true）
  sizeDeltaUsd = order.sizeDelta
  开多 sizeDeltaInTokens = floor(sizeDeltaUsd / executionPrice)
  开空 sizeDeltaInTokens = ceil(sizeDeltaUsd / executionPrice)

Token 模式（isSizeDeltaUsd = false）
  sizeDeltaInTokens = order.sizeDelta
  sizeDeltaUsd      = sizeDeltaInTokens × executionPrice
```

`executionPrice` 已包含 Oracle min/max 边界与 Dynamic Spread。原始整数精度正好配对：

```plain
sizeDeltaUsdRaw(1e30) / executionPriceRaw(1e12) = sizeDeltaInTokensRaw(1e18)
```

所有标的仓位的 `sizeInTokens` 都按 18 位保存，包括链上原生 decimals 不是 18 的 WBTC；只有“用户输入 Token 数量”时才使用 `indexToken.decimals`。

#### B. 仓位开仓 / 加仓后

```plain
nextPosition.sizeInUsd
  = oldPosition.sizeInUsd + sizeDeltaUsd

nextPosition.sizeInTokens
  = oldPosition.sizeInTokens + sizeDeltaInTokens
```

新仓的两个 old 值均为 0。多次加仓时两项逐笔累计，所以 `sizeInUsd / sizeInTokens` 自然形成加权 Entry Price。

#### C. 部分减仓与全平

```plain
按 USD 减仓：
  平多 sizeDeltaInTokens
    = ceil(position.sizeInTokens × sizeDeltaUsd / position.sizeInUsd)
  平空 sizeDeltaInTokens
    = floor(position.sizeInTokens × sizeDeltaUsd / position.sizeInUsd)

按 Token 减仓：
  平多 sizeDeltaUsd
    = floor(position.sizeInUsd × sizeDeltaInTokens / position.sizeInTokens)
  平空 sizeDeltaUsd
    = ceil(position.sizeInUsd × sizeDeltaInTokens / position.sizeInTokens)

减仓后：
  nextSizeInUsd    = oldSizeInUsd - sizeDeltaUsd
  nextSizeInTokens = oldSizeInTokens - sizeDeltaInTokens
```

全平不走比例换算，直接使用完整的 `position.sizeInUsd` 与 `position.sizeInTokens`，两项都必须归零，避免残留 dust。

#### D. 页面展示换算

```plain
displaySizeUsd   = position.sizeInUsd / 1e30
displaySizeToken = position.sizeInTokens / 1e18
entryPrice       = position.sizeInUsd / position.sizeInTokens
```

页面显示时可以按产品小数位格式化，但测试必须先比对原始整数，再单独断言显示舍入。

### 1.3 杠杆

```plain
下单预览:  Leverage = OrderValue / Collateral
           其中 OrderValue = sizeInTokens × oraclePrice
```

### 1.4 最大可开杠杆

```plain
maxLeverage = 1 / (minCollateralFactor + s_open + s_close + f_open + f_close)
```

| 符号 | 含义 |
|---|---|
| `minCollateralFactor` | 开仓所需最低抵押率（每市场配置） |
| `s_open` / `s_close` | 开 / 平方向的动态点差 |
| `f_open` / `f_close` | 开 / 平仓位费 |

> 流动性浅或单量大时，实际可开杠杆会**低于**理论上限——点差吃掉了一部分空间。预览应显示当前实际可开的最大杠杆。

### 1.5 执行价与滑点

```plain
useMax    = (open & long) OR (close & short)
execPrice = useMax ? ceil ( indexAsk · (1 + totalSpread) )
                   : floor( indexBid · (1 − totalSpread) )

rawSpread = constantSpread + depthSpread + skewImpact

当前 release：
totalSpread = max(0, rawSpread)

07-29 最新目标：
普通交易 totalSpread = clamp(MIN_DYNAMIC_SPREAD, MAX_DYNAMIC_SPREAD, rawSpread)
清算/ADL/安全校验 totalSpread = max(0, rawSpread)

depthSpread = max( exp(orderSize · k / depth) − 1 , orderSize / depth ) / 100

maxAcceptablePrice = execPrice · (1 ± slippage)
    开多 / 平空:  · (1 + slippage)
    开空 / 平多:  · (1 − slippage)
```

> **仅市价单适用**。触发单的 `acceptablePrice` 恒为哨兵值，滑点字段不生效。
>
> **负 spread 状态**：普通交易改善平衡时成交价可以优于 oracle；Price Impact 显示负值并解释为 rebate。清算、ADL 和仓位安全校验仍不允许负值。该行为尚待方案合入。
>
> **P0 风险 R5-B02**：`depthSpread` 的指数必须在调用 `exp` 前封顶；仅在 `exp` 后 cap 结果无法防止低深度市场的清算路径 revert。

### 1.6 挂单预览与最终 `sizeInTokens` 的口径差异

```plain
市价单创建预览: previewSizeInTokens = SIZE / creationPrice
触发单挂单预览: previewSizeInTokens = SIZE / triggerPrice

订单实际执行:   positionDeltaInTokens = SIZE / executionPrice
                executionPrice 为触发时 Oracle + Dynamic Spread 后价格，
                并按开多 floor / 开空 ceil 取整
```

前两项是订单列表 / 下单预览口径，不是最终仓位存储值。挂起期间 **OI 与 collateral 均不变**，前端不应把挂单计入持仓统计；执行后以 Reader 返回的 `position.sizeInTokens` 为准。

## 二、持仓面板（Positions）

### 2.1 开仓价

```plain
entryPrice = sizeInUsd / sizeInTokens
```

记录的是**执行价（含点差）**，而非 oracle 中间价。此后所有 PnL 与清算计算都以它为基准，**不随市场重新标记**。

### 2.2 杠杆（与下单面板口径不同）

```plain
pendingFundingNetToken
  = negativeFundingFeeAmount - positiveFundingFeeAmount

effectiveMarginToken
  = collateralAmount
  - negativeFundingFeeAmount
  + positiveFundingFeeAmount

effectiveMarginUsd
  = effectiveMarginToken × collateralPrice.min

持仓面板: Leverage = sizeInUsd / effectiveMarginUsd
```

**三条必须向用户解释的性质**：
- 用**有效 Margin**（抵押 − 应付 Funding + 应收 Funding）作分母；抵押币价格边界不变时，不随标的价格抖动
- 未实现盈亏**不计入**分母 → 价格波动不改变杠杆显示
- 保证金小、资金费累积时净抵押被压缩，显示杠杆可能**高于开仓杠杆**——这是当前真实杠杆，真实风险请看清算价

### 2.3 未实现盈亏

```plain
LONG  : UnrealizedPnL = sizeInTokens × oraclePrice − sizeInUsd
SHORT : UnrealizedPnL = sizeInUsd − sizeInTokens × oraclePrice

ROE   = UnrealizedPnL / 初始保证金
```

- 这是**纯价格盈亏**——**不含**资金费、平仓费、平仓价格冲击
- 空头正盈利受**资金池 PnL 上限**约束：超过 `maxPnlFactor × poolValue` 时会被封顶（保护 LP）

### 2.4 预计可得（Est. Receive）—— 与浮盈亏的差别

```plain
Est. Receive ≈ collateral + UnrealizedPnL + closingImpact − closingFee − pendingFunding
```

| 项 | 含义 | 为何不在浮盈亏里 |
|---|---|---|
| `closingImpact` | 平仓那一刻的价格冲击 | 平仓才实现 |
| `closingFee` | 平仓仓位费 | 未平仓不产生 |
| `pendingFunding` | 待结算资金费（常态为 0） | 结算时才扣 |

> **页面顶部的浮盈亏是「纯价格盈亏」；`Est. Receive` 才是实际到账数。** 这一区分必须在 UI 上明确，否则用户会认为系统吞钱。

### 2.5 清算价

```plain
LONG  : liqPrice = entryPrice · (1 + minCF_liq + closeFeeRatio) − netCollateral / sizeInTokens
SHORT : liqPrice = entryPrice · (1 − minCF_liq − closeFeeRatio) + netCollateral / sizeInTokens

where  netCollateral = collateral + closingImpact − pendingFunding
```

| 符号 | 含义 |
|---|---|
| `minCF_liq` | `minCollateralFactorForLiquidation`，清算维持因子（每市场配置，**低于**开仓最低抵押率，差额即安全缓冲） |
| `closeFeeRatio` | 平仓仓位费率 |
| `netCollateral` | 净抵押 = 抵押 + 平仓价格冲击 − 待结算资金费 |

**口径要点**：
- ✅ **含平仓费**——清算是被迫平仓，平仓费照收
- ✅ **含平仓价格冲击**——清算价问的是「现在平掉还剩多少」
- ❌ **不含未来资金费**——无法预估，取 0

### 2.6 清算触发判定

```plain
remainingCollateral = collateral + PnL(oracle) + closingImpact − closingFee − pendingFunding

if  remainingCollateral ≤ sizeInUsd × minCollateralFactorForLiquidation:
        → 可被清算
```

### 2.7 Funding 列

```plain
符号约定:  负值 = 你在支付      正值 = 你在收取
```

**结算语义**（文案已定稿，中英双语）：
> zh：本仓位的资金费直接结算进它的保证金——"Owed" 会在下次更新或平仓时扣除；若你在较轻的一侧，则改为计入保证金。无需手动领取。
>
> en：This position's funding settles directly into its margin — "Owed" is deducted on the next update or close; if you're on the lighter side, funding is added to margin instead. No manual claim.

### 2.8 调整保证金 / 调整杠杆

```plain
调整保证金:  newMargin   = currentMargin ± amount
             newLeverage = sizeInUsd / newMargin

调整杠杆:    targetSize  = targetLeverage × collateral      （保持抵押不变、改名义规模）
             sizeChange  = targetSize − currentSize
             estFee      = |sizeChange| × positionFeeFactor  （仅加仓部分收费）
```

- 加保证金 → 清算价远离现价（更安全）；减保证金 → 更接近清算
- 调高杠杆 = 加大名义规模（相当于加仓，按增量收仓位费）

## 三、止盈止损预览（TP / SL）

```plain
Expected Profit (TP) = sizeInTokens × (triggerPrice − entryPrice)     （多头；空头反向）
Expected Loss  (SL)  = sizeInTokens × |markPrice − triggerPrice|
TP% / SL%            = priceChange / mark × leverage
```

> 方向以**仓位多空**为准，不是订单方向。

## 四、清算保护卡片（Protection Card）

> 07-29 最新 UI 定案：Protection 面板删除重复的 `Est. Liq. Price`，仅保留动态 PnL；清算价继续在 Positions 行显示。

### 4.1 保护期推导

```plain
graceEnd = graceStart + gracePeriodBase × tierMultiplier / WEI_PRECISION

Tier=0：multiplier = 8e18 ，base = 15s → +120s
Tier=1：multiplier = 16e18，base = 15s → +240s
```

保护状态从 `position.graceStart` / `position.graceEnd`（合约写入的 unix timestamp）**实时推导**，无需单独维护倒计时 atom。

### 4.2 5 状态机

| 状态 | 触发条件 | 视觉 |
|---|---|---|
| **Promo** | 无持仓 | 宣传态，盾牌 SVG + 概念图 |
| **Safe** | 有持仓 + timer > 0 + 价格 > 清算价 | 绿色，实时 PnL |
| **Danger** | 有持仓 + timer > 0 + 价格触碰清算线 | 红色脉冲边框 + Add Margin CTA |
| **Recovered** | 之前触碰过清算线 + 价格回升 | 胜利态，显示节省金额 |
| **Expired (clean)** | timer = 0 + 从未触碰清算线 | 绿色，\$0 |
| **Expired (saved)** | timer = 0 + 曾触碰清算线 | 橙色，显示节省金额 |

> `hadDanger` 布尔用于区分两种 Expired 态。

### 4.3 部署依赖

确认合约端 `LIQUIDATION_GRACE_PERIOD_BASE` 已配置**非零**。若配为 0，`hasGrace = false`，所有仓位显示 Safe 且不会倒计时。

## 五、市场信息面板

### 5.1 可用流动性

```plain
availableLiquidity = min(
    maxOpenInterest − currentOI,             // 该市场持仓硬上限
    poolValue × reserveFactor − reserved     // 池子按 reserveFactor 可承接的额度
) 及其它风控上限
```

> **注意**：v0.3.0 的 `RESERVE_FACTOR` 语义已改为**多空合计口径**——`(longOITokens + shortOITokens) × price.max ≤ RF_i × poolUsd`，建议值换算为 3.0（起步）→ 6.0（成熟）。单边集中由 per-side `MAX_OPEN_INTEREST` 兜底。

### 5.2 资金费率

```plain
skew    = 1h-EMA( (longOI − shortOI) / totalOI )
f_long  = clamp( floorFactor + baseFactor · skew , min, max )    // floor 只加在多头侧
f_short = clamp(              − baseFactor · skew , min, max )
```

| 状态 | 多头 | 空头 |
|---|---|---|
| 均衡（skew = 0） | `f_long = floorFactor > 0`（付 floor 给 LP） | `f_short = 0`（不付） |
| 失衡 | 较拥挤侧付得更多 | 较轻侧**可能收取** |

- 某侧费率 > 0 = 该侧**付**；< 0 = 该侧**收**（自动计入保证金）
- 合约按**每秒**计，界面按**每小时 %** 显示
- 净额流向 **LP 池**，不是一方直接付给另一方

### 5.3 全局风控指标（v0.3.0 新增）

```plain
net_i    = max(0, longPnl_i) + max(0, shortPnl_i)     // 跨边不轧差，边内轧差
pnlRatio = Σ net_i / poolUsd                          // 全局净义务比

pnlRatio > 0.75  → ADL 触发
pnlRatio ≤ 0.50  → ADL 退出
pnlRatio > 0.65  → LP 提款封锁
```

## 六、订单列表（Open Orders / History）

| 字段 | 计算 / 格式化 | 精度陷阱 |
|---|---|---|
| Size (USD) | `order.sizeDeltaUsd` | `× 10^30` |
| Token Size | `formatUnits(sizeInTokens, 18)` | ⚠️ **必须用 18，不是 `indexToken.decimals`** |
| 关仓单 Token Size | `tokensRaw = (position.sizeInTokens × sizeDeltaUsd) / position.sizeInUsd`，再 `formatUnits(tokensRaw, 18)` | 同上 |
| Trigger 价格 | `parseContractPrice(contractTriggerPrice, 18)` | ⚠️ 用 8 会显示 `0.000007` |
| 触发条件文案 | 按 §订单类型表的 max/min 条件生成 | 多空方向别写反 |

> ℹ️ `orders.ts` 中 limit / stop-limit 的 **increase 路径**使用自消除公式 `(sizeDeltaUsd × 10^k / price)` 再 `formatUnits(result, k)`，等价于 `sizeDeltaUsd / price`，**k 值无关**，显示正确，无需改动。

## 八、UI 文案建议（防误解清单）

| # | 场景 | 建议 |

| 1 | Pay / Size 栏 | Pay 标「USDC」、Size 标「USD」——10 USDC ≠ \$10 USD，差 0.01%~0.02% |

- 补齐 `sizeDeltaUsd` / `sizeDeltaInTokens` 到 `position.sizeInUsd` / `position.sizeInTokens` 的开仓、加仓、部分减仓、全平与展示换算。
