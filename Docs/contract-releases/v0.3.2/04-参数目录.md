## 1. 阅读说明

### 1.1 每行字段口径（deliverables.md 第 04 项）

每个逐行参数卡片包含 14 个必填字段（默认值与部署值分列）：

| 字段 | 含义 |
| --- | --- |
| 参数名 | Keys 库中的 base key 常量名 |
| key 构造 | fullKey 的构造方式（base key + abi.encode 附加维度） |
| Solidity 类型 | DataStore 存取类型（uint256 / int256 / address / bool / string / bytes32） |
| 精度 | FLOAT_PRECISION（1e30，1e30 表示 100% 或 1x）或 WEI_PRECISION（1e18，1e18 表示 100% 或 1x）或无量纲/秒 |

### 1.2 精度与 key 构造记法

- `FLOAT_PRECISION = 1e30`、`WEI_PRECISION = 1e18`（`src/utils/Precision.sol`；v0.3.2 在 `src/constants/FX100Keys.sol` 头部新增了统一精度注释约定，`src/data/Keys2.sol` 同）。
- fullKey 构造：`Config` 侧为 `FX100Keys.sol::getFullKey`，即 `data` 为空时 fullKey = base key（全局参数），否则 `keccak256(bytes.concat(baseKey, data))`；Keys 库内的专用 builder（如 `FX100Keys.sol::minDynamicSpreadKey`）等价于 `keccak256(abi.encode(BASE, 维度...))`，二者字节序列一致。
- 写入权限体系：`src/config/Config.sol::setUint/setInt/setAddress/setBool/setBytes32` 受 `onlyKeeper`（CONFIG_KEEPER 或 LIMITED_CONFIG_KEEPER，后者仅限 `allowedLimitedBaseKeys`）+ `_validateKey`（`allowedBaseKeys` 白名单）约束；仅 `setUint` 走 `ConfigUtils.sol::validateRange` 数值校验，**`setInt` 不做任何范围校验**（`src/config/Config.sol::setInt` 函数体只有 `_validateKey`）。绕过 Config 的 `DataStore` 直写需要 CONTROLLER 角色（`src/data/DataStore.sol`）。

### 3.1 动态点差链路总述（uint256 → int256）

提交 `4a40477`（phase1，uint256→int256）、`c8b84e3`（phase2，min/max clamp）、`7d639c9`（phase3+4，清算/ADL `allowNegativeSpread=false`）、`b81786f`（R2-B10 指数上限）。核心 diff：

- v0.3.1 `PositionPricingUtils.sol::getDynamicSpread` 返回 `(uint256, bool)`，`dynamicSpread <= 0` 时直接截为 0；
- v0.3.2 返回 `(int256, bool)`，改为 `Calc.clamp(dynamicSpread, minDynamicSpread, maxDynamicSpread)`，普通开/减仓允许负点差；清算与 ADL 经 `PositionUtils.sol::getExecutionPriceForDecrease` 传 `allowNegativeSpread=false`，把负的 min 抬到 0。

以下 3.2–3.6 各参数自身 key、类型、精度、写入入口均未变，「版本变化」列只记消费端语义差异。
