## 1. 先建立一个正确模型

FX100 是 Oracle 定价的 Perp，不是订单簿撮合交易。一笔订单可以拆成四个问题：

1. **是增加还是减少仓位？** `Increase` 表示开仓/加仓，`Decrease` 表示减仓/平仓。这不是价格涨跌的意思。
2. **是立即执行还是等待条件？** `Market` 尽快由 keeper 执行；`Limit` / `Stop` 等待触发价。
3. **是多仓还是空仓？** 由 `isLong` 决定；多和空不是两组新的 `OrderType`。
4. **触发后允许什么成交价？** `triggerPrice` 决定何时可执行，`acceptablePrice` 用于验证执行价是否可接受；两者不是同一个字段。

`Market` 也不等于同步成交。用户创建订单后仍需 keeper 执行，页面必须能表达 Pending、Executed、Cancelled 等过程和结果。

## 2. 七种主订单类型

| 合约枚举 | 交易员理解 | 多头例子 | 空头例子 | 主要测试风险 |
|---|---|---|---|---|
| `MarketIncrease` | 市价开仓/加仓 | 现在开多 | 现在开空 | 滑点方向反了、重复建仓、取错 bid/ask |
| `LimitIncrease` | 回调或反弹到目标价再开仓 | 现价下方低吸开多 | 现价上方高抛开空 | 多空触发不等号或 min/max 用反 |
| `StopIncrease` | 突破/破位后追加方向仓位 | 现价上方突破开多 | 现价下方破位开空 | 被误识别成 Limit，触发价被误当成成交上限 |
| `MarketDecrease` | 市价减仓/平仓 | 卖出平多 | 买回平空 | 平仓取价方向错、部分平变全平、反向开仓 |
| `LimitDecrease` | 止盈减仓 | 价格上涨到 TP 平多 | 价格下跌到 TP 平空 | 空头条件写反、超额减仓、autoCancel 残留 |
| `StopLossDecrease` | 止损减仓 | 价格下跌到 SL 平多 | 价格上涨到 SL 平空 | 空头条件写反、跳空后误把 trigger 当成成交价 |
| `Liquidation` | 仓位达到可清算条件后由 keeper 强制平仓 | 价格下跌使多仓失去抵押安全垫 | 价格上涨使空仓失去抵押安全垫 | 保护期未到就清算、多空价格方向错、与 ADL 混淆 |

`SecondaryOrderType.Adl` 是二级标记，用来说明这次强制去杠杆是 ADL 路径。它不是第八种用户挂单，页面不应把 ADL 显示成用户主动市价平仓或普通清算。

## 3. 触发单的精确条件

Oracle 提供 `min` / `max` 双价。页面文案可以简化为“市价 ≤ / ≥ 触发价”，但测试断言必须使用合约精确侧：

| 订单类型 | 多头触发 | 空头触发 | 策略记忆 |
|---|---|---|---|
| `LimitIncrease` | `max <= triggerPrice` | `min >= triggerPrice` | 多头等跌，空头等涨 |
| `StopIncrease` | `max >= triggerPrice` | `min <= triggerPrice` | 多头追涨，空头追跌 |
| `LimitDecrease` | `min >= triggerPrice` | `max <= triggerPrice` | 多头涨了止盈，空头跌了止盈 |
| `StopLossDecrease` | `min <= triggerPrice` | `max >= triggerPrice` | 多头跌了止损，空头涨了止损 |

边界测试不能只做“越过触发价”，每个方向都要执行：未到边界一个最小单位、恰好等于边界、越过边界一个最小单位。对应数据集见 SCN-069。

## 4. 触发价、执行价和可接受价

| 字段 | 回答的问题 | 测试要点 |
|---|---|---|
| `triggerPrice` | 什么时候允许 keeper 执行？ | 只决定触发，不等于最终成交价 |
| Oracle `min/max` | 此次是否达到精确触发条件？ | 不能只用 K 线最后价代替 |
| `executionPrice` | 这笔仓位实际用什么价格变化？ | 包含执行时价格和 Price Impact / spread |
| `acceptablePrice` | 执行价最差能接受到哪里？ | 开多/平空与开空/平多的方向相反 |

市价单的四象限是：

| 操作 | 对用户不利的方向 | 合约可执行条件 |
|---|---|---|
| 开多 `MarketIncrease long` | 买入价更高 | `executionPrice <= acceptablePrice` |
| 平空 `MarketDecrease short` | 买回价更高 | `executionPrice <= acceptablePrice` |
| 开空 `MarketIncrease short` | 卖出价更低 | `executionPrice >= acceptablePrice` |
| 平多 `MarketDecrease long` | 卖出价更低 | `executionPrice >= acceptablePrice` |

在 `acceptablePrice` 边界恰好相等时应允许执行；只向不利方向越过一个最小价格单位时，市价单应 Cancelled 并退款。完整数据集见 SCN-070。

## 5. 三种“执行没有成功”不能混为一种

| 结果 | 订单 | 资金 | 用户下一步 |
|---|---|---|---|
| `Cancelled` | 删除/终态 | 应退还的资金退还 | 修改策略后新建订单 |
| `Frozen` | 保留且标记冻结 | 不按撤单退款 | 调整或由冻结单 keeper 重试 |
| Oracle / Sequencer `Revert` | 回滚到原状态 | 不变 | 等依赖恢复，不要重复创建 |

`Pending` / `Waiting` 也不是失败：市价单可能在等 keeper，触发单可能在等价格或 `validFrom`。页面必须告诉用户正在等什么。

## 6. 补齐后的覆盖矩阵

| 类型/能力 | 原 64 条 | 补充场景 | 补齐后的明确范围 |
|---|---|---|---|
| `MarketIncrease` | 开多明确，开空间接 | SCN-065、070 | 市价开多/开空及可接受价边界 |
| `MarketDecrease` | 多空都有 | SCN-070 | 市价平多/平空及可接受价边界 |
| `LimitIncrease` | 多空都有 | SCN-069、071 | 多空精确触发边界和生命周期 |
| `StopIncrease` | 多空都有 | SCN-069、071 | 多空精确触发边界和生命周期 |
| `LimitDecrease` | 多头 TP | SCN-066、069、071、072 | 多空 TP、边界、状态和关联 TP/SL 清理 |
| `StopLossDecrease` | 多头 SL | SCN-067、069、071、072 | 多空 SL、边界、状态和关联 TP/SL 清理 |
| `Liquidation` | 通用强平 | SCN-068 | 多仓/空仓强平、保护期和残留单清理 |
| `Adl` | 用户可见结果 | SCN-068 | 与普通平仓/清算的显示和事件区分 |

“覆盖全部类型”不等于“穷尽所有组合”。S07 将主订单类型、多空方向、关键一单位边界和三种失败资金语义纳入发布验收；费用逐 wei 守恒和合约内部分支仍由 ledger / integration 用例承担。
