## 描述（Text 属性）

【结论先说】/api/stats/volume 与 subgraph 都是正常的，数据也是真实的。真正的缺陷是前端把「还在加载」显示成了「N/A」。

【已排除的可能】
1. subgraph 有数据：直接打 NEXT_PUBLIC_INDEXER_URL（v0.3.3），24h 内 22 个 token 都有真实成交量，例如 BTC $984,873、ETH $2,258,911、AAVE $1,681,274。
2. 接口聚合逻辑正确：用 route 的原样查询（含 indexToken_in 过滤、first=604）单独复现，返回 82 条、聚合出 22 个 token，金额与预期一致。
3. 不慢：同一条查询实测 3 次 849ms / 318ms / 402ms。
4. 不是缓存问题：本地 REDIS_ENABLED=false，该 route 的 redisEnabled = (REDIS_ENABLED !== 'false') 因此为 false，不走 Redis。

【根因】MarketSelect.tsx:318
    const formatVolume = (volume?: number | bigint) => {
      if (volume === undefined || volume === 0 || volume === 0n) return 'N/A';
      ...
undefined（尚未加载）与 0（确实无成交）被合并成同一个 'N/A'。
而 volume24hAtom 的初始值是 {}（state/base/markets.ts:128），useVolume24h 在 TradePage 挂载后才发起 fetch，所以【首屏必然全是 N/A】，直到请求返回才一次性全部出现 —— 这正是「过一会就都出来了」的现象。

整条链路都没有加载态可用：useVolume24h 不返回 isLoading（hooks/market/useVolume24h.ts），MarketSelect 里也没有任何 isLoading/isPending。同一个文件里 formatOnchainUsd(:324) 和 formatChange(:329) 有同样的问题。

【为什么这不只是「等一下就好」】
N/A 的语义是「此数据不存在」，用户看到会判断成后端没记录，从而去查一个不存在的问题（本次就是这样触发的排查）。而且 useVolume24h 是 5 分钟一次的轮询，任何一次失败都会静默 return（:25 if (!res.ok) return; 和 :45 catch 空实现），前端仍然显示上一次的值或 N/A，无法察觉接口已经挂了。

【建议】
1. 区分三态：undefined = 加载中（显示骨架屏或 '—'）、0 = 真的无成交（显示 '$0' 或 '—'，不要用 N/A）、有值 = 正常。至少让「加载中」不要显示成 N/A。
2. useVolume24h 暴露 { isLoading, isError }，MarketSelect 与顶栏据此渲染。
3. fetch 失败不要完全静默 —— 至少 console.warn，便于排查（现在两处都是空 catch / 裸 return）。
4. 同文件的 formatOnchainUsd / formatChange 建议一并处理，它们有同样的 undefined-vs-0 混淆。

【顺带一个潜在问题（不紧急，未触发）】
route 的 QUERY_FIRST = 24 * INDEX_TOKENS.length + 4，配合 orderBy timestamp desc + first 使用。24h 滚动窗口最多可跨 25 个整点桶（首尾各一个不完整小时），25 个 token 全程活跃时需要 25×25=625 行，而当前上限是 25×24+4=604 —— 极端情况下最旧的桶会被静默丢弃，导致 24h 成交量少算。目前实际只有 82 行，远未触发。建议把 +4 改成 +INDEX_TOKENS.length（即 25×N），或直接分页取全。

【补充说明：从未交易过的市场有成交量，这个不是 bug】
排查中确认 AAVE 有连续 8 个小时桶、金额零散（$87 / $9,748 / $767,166），是明显的真实活跃交易；ZEC $200,000 / ONDO $80,000 / TIA $20,000 三个整数集中在同一个整点（2026-08-06T08:00），像是一次性下的测试单。Base Sepolia 是共享测试网，其他人（含开发者验证 batch2）也在交易，所以自己没交易过的市场有量属正常。
