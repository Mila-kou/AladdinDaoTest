### 范围

- `DataStore`

- 权限
- 配置值
- 治理事件
- 配置前后业务行为
- 部署失败时不得留下半初始化状态

## M05 执行价与 Dynamic Spread

### 当前状态

负 Dynamic Spread 方案为**待评审实施**。目标用例可以先编写，但不得把目标行为描述成 v0.3.1 已上线。

### 目标公式

```plain
rawSpread = constantSpread + depthSpread + skewImpact

普通自愿交易：
dynamicSpread = clamp(
  MIN_DYNAMIC_SPREAD[market][isLong],
  MAX_DYNAMIC_SPREAD[market][isLong],
  rawSpread
)

清算 / ADL / 仓位安全校验：
dynamicSpread = max(0, rawSpread)
```

### 必测场景

1. Constant Spread、Depth Spread、Skew Impact 单独生效。
2. 三项组合和取整方向。
3. 改善平衡时普通交易出现负 spread / rebate。
4. 加剧失衡时正 spread。
5. Long / Short 分别验证 MIN/MAX clamp。
6. `minSkewImpact` 更紧时由 skew clamp 生效。
7. `minDynamicSpread` 更紧时由 dynamic clamp 生效。
8. 普通开仓、加仓、减仓、平仓均支持目标负值行为。
9. 清算、ADL、安全校验始终 floor-at-0。
10. Event 与 Reader 返回 `int256`，正负号正确。
11. 前端执行价、Total Spread、Price Impact 三处结果一致。
12. 缺省配置为 0 时应被部署检查识别，不能静默上线。

### P0：R5-B02

Price Impact 的指数必须在调用 `exp` 前封顶：

```plain
exponent = orderSize × parameter / depth
```

需要验证：

- 低深度 + 中等规模订单不会使 `exp` revert。
- 超界时返回受控上限。
- 清算判定和清算执行保持可用。
- 与乘法溢出类问题分别覆盖。

## M08 清算、保护期与 ADL

### 清算

1. 价格暴跌 / 暴涨触发多空清算。
2. Funding 侵蚀触发清算。
3. 补保证金、减仓和价格恢复救仓。
4. 清算费和剩余保证金精确账本。
5. Oracle 时间窗使用仓位最后一次增减时间。
6. 保护期内拒绝 Keeper 清算，到期后允许。
7. 加仓不重置保护期。
8. 用户主动减仓不受保护期限制。

### R5-B01

`isPositionLiquidatable` 必须使用真实的 `balanceWasImproved`：

- 改善平衡档费率变化必须影响清算判定。
- 不得因默认 `false` 高估费用而提前清算。
- 同时验证开仓、加仓、减仓后的安全校验。

### ADL

1. 全局 PnL Ratio > 0.75 触发。
2. 降至 <= 0.50 退出。
3. 0.65～0.75 期间 LP 提款封锁但 ADL 不触发。
4. 跨市场聚合。
5. 只能对盈利侧执行。
6. 执行前检查全局价格时效。
7. ADL 订单使用独立 SecondaryOrderType。
8. ADL 执行价始终 floor-at-0。
9. Grace 是否限制 ADL 必须按最终产品决定验收。

### R4-B01

Vault 本地余额不足以覆盖提款时：

```plain
receiver 实收
= Vault 本地余额
+ Strategy 提取差额
```

必须覆盖：

- 本地余额为 0。
- Strategy 余额为 0。
- 两者同时存在。
- 本地余额刚好等于提款额。
- Strategy 提取失败。
- Receiver 最终到账和 Vault/Strategy 余额闭合。

- Cancel：订单取消且已退款。
- Freeze：订单冻结，可重试，资金未退。
- Oracle Revert：价格源暂不可用，订单保持。
- Relay 错误：展示具体失败原因和重试入口。

## 十、完成标准

一个模块只有同时满足以下条件才算完成：

1. 正常、边界、异常和恢复场景均有用例。
2. Long / Short 和关键订单类型已覆盖。
3. 状态、资金、事件、错误、恢复五类断言齐全。
4. 所有金额类用例满足账本闭合。
5. P0 / P1 缺陷有复现和修复后目标测试。
6. 待评审需求没有被误写成已上线行为。
7. Skip 和 Expected Fail 有明确原因及解除条件。
8. 用例已加入测试账本对应模块。
9. 全量测试无非预期失败。
10. 前端、SDK、Reader、Indexer 对关键字段口径一致。
