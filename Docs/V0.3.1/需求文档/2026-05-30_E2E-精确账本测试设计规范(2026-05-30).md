# 第一节：LedgerSnapshot 完整结构
每笔操作前后各调用一次 `_snapshot()`，捕获下面所有状态。
## AccountState（链上余额）
- `traderUsdc` — usdc.balanceOf(trader)
- `lpVaultAssets` — lpVault.totalAssets() ★ **LP核心，最关键**
- `posVaultUsdc` — usdc.balanceOf(positionVault)
- `feeReceiverUsdc` — usdc.balanceOf(feeHandler)，仅 claimFees() 后变化
## MarketState（DataStore 市场级别）
**OI（两个维度，缺一不可）**
- `oiLongUsd` — cumulativeOpenCostsKey(mi, true)：多头总开仓成本(USD)
- `oiShortUsd` — cumulativeOpenCostsKey(mi, false)：空头总开仓成本(USD)
- `oiLongTokens` — openInterestInTokensKey(mi, true)：多头总token数量
- `oiShortTokens` — openInterestInTokensKey(mi, false)：空头总token数量
**Funding per size（4个方向）**
- `negFundingPerSizeLong/Short` — negativeFundingFeePerSizeKey
- `posFundingPerSizeLong/Short` — positiveFundingFeePerSizeKey
- `fundingUpdatedAt` — fundingUpdatedAtKey
**协议手续费**
- `claimableFeeAmount` — claimableFeeAmountKey(mi, usdc)
**价格影响池（G-DS 场景）**
- `positionImpactPoolAmount` — positionImpactPoolAmountKey(mi)
## PositionState（当前 trader 仓位）
- `sizeInUsd / sizeInTokens / collateralAmount`
- `negFundingFeePerSize / posFundingFeePerSize`（开仓时写入的基准费率）
## 关键概念
**oiLongUsd 是什么？** 所有多头仓位的 sizeInUsd 之和，按开仓时的执行价计算，**不随价格变化**。
**LP 的盈亏从哪里来？**
```javascript
LP浮盈浮亏 = oiLongTokens × 当前价格 - oiLongUsd    （多头方向）
```
价格上涨时多头盈利，LP 亏损（需要支付 PnL 给 trader）。

# 第二节：断言分层框架
在 `test/e2e/accounting/fixtures/E2ELedger.t.sol` 中实现。
```solidity
// Layer 1：资金守恒（每笔操作都必须通过）
function _assertZeroSum(LedgerSnapshot memory s0, LedgerSnapshot memory s1) internal;

// Layer 2：账户精确值（精确到 1 wei）
// expTraderDelta: 正=trader收到USDC，负=trader发出USDC
function _assertExactAccount(s0, s1, int256 expTraderDelta, int256 expLpDelta) internal;

// Layer 3：OI精确变化
function _assertOI(s0, s1, int256 expLongUsd, int256 expShortUsd,
                   int256 expLongTok, int256 expShortTok) internal;

// Layer 3：协议费累积
function _assertClaimableFee(s0, s1, uint256 expFeeDelta) internal;

// Layer 3：资金费率只增不减
function _assertFundingAccumulated(s0, s1, bool isLong) internal;
```
**典型使用方式：**
```solidity
LedgerSnapshot memory s0 = _snapshot(posKey);
_openPosition(true, 10_000e6, 50_000e30);
LedgerSnapshot memory s1 = _snapshot(posKey);

_assertZeroSum(s0, s1);
_assertExactAccount(s0, s1, -10_000e6, 0);    // trader-10k，LP不变
_assertOI(s0, s1, 50_000e30, 0, 25e18, 0);    // oiLong +50k，tokens +25e18
```

# 第六节：计算公式速查
## 开仓（USD模式，零spread，零fees）
```javascript
executionPrice = indexPrice（normalizedPrice = 2_000e12，非2_000e30）
sizeInTokens   = sizeDeltaUsd / executionPrice = 50_000e30 / 2_000e12 = 25e18

DataStore变化：
  cumulativeOpenCostsKey    += sizeDeltaUsd   ← OI USD增加
  openInterestInTokensKey   += sizeInTokens   ← OI tokens增加

资金流：positionVault += collateral；trader -= collateral；LP = 不变
```
## 平仓（USD模式，零spread，零fees）
```javascript
pnl(long) = sizeInTokens × (closePrice - openPrice) / FLOAT_PRECISION / USDC_PRICE
          = 25e18 × (2100e12 - 2000e12) / 1e30 / 1e24 = 2500e6 = 2500 USDC

资金流：trader += collateral + pnl；lpVault -= pnl；posVault -= collateral
零和验证：(col+pnl) + (-pnl) + (-col) = 0 ✓
```
## 含spread的开仓
```javascript
executionPrice = normalizedIndexPrice × (1 + spread/WEI_PRECISION)
                 normalizedIndexPrice = 2_000e12（WNT 18decimals，oracle乘数1e12）
sizeInTokens   = sizeDeltaUsd / executionPrice（比零spread时少）
```
## 资金费计算
```javascript
fundingFee(USDC) = sizeInTokens × Δneg / FLOAT_PRECISION / USDC_PRICE
                 = sizeInTokens × deltaNeg / 1e30 / 1e24
```
## Token模式 vs USD模式
```javascript
USD模式:   sizeInTokens = sizeDelta / executionPrice
Token模式: sizeInUsd    = sizeDelta × executionPrice

给定相同资金：两种模式开仓后 position 状态完全相同。
```
