# fx100-dev 交易场景手工测试用例

> 与 [FX100-Trade页面功能测试用例.md](../../FX100-Trade页面功能测试用例.md)（54 条控件级用例，**保持不动**）互补：本文档以**真实交易为主线**——每条用例是一笔（或一组）具体交易，写清交易数据与它要验证的目标（免清算保护 / 关仓 / 加仓 / 调杠杆 / 调保证金 / 限价开仓语义）。
> 执行方式：测试人员在自己 Chrome 人工操作 + Rabby 逐笔签名；记录员（Claude）经浏览器扩展同步读取页面回填数据核对。环境与钱包前置见 [README.md](README.md)，过程记录见 [OPERATION-LOG.md](OPERATION-LOG.md)。

## 一、页面交易数据全字段断言清单（每条用例的公共核对底座）

**总规则：每条交易用例执行时，对其涉及的数据面做全字段断言**（不只核对个别字段）；用例内"核对数据"栏只列本用例专属的推导断言。字段级核对公式见 [RUN-SHEET.md](RUN-SHEET.md) 锚点表。

| 面 | 数据面 | 字段清单 | 断言基准 |
|---|---|---|---|
| S1 | 下单预览（交易详情） | 仓位规模 / 抵押品 / 预估成交价 / 预计清算价格(+距开仓价%) / 价格影响 / 最大滑点 0.5% / 最高（做空为最低）可接受价 / 手续费(0.0500%) / 中继费(估算) / 预计支付；另：可用余额、输入框≈换算值 | 锚点 1-6：抵押=规模/杠杆；费=规模×0.05%；预计支付=抵押+费（不含中继费）；可接受价=成交价×(1±0.5%)；清算价=成交价×(1∓(1/杠杆−0.55%)) |
| S2 | 持仓行 | Coin+杠杆徽标 / Direction / Size(币量+价值$) / Entry Price / Oracle / PnL($,%) / Est. Liq. Price 或保护倒计时 / Margin / Net Value / Funding / 四个操作按钮（Close Position、TP/SL、Leverage、Adjust Margin） | 净值=Margin−开仓费±PnL−资金费；PnL=(Oracle−Entry)×Size×方向；杠杆徽标≈Value/NetValue；Liq 价按公式 |
| S3 | 免清算保护面板 | 市场徽标 / 杠杆徽标 / 倒计时(15:00 起、链上时间基准) / PnL / Liq 曲线 / 说明文案 | 与 S2 同源：徽标=当前市场与实际杠杆；倒计时与持仓行一致（差≤2s）；PnL 与 S2 一致 |
| S4 | 当前订单行 | 字段全清单**以首笔挂单实测补全**（预期含：类型/方向/规模/触发价与条件符号/创建时间/撤单入口） | 与提交参数一致；撤单后全额退款 |
| S5 | 历史行（交易/订单/资金费率历史） | 字段全清单**以首笔成交实测补全**；重点：记录类型区分（Executed/Cancelled/Liquidation/用户平仓） | 与链上回执一致；无重复行、无丢行 |
| S6 | 顶部统计条 + 余额 | 预言机价格 / 24h涨跌 / 24h成交量 / 持仓量(%与金额) / 资金费率/时 / 可用流动性 / 可用余额 | 交易前后 Δ 断言：OI 随开平仓同向变化（受显示舍入 0.01M 限制）；余额 Δ 符合资金闭环公式 |
| **S7** | **出单参数（链上创建 tx 解码断言，2026-08-28 增补）** | 每笔订单创建 tx 解码：orderType / acceptablePrice / triggerPrice / sizeDeltaUsd / autoCancel | ①**orderType 与用户输入一致**：TP→3(LimitDecrease)、SL→4(StopLossDecrease)、限价开→Limit/StopIncrease（TPSL-007 断言）；②**触发单 acceptablePrice 恒为哨兵**（需求：trading-guide §4.3 + Limit-Stop 规范）：触发开仓 long=MaxUint256/short=0，**触发平仓（TP/SL）long=0/short=MaxUint256**（SLACCEPT-009 断言）；③市价单 acceptable = 创建时预估成交价×(1±maxSlippage)（方向按买卖）；违反任一即立缺陷 |

⚠️ 已知观察项（执行时复核）：市场选择器弹窗中 BTC 持仓量（2026-08-28 实测 $7.56M/$2.40M）与顶部统计条（同时刻 $6.72M/$2.07M）**数值不一致**——执行 006/011 时同屏截图取证，确认是口径差异（名义 OI vs 成本 OI）还是缺陷。

### E2E-PROT-001 · 开仓即激活免清算保护：倒计时起点 15:00、链上时间基准、页面刷新不重置

| 字段 | 内容 |
|---|---|
| 目的（这笔交易测什么） | 这笔交易用来验证免清算保护随开仓即时激活：倒计时初值为 15:00，到期时刻严格等于开仓交易的链上区块时间戳 +900 秒（而非本地时钟或页面加载时刻），且页面硬刷新后倒计时按剩余时间续显、绝不重置回 15:00。 |
| 设计方法 | 场景法 + 边界值分析（计时起点 15:00）+ 时钟基准配对核对（页面读数 vs 链上区块时间戳） |
| 优先级 | P0 |
| 资金风险 | 低——成本仅开/平手续费合计 ~$1.00 + 中继费 ~$0.15×2；2x 强平价距现价 −49.45%，真实波动不可能触及。 |
| 前置条件 | 1) https://fx100-dev.vercel.app/trade?market=BTCUSDC 已通过 Browser Wallet 连接 Rabby，网络 Base Sepolia 84532；2) 账户 USDC 余额 ≥ 600（当前 ~98,217 充足）；3) 当前无 BTCUSDC 持仓、无挂单；4) sepolia.basescan.org 可访问用于查区块时间戳。 |
| 测试数据 | 市场 BTCUSDC；市价页签；方向 Long；仓位规模 $1,000（USD 计价输入 1000）；杠杆 2x → 保证金 $500；不设 TP/SL；不开仅减仓。 |
| 操作步骤 | 1. 记录下单前 oracle/指数价 P0 与账户余额 B0（截图）。<br>2. 市价开多 $1,000 / 2x，核对下单区"预计支付"金额后 Rabby 签名提交，记录开仓 tx hash。<br>3. 成交后 ≤10 秒内截图保护面板与持仓行，记录倒计时首次读数。<br>4. 在 sepolia.basescan.org 打开该 tx，记录区块时间戳 T_block；计算链上到期时刻 T_end = T_block + 900 秒。<br>5. 等待约 2 分钟，记录刷新前倒计时读数 R1 及本地时刻，立即硬刷新页面（Cmd+Shift+R），页面恢复后记录读数 R2 及本地时刻。<br>6. 再任取 1 个时刻 t 记录页面倒计时 R(t)，与 T_end − t 对照（本地钟与链上钟的偏差用 BaseScan 最新区块时间校准）。 |
| 核对数据 | 开仓 tx hash 与区块时间戳 T_block；下单区预计支付、成交价 entry、开仓手续费、保证金；倒计时首次读数；R1/R2 及各自本地时刻；T_end 反推剩余时间；余额 B0 与成交后余额。 |
| 期望结果（含推导） | 推导：开仓手续费 = 1,000 × 0.05% = $0.50；预计支付 = 500 + 0.50 = $500.50（中继费 ~$0.15 另扣）；entry ≈ P0 × (1 + 0.14%)（$1,000 单实测价格影响 ~0.14%）；初始净值 ≈ 500 − 0.50 − 1,000×0.14% ≈ $498.10（±0.5）。<br>判定：a) 成交后 ≤10 秒的首次倒计时读数介于 14:50–15:00（初值 15:00 扣除页面轮询延迟）；b) 任一时刻页面读数 R(t) 与 T_end − t 之差 ≤ 5 秒，证明计时基准为链上 T_block+900 而非本地/页面时间；c) 刷新不重置：R2 ≈ R1 − 刷新耗时（差 ≤ 5 秒）且 R2 < R1，绝不回跳 15:00；d) 持仓行 Est. Liq. Price 列在保护期内显示倒计时而非强平价数值（以实测回写具体呈现）。 |
| 恢复清理 | 若不接续执行 PROT-002/003：立即 Close Position 全平（平仓费 = 1,000×0.05% = $0.50），记录平仓 tx hash，确认持仓行消失、无残余挂单；若接续执行后续用例，仓位保留交由 PROT-002/003 处置并在本条备注。 |

### E2E-PROT-002 · 保护面板倒计时与持仓行 Est. Liq. Price 列倒计时一致性（三时点采样）

| 字段 | 内容 |
|---|---|
| 目的（这笔交易测什么） | 这笔持仓用来验证同一保护到期时刻在两处 UI（免清算保护面板、持仓行 Est. Liq. Price 列）的倒计时呈现一致，不存在两套计时源或漂移。 |

### E2E-PROT-003 · 保护期内主动全平：平仓不受限、保护随仓位消失、返还金额符合净值公式

| 字段 | 内容 |
|---|---|
| 目的（这笔交易测什么） | 这笔交易用来验证免清算保护只限制强平、不限制用户主动操作：保护期内可正常全平，平仓后保护面板与持仓行倒计时随仓位一并消失（证明保护是仓位属性），返还金额与净值公式吻合；并附探针步骤实测"平仓后立即重开是否重新获得完整 15:00"。 |
| 设计方法 | 状态迁移法（保护中 → 用户平仓 → 无仓位 → 重开探针）+ 资金守恒核对 |
| 优先级 | P0 |
| 资金风险 | 低——主仓成本手续费 ~$1.00，探针仓额外 ~$0.10，另中继费每笔 ~$0.15。 |

| 测试数据 | 主操作：Close Position 弹窗市价全平 100%；探针（可选）：平仓后立即市价开多 $100 / 2x（保证金 $50），随后立即全平。 |

### E2E-LMT-007 · 限价预览锚定核对：预估成交价/强平价应随触发价联动（锚定触发价而非当前 oracle），预计支付不随价变

| 字段 | 内容 |
|---|---|
| 目的（这笔交易测什么） | 核对限价模式下预览区计算锚点：预估成交价应锚定所填触发价（±价格影响），强平价应按触发价推导，预计支付（抵押+开仓费）只与规模/杠杆相关不随触发价变化——识别前端把限价预览错误锚定当前 oracle 的公式缺陷。以实测回写实际锚定行为。 |
| 设计方法 | 公式核对 + 对比测试（同参数下改变触发价观察预览联动） |
| 优先级 | P2 |
| 资金风险 | 预览为纯前端计算，两次抄录间 oracle 漂移会引入小幅噪声——两组抄录间隔控制在 1 分钟内，并同时记录当时 P0 用于归因。 |
| 前置条件 | 同 E2E-LMT-001 前置；本条主体为前端预览核对，仅可选提交一笔远价挂单。 |
| 测试数据 | Long / Limit；规模 $500；杠杆 5x（抵押 100 USDC）；对比两组触发价：T1 = P0 × 0.998（例 79,640.4）、T2 = P0 × 0.95（例 75,810）——同一填单会话内先后输入；可选仅提交 T2（远价档，挂单资金 100.25 USDC，不会触发）。 |
| 操作步骤 | 1) 限价页签填规模 500、杠杆 5x、触发价 T1，截图并抄录预览三项：预估成交价 / 预估强平价 / 预计支付；2) 只改触发价为 T2，再次截图抄录同三项；3) 对比两组数值判定锚定基准；4)（可选）提交 T2 挂单并签名记录 tx hash，核对订单行显示的触发价/强平价与预览一致；5) 撤单，记录 tx hash，按 LMT-002 口径核退款。 |
| 核对数据 | T1 组 vs T2 组的预估成交价、强平价、预计支付三项差异；订单行显示值 vs 预览值。 |
| 期望结果（含推导） | 锚定正确的判定标准：① 预估成交价随触发价联动——T2 组 ≈ 75,810（±0.2%，含价格影响 ~0.07%：$500 单按 $1,000 单 0.14% 内插），明显不同于 T1 组 ≈ 79,640；② 强平价按触发价推导——T2 组 ≈ T2 × 0.8055 = 75,810 × 0.8055 ≈ 61,065（推导：1 − (1/5 − 0.55%)），T1 组 ≈ 79,640 × 0.8055 ≈ 64,150；③ 预计支付两组相同 = 100 + 0.25 = 100.25 USDC（推导：抵押 500/5 + 开仓费 500×0.05%，开仓费按规模计与价格无关）。缺陷判定：若两组预估成交价都停在当前 oracle 附近、不随 T 变化，或强平价按 oracle 而非触发价推导 → 前端限价预览锚定错误，记缺陷候选（fx100-BUG-NNN）并回写实测锚定行为。若提交了挂单：订单行触发价/强平价须与 T2 组预览一致（±1 tick）。 |
