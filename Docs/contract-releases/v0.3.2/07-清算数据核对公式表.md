## 0. 一句话核心事实

**清算 = keeper 调 `LiquidationHandler.executeLiquidation` → 过保护期闸门 → 就地造一张「全平 Liquidation 订单」→ 走与普通减仓完全相同的账务路径，只多三件事：执行价禁负点差、执行时再判一次 `isPositionLiquidatable(true,true)`、费用里追加清算费并允许破产早退。**

| 事实 | 依据 |
|---|---|
| 判定式 `remaining = collateralUsd + PnL(清算执行价) + 正funding − (平仓费+负funding)`，**不含清算费** | `src/position/PositionUtils.sol:354-386`（`isLiquidation=false` :366） |
| 三段判定顺序：`< MIN_COLLATERAL_USD`（受门控）→ `<= 0` → `< sizeInUsd×factor` | `PositionUtils.sol:400-413` |
| 清算路径 factor = `MIN_COLLATERAL_FACTOR_FOR_LIQUIDATION`（#1 0.4% / #2 0.5% / #4 0.5%），开减仓校验用 `MIN_COLLATERAL_FACTOR`（#1/#2 1% / #4 0.5%） | `PositionUtils.sol:388-392`；参数快照 |
| `OrderType.Liquidation` 枚举值 = **5** | `src/order/Order.sol:10-27`（第 6 项） |
| 保护期 `graceEnd = ts + BASE × MULTIPLIER / 1e18`，仅首开仓写入；`graceEnd > block.timestamp` 即 revert | `src/order/IncreaseOrderUtils.sol:46-55`；`src/liquidation/LiquidationUtils.sol:44-46` |
| 支付瀑布顺序：正PnL入账 → +正funding → 负funding → 负PnL → 费用整包（平仓费+清算费−折扣）→ 剩余退 trader | `src/position/DecreasePositionCollateralUtils.sol:113-240`；`DecreasePositionUtils.sol:275-277` |
| 清算失败整笔 revert（无 try/catch），不会出现 OrderCancelled | `src/exchange/LiquidationHandler.sol:51-74` |
| tx-fork 当前 `POSITION_FEE_FACTOR(market#1, balanceWasImproved=false)` **未设置=0**（旧快照 260902 为 5e26） | 260902-2305 parameters.json；**冲突见 §8** |

## 5. 账本守恒（单笔清算，USDC 计）

记：`C0` = 清算前 collateralAmount；`G = P>0 ? ⌊P/price.max⌋ : 0`；`L = P<0 ? ⌈|P|/price.min⌉ : 0`；`pos/neg` = 正/负 funding token；`TC = totalCostAmountExcludingFunding`；`FAP = feeAmountForPool`；`FRA = feeReceiverAmount`（含 liqR）；`liqR = liquidationFeeAmountForFeeReceiver`；`aff = affiliateRewardAmount`。

偿付型（无早退）：
```
ΔTrader        = + G + C0 + pos − neg − L − TC                                     // §4 ⑥
ΔLP Vault      = − G − max(pos − neg, 0) + L + FAP
ΔPositionVault = − C0 + max(neg − pos, 0) + FRA + aff
                 // 即 −C0 + Δclaimable(FUNDING) + Δclaimable(POSITION) + Δclaimable(LIQUIDATION) + Δaffiliate
ΔFeeHandler    = 0（claimFees 前）；ΔOrderVault = 0；Δ清算人(USDC) = 0（executionFee = 0，只付 gas）；ΔinsuranceTreasury：不存在

ΣΔ = [G + C0 + pos − neg − L − TC] + [−G − max(pos−neg,0) + L + FAP] + [−C0 + max(neg−pos,0) + FRA + aff]
   = (pos − neg − max(pos−neg,0) + max(neg−pos,0)) + (−TC + FAP + FRA + aff)
   = 0 + 0 = 0          // 第二括号即 §3.3 守恒式
Δclaimable(POSITION) = FRA − liqR；Δclaimable(LIQUIDATION) = liqR；Δclaimable(FUNDING) = max(neg − pos, 0)
```
破产型：
- step="fees"：`ΔTrader = 0`；`ΔLP = −G − max(pos−neg,0) + L`（无 FAP）；`ΔPositionVault = −C0 + max(neg−pos,0) + 已扣费用残留`（残留 = 步⑤ amountPaidInCollateralToken，无键登记）。token ΣΔ 仍 = 0，但 **PositionVault 余额 Δ ≠ 各 claimable 键 Δ 之和**。
- step="pnl"：`L_paid < L`，LP 少收 `remainingCostUsd/price.min`；无费用转账。
- step="funding"：`paid < neg`，`settleFundingFees(paid, pos)` 按 paid 路由；LP/协议少收。

源码：`DecreasePositionCollateralUtils.sol:113-240`；`MarketUtils.sol:445-469`；`src/fee/FeeUtils.sol:34-51`；`DecreaseOrderUtils.sol:59`。合约仓 `test/integration/Liquidation.t.sol` 有两个独立用例以 `-pvDelta == lpDelta + traderDelta` 闭环：`:195`（100x 跌 0.51% 清算）与 `:241`（20% 清算费）。

### 9.2 合约口径反解（ground truth）

记 `q=sizeInUsd, s=sizeInTokens, C=collateralAmount×min, F=neg×min − pos×min, ff=POSITION_FEE_FACTOR(m, balanceWasImproved_全平方向), D=折扣×min, f=MIN_COLLATERAL_FACTOR_FOR_LIQUIDATION, s_liq=清算规则 spread ≥ 0`：
```
多头临界执行价 P_exec = ( q×(1 + f + ff) − C + F − D ) / s ；对应 oracle：index.min = P_exec / (1 − s_liq)
空头临界执行价 P_exec = ( q×(1 − f − ff) + C − F + D ) / s ；对应 oracle：index.max = P_exec / (1 + s_liq)
  推导：remaining = C + PnL + pos×min − (posFee − discount + neg)×min = C + PnL − q·ff + D − F（§1.2），
        令 remaining < q×f（§1.4 ③）并代入 PnL(多)= s·P_exec − q、PnL(空)= q − s·P_exec 即得上式。
  取整：合约的费用项实为 ⌊⌊q×ff/1e30⌋ / min⌋ × min ≤ q×ff（PositionPricingUtils.sol:475 + PositionUtils.sol:374 两次向下再回乘），
        折扣项同样经 applyFactor 取整；用连续量 q×ff 反解会让临界价偏保守，缺口 ≤ 1×collateralTokenPrice.min（tx-fork ≈ 1e-6 USD）。
```

| 6 | 取整 | `/ sizeInTokens` 先除后乘 1e18 | mulDiv | 1e-12 USD 级，展示性 |
| 7 | 保护期 | 文案写死 15 min；窗口需 now ≥ start | 只看 graceEnd；tier≥1 无保护期 | 文案与链上不符 |

### 10.2 陷阱

1. **reason 字符串**：MIN_COLLATERAL_USD=0 时 `remaining<0` 得 `"min collateral"`，非 `"< 0"`（§1.4）。
2. **两套 factor**：Reader 预判必须传 `forLiquidation=true`，否则 #1/#2 按 1% 提前 2～2.5 倍报可清算；mock #4 两者相等（5e27），违背 `MarketUtils.sol:836-837/845` 注释约束 → 按上限杠杆开仓扣一笔费即可清算。
3. **判定不含清算费、执行含**（`PositionUtils.sol:366` vs `DecreasePositionCollateralUtils.sol:109`）：刚过线的仓位可能 `InsolventClose(step="fees")`，此时 `PositionFeesCollected` 全零、claimable 不增，真实费用读 `PositionFeesInfo`。「清算费恒 >0」断言错误。
4. **费用整包 all-or-nothing + 残留**：付不全时已扣部分留在 PositionVault 无记账（`:231-236`），PositionVault 余额 Δ ≠ claimable 键 Δ 之和。
5. **无 insurance/insuranceTreasury**：缺口由 LP 承担；文档若写「清算费进保险金库」属幽灵内容。
6. **清算 keeper 零收益**：executionFee=0，无 KeeperExecutionFee；清算费 receiver 份走 claimable → FeeHandler → FEE_RECEIVER。
7. **失败整笔 revert**：无 OrderCancelled/Frozen，OrderCreated 亦回滚；证据取回执 revert data（selector + 三值）。
8. **Oracle 时间戳**：用 `max(increasedAtTime, decreasedAtTime)` 而非 order.updatedAtTime，无 REQUEST_EXPIRATION_TIME 上限；同块刚加/减仓的仓位易 `OracleTimestampsAreSmallerThanRequired`。MAX_ORACLE_PRICE_AGE=60 s：mock feed 60 s 内未刷新即 `MaxPriceAgeExceeded`（`Oracle.sol:291`）。
9. **funding 时点**：执行在 `updateFundingState` 之后判定；Reader 读旧指数；长时间无交易的市场离线与链上判定有差。
10. **funding 口径不对称**：负 ⌈÷min⌉、正 ⌊÷max⌋ 再 ×min 折 USD；min≠max 时应收偏小、更易判可清算。tx-fork mock USDC 0.999/1.001 即触发此差。
11. **PnL 封顶**：#4 为 60%（#1/#2 100%）；poolPnl 用 maximize=true 的价（多 max/空 min），与个人 PnL 的执行价不同源；`uncappedBasePnlUsd − basePnlUsd` 应作断言而非忽略。
12. **保护期**：公式漏 `/1e18`（文档）；tier 取交易者自身 referrerTiers；tier≥1 在 tx-fork 无保护期；只挡 createLiquidationOrder；加/减仓不重置。
13. **Grace 键 packed-string**：用 abi.encode 派生读回恒 0（TestCode `chain-parameter-snapshot.ts:133-144` 已按 packed 处理，读者）。
14. **全局裸键**：POSITION_FEE_RECEIVER_FACTOR / LIQUIDATION_FEE_RECEIVER_FACTOR / MIN_COLLATERAL_USD / MAX_PRICE_IMPACT_SPREAD 不带 marketIndex。
15. **事件反推**：`feeReceiverAmount` / `feeAmountForPool` 已混入清算费份额，拆分用 `positionFeeAmountForPool` 与 `liquidationFeeAmountForFeeReceiver`；清算费三字段动态追加，按 key 名匹配不按 index；`liquidationFeeUsd` 不进事件；`PositionDecrease.collateralDeltaAmount` = 清算前抵押，到账只能从 Transfer 或 callback eventData 取。
16. **OI 键名**：无 OPEN_INTEREST 键，事件名仍叫 OpenInterestUpdated。
17. **sizeDeltaInTokens 全平不取整**，不要套部分平仓规则。
18. **autoCancel**：只撤 autoCancel=true 的 TP/SL，用例前置须声明。
19. **穿仓时用户全平不成立**：MarketDecrease 的 isInsolventCloseAllowed=false → `InsufficientFundsToPayForCosts` 取消，只有清算能完成；竞争场景用户先平后清算的 selector 为 `EmptyPosition`（读者 `DecreaseOrderUtils.sol:37`）。
20. **STABLE_PRICE 锚**：抵押价与指数价同笔取 oracle 主价，改 mock 价须同步锚，否则判定按 min 估值、执行按 max 成交产生假清算/假 revert（手册 traps，读者）。
21. **SCN-079 「少 1 个 USD 原始单位」**：funding 项粒度为 `token(1e6)×min(1e24)=1e24`，1e30 级步进只能通过 sizeInUsd / 执行价 / collateralAmount×min 调整（读者）。
22. **#1 POSITION_FEE_FACTOR(false)=0 部署缺口**：#1 在 balanceWasImproved=false 分支平仓/清算判定手续费为 0，用 0.05% 会算错；R5-B02 费档差异在 #2 不可见（两档同值），在 #1 表现为 0.05% vs 0。
23. **MAX_POSITION_IMPACT_FACTOR_FOR_LIQUIDATIONS** 死键，不要写进期望；前端读它做 clamp（当前 0）。
24. **行号漂移**：`fx100-verify-handbook` formulas.md §9 / v031-facts 引用的 PositionUtils 324→321、364-365→365-366、PositionPricingUtils 373-400→352-391、MarketUtils 979/987→838/846、DecreasePositionCollateralUtils 219-226→202-209、228-236→211-220、IncreasePositionUtils 220-227→（本表 153-163）；另 formulas.md §9 引的 `PositionUtils.sol:399-412`/`384-412` → v0.3.2 实为 :385-386(remaining) / :388-392(factor) / :397-398(阈值) / :400-413(三分支)，前端 `positions.ts:281-297` → 非同币分支实为 :286-296——需回写。
