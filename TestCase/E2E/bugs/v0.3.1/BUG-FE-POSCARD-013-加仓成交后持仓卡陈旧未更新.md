# BUG-FE-POSCARD-013 · 加仓成交后持仓卡陈旧

## 链上事实（tx 级）

- 00:22:08 加仓单 **OrderExecuted**（tx `0x697b7f79…`）：仓位真实跳为 **sizeInUsd $95,708.83 / 39.118245 ETH / 抵押 $957.08 / ≈100x**。
- 而 ~00:24–00:28 期间前端持仓卡与下单区仍显示 **$10,000 / 10x / 4.0847 ETH / Est. Liq $2,205.21（−9.45%，10x 旧清算线）**——**完全漏掉这笔已成交加仓**。
- TP/SL 行 Token Size 4.0847→**4.0872** 的"微增"是**纯前端显示漂移**：链上 sizeInTokens 真实轨迹 4.084746 → 39.118245（8.5 倍跃升）→ 0，从无 4.0872 中间态。

## 影响（关键）

用户在加仓成交后的数分钟内，从持仓卡读到的是**错误的低风险画像**：
- 真实杠杆 100x、真实清算线约 $2,423（入场下方 ~1%），前端却显示 10x、清算线 $2,205（−9.45%）；
- 用户据此严重低估清算风险；本例 ETH 从 $2,448 跌到 $2,423 只需 −1% 即触发清算，而前端让用户以为还有 −9.45% 缓冲。
- 与 E2E-TRD-035"持仓面板与 Reader T3 内一致"的期望严重不符——偏差非舍入级，而是整仓规模/杠杆/清算价全错。

## 期望

加仓（Adjust Leverage / 加仓市价单）成交后，持仓卡的 Size / 杠杆 / 抵押 / 清算价及 TP/SL 覆盖应即时同步链上真实值（或明确"同步中"提示），不得停留旧仓数据。

## 关联

- 与 BUG-FE-IDXLAG-005（历史/订单状态回填滞后）同源指向前端-索引同步链路，但本单更严重：持仓卡是实时风控依据，陈旧直接误导清算风险判断，故评 S2。
- BUG-FE-TPSLSIZE-012（加仓后 TP/SL 未放大）为并行的真实缺陷（链上 TP/SL sizeDelta 确实仍 $10,000，非显示问题）。

## 证据

链上 tx `0x697b7f79…`（加仓成交）/ `0x4b29bb8e…`（清算）；前端截图（持仓卡 $10,000/10x 与链上 $95,708/100x 并存）；取证脚本 scratchpad forensics7.mjs / query-pos.mjs。
