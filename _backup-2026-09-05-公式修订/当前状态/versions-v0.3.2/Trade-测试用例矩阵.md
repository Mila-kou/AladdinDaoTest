### 2.1 术语规范

| 对象 | 统一写法 | 使用规则 |
|---|---|---|
| 市价开仓 | 市价开仓 / `MarketIncrease` | 用户动作和用例标题写“市价开仓”；合约订单类型写 `MarketIncrease` |
| 限价开仓 | 限价开仓 / `LimitIncrease` | 用户动作和用例标题写“限价开仓”；合约订单类型写 `LimitIncrease` |
| 条件开仓 | 条件开仓 / `StopIncrease` | 用户动作和用例标题写“条件开仓”；合约订单类型写 `StopIncrease` |
| 加仓 | 市价加仓 / `MarketIncrease` | 已有同市场同方向仓位时再执行 `MarketIncrease` |
| 部分减仓 | 市价部分减仓 / `MarketDecrease` | 请求规模小于完整仓位；不使用“部分平仓”或“平 50%” |
| 关仓与全平 | 市价关仓 / `MarketDecrease`；结果为“全平” | “市价关仓”表示用户动作；“全平”只表示 Position 规模归零的结果 |
| 订单更新 | 更新订单 / `updateOrder` | 不再混用“编辑”、“修改”和 Update |
| 订单取消 | 取消订单 / `cancelOrder` | 用户动作写“取消订单”；终态写 `Cancelled` |
| 保护单 | TP/SL 保护单 | 不再混用“附属单”、“子单”和“保护订单” |
| 自动取消 | 自动取消 / `autoCancel` | 行为写“自动取消”；字段和列表名写 `autoCancel` |
| 多空方向 | `long` / `short`；结果为“多仓” / “空仓” | 标题与测试数据使用 `long` / `short`；期望结果可使用中文仓位名称 |
| 订单状态 | `Open` / `Executed` / `Cancelled` / `Frozen` | 只用这组精确状态值，不用“完成”代替具体终态 |
| 费用 | Execution Fee、Position Fee、UI Fee、Funding Fee、Relay Fee | 根据实际费用类型列出，不以单独的 `fee` 作为断言名称 |
| 标准交易 | 标准交易 / Standard | 业务名称写“标准交易”；路径值或产品标识保留 Standard |
| 快速交易 | 快速交易 / Flash | 业务名称写“快速交易”；路径值或产品标识保留 Flash |
| 代付费 | 代付费 / Relay Fee | 业务名称写“代付费”；合约费用类型和字段语境保留 Relay Fee |

### 2.2 入口分类

| 入口 | 含义 | 可判定范围 |
|---|---|---|
| 页面 | 用户从 Trade 页面填写、点击并连接钱包完成操作 | 可判定前端层；结合链上证据时可判定跨层一致性 |
| RPC | 测试账户直接签名并调用用户可用的合约接口 | 只判定合约层，不代替页面交互 |
| RPC 只读 | 只读取链上配置、代码、Reader 或余额，不发送交易 | 只判定环境与数据基线 |
| Admin RPC | 使用管理员或配置角色设置参数、Oracle 或测试夹具 | 只作为数据准备或管理权限验证，不代替用户入口 |
| Time RPC | 在支持时间控制的测试环境推进或指定区块时间 | 只作为时间边界的数据准备手段 |
| Keeper RPC | 使用 Order、Liquidation 或 ADL Keeper 执行相应订单 | 判定执行阶段；必须与订单创建入口的证据关联 |
| Relay RPC | 通过 Relay 提交 EIP-712 请求或快速交易请求 | 判定 Relay、Flash、Relay Fee 与签名链路 |
| 故障注入 RPC | 人为注入 RPC、Oracle、Keeper 或 Indexer 异常 | 只用于异常恢复与幂等性验证 |
| 复用关联用例证据 | 不重复发送业务交易，只复用已登记原子用例的同一份证据 | 只补充订单类型映射或跨域断言，不新增执行次数 |

组合入口统一使用 ` + ` 连接；例如 `RPC + 页面` 表示同一原子用例分别补齐合约层与前端层证据，不表示一次操作同时从两个入口提交。

### 2.4 数据约定

- 主测市场从 CURRENT 部署清单选择；不得把部署 fixture 名称当作固定产品需求。
- Mock 合成市场的 symbol、indexToken、Oracle、marketIndex、collateralToken 和 decimals 均运行时读取。
- Token 精度至少覆盖 8 位和 18 位；Collateral 按实际 decimals；USD 金额按合约 1e30 口径。
- 价格边界中的“±1”指该字段原始整数精度的一个最小单位，不是页面显示的一美元或一美分。
- 每个数据集独立 snapshot/revert 或使用独立账户，避免前序 OI、仓位和订单污染。
- 每条写链用例至少核对 payload、Order 事件、Order Store、Reader、Position/OI、余额差分和页面最终状态。

### 2.5 条件订单 `Frozen` 原子用例约束

`Frozen` 是“订单已进入执行校验，但当前业务状态无法履约”的持久状态，不是所有 Keeper 执行失败的通用结果。本约束适用于 `LimitIncrease`、`StopIncrease`、`LimitDecrease` 和 `StopLossDecrease`；`MarketIncrease` / `MarketDecrease` 遇到同类业务错误时终态为 `Cancelled`，不得写成 `Frozen`。

| 执行分类 | 必须单独设计的原子用例 | 期望状态 |
|---|---|---|
| 未进入履约校验 | 触发价未达到；`validFromTime` 未到 | 执行交易 revert，订单保持 `Open` |
| 系统性不可执行 | Oracle 错误、`DisabledFeature`、回调/取消/自动取消 Gas 不足 | 执行交易 revert，订单保持 `Open` |
| 增仓容量在等待期间变化 | `MAX_POSITION_SIZE_USD`、`MAX_OPEN_INTEREST`、`MAX_OPEN_INTEREST_FACTOR`、`RESERVE_FACTOR` 分别设计；创建时可履约，触发前由其他仓位或同一目标仓位占用余量 | 触发后为 `Frozen` |
| 增仓履约条件在等待期间变化 | acceptablePrice 失效、抵押不足、费用/Funding 导致仓位风险校验失败、市场被禁用 | 触发后为 `Frozen` |
| 减仓履约条件在等待期间变化 | acceptablePrice 失效、实际输出低于 `minOutputAmount`、无法支付费用/亏损、取出抵押后不安全、剩余仓位风险校验失败、市场被禁用 | 触发后为 `Frozen` |
| 非市价订单的明确例外 | `EmptyPosition`、`EmptyOrder`、`InvalidKeeperForFrozenOrder`、`UnsupportedOrderType` | 执行交易 revert，订单保持原状态 |
| 结构性无效 | `InvalidPositionMarket`、`InvalidCollateralTokenForMarket`、`InvalidPositionSizeValues` | `Cancelled` |

凡功能存在“创建态—等待态—执行态”的时间间隔，必须对每一个适用的 `Frozen` 原因单独登记“触发时执行失败”用例；不得用一条“容量不足”或“订单冻结”合并不同公式和错误来源。恢复流程可使用一个代表性 `Frozen` 原因，但必须拆成三条独立用例：容量/条件恢复后由 `FROZEN_ORDER_KEEPER` 重试、用户更新订单解除冻结并补足 Execution Fee、用户取消冻结订单。

每条 `Frozen` 原子用例统一核对：

- 订单仍存在且 `isFrozen=true`，`executionFee=0`；产生 `OrderFrozen`，`reasonBytes` 能解析为本用例的精确 error selector 和参数，不产生 `OrderExecuted` / `OrderCancelled`。
- 执行子调用的 Position、OI、Funding 和余额变化全部回滚；增仓订单的初始抵押仍留在 OrderVault；`autoCancel` 关联不得被误清理。
- 前端在约定的同步时间内，在同一笔 orderKey 上显示“已冻结”、本地化的准确原因、实际冻结时间和冻结交易；刷新后状态不回退，不得误用创建交易/创建时间代替冻结证据。
- 前端只显示实际可用的更新/取消动作，不得显示为已成交或已取消；若提供更新入口，必须重新计算并允许补足已在冻结时归零的 Execution Fee；不得显示实际不存在的用户重试入口。

### B. 开仓、关仓、仓位调整与主单取消（92 条原子用例）

> 执行前从当前市场配置读取：最小允许杠杆 `L_min`、最大允许杠杆 `L_max`、`MIN_COLLATERAL_USD`、`MIN_COLLATERAL_FACTOR`、Position Fee、UI Fee、Execution Fee、抵押品价格与 decimals。对固定 size 计算本次开仓的有效最小抵押 `C_eff`；`C_eff` 必须同时满足固定最低抵押、最低保证金率、费用和精度取整。不得把某次部署示例值写死为长期需求。

`C_eff` 的测试数据准备口径：先按 `max(MIN_COLLATERAL_USD, sizeInUsd × MIN_COLLATERAL_FACTOR)` 得到费用前最低有效抵押 USD，再加入开仓后会从抵押中承担的 Position Fee、UI Fee、Funding Fee 等成本，最后按 collateral price 和 token decimals 向风险侧取整。该值只是链下造数结果，执行时仍以合约 `remainingCollateralUsd` 与 collateral sufficiency 校验为最终权威。Execution Fee、Relay Fee 若从钱包单独支付，只进入总 Pay/余额校验，不混入仓位 collateral。

**原子与分层执行约定（2026-09-02）**

- 一行 = 一个链上动作的原子。同一原子带三组核对点：合约层（Order/Position/OI/账本/事件/公式）、前端层（表单、预览、签名弹窗、Toast、仓位行）、交叉一致（页面提交参数 = OrderCreated = Reader = 余额差分）。原子身份用 orderKey；同一原子同一数据集的前端层证据后补时挂到同一条记录，不重跑合约层。
- 入口二选一：`RPC`（私钥签名 createOrder + Inline Keeper 执行）或 `页面`。RPC 入口只能把合约层记 PASS，前端层记 GAP，交叉一致不判；只有页面入口能记前端层与交叉一致。ID 前缀 XT/FT 表示该行设计的完整核对面，不表示本轮必须走页面。
- 先跑合约层：本轮所有 XT 行先以 RPC 入口在 tx-fork 执行；FT 行与 XT 行的前端层等 `tx-fork:frontend` 准入（06 §5 C-2）后按同一原子补跑。
- 环境：tx-fork Mock token；两个现有市场的 index token 均为 18 位口径，18 位精度行用 market 2，8 位精度行 BLOCKED 待 8 位 Mock 市场；其余行默认主测市场 market 2；触发类行用 Mock Oracle 推价（min=max），不需要 oracle-fork；只有 XT-LMT-TIME-012 涉及时间。
- 地址：每条写链用例分配一个独立测试账户（见 B1～B4 用例表）；只做表单校验、不创建订单的前端用例可共用前端探针账户。执行前按用例要求注资并设置 allowance，数据集之间使用 snapshot/revert；账号映射以本矩阵用例 ID 为键，不复用或依赖其他测试体系的编号。
- §4 的 OT-MI-001/002、OT-LI-001/002 与本节 XT-MKT-OPEN-001/002、XT-LMT-OPEN-001/002、XT-LMT-TRG-007/008、XT-LMT-ACC-015 是同一动作：§4 行引用本节原子与数据集，不单独执行，一次执行两处断言。
- 第二批（需新增驱动）：XT-LMT-UPD-013（updateOrder）、XT-LMT-CAN-014（cancelOrder）；含快速交易数据集的行（FT-MKT-COL-012、XT-LMT-CAN-014）拆出快速交易（Flash）组，等待 Relay 驱动与 `tx-fork:frontend` 准入。标准交易（Standard）/快速交易（Flash）对比、方向、TP/SL 与费用不足组合统一在快速交易与代付费专项设计，不在 B 节重复。

**开仓与关仓成对执行约定**：市价关仓是被测功能，不是环境清理。每条成功开仓用例的自动化必须继续执行对应市价关仓；开仓与关仓分别保留独立 ID、测试标题和断言，但共享同一次自动化、同一测试账户、同一 snapshot 及前后态证据。只有开仓和对应市价关仓都通过，整条自动化流程才通过。

- B1 将每条成功的市价开仓与一条显式 `XT/FT-MKT-CLOSE-*` 用例配对。市价关仓用例核对 Est. Receive（页面入口）、`MarketDecrease` 创建与执行、Position 删除、对应方向 OI 回落、PnL、Funding Fee、Position Fee、UI Fee、Execution Fee、适用时的 Relay Fee，以及钱包/Vault 余额差分。
- 带 TP/SL 的配对市价关仓用例必须在关仓前确认保护单为 `Open`，并在全平后确认所有保护单同流程自动取消、`autoCancel` 列表清空、退款正确且 Keeper 不能再次执行残单。
- B3/C 中的“市价关仓标准操作”与“市价关仓并校验保护单自动取消”均是被测功能阶段，不是测试清理；断言口径与 B1 的显式市价关仓用例一致。
- “取消订单标准操作”用于尚未触发的条件单：取消订单并核对 Store 删除、抵押品/Execution Fee 退款、无仓位与无残单。
- “无关仓动作”用于提交前拦截、执行失败或无仓位数据：不提交 `MarketDecrease`，仅确认 Position、OI、Order 与余额没有非预期变化。

TP/SL 价格校验中的 `P_ref` 是页面本次校验与构造 payload 使用的同一笔新鲜 Oracle 参考价；每个数据集必须记录其原始精度值，不能用截图中的舍入显示值代替。
