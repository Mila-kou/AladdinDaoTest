# 后续用例实施约定

## 1. 场景映射

- 一个自动化测试必须对应一个现有 Case ID：共享场景 `SCN-xxx`（80 条，跨版本）或版本功能用例 `CT|XT|FT-…-xxx`（来源 `TestCase/E2E/versions/<release>/Trade-测试用例矩阵.md`，结果记同目录 `results.md`）；CT/XT/FT spec 不要求对应某条 SCN，两类用例的双向映射待代码化阶段 E 的 case-registry 统一提供（ID 分类见 CLAUDE.md 测试标准第 2 条）；
- 数据驱动子边界必须在报告中保留独立结果：同一 Case ID 下的参数样本用 `variantId`、每次执行用 `executionId` 区分；
- 不创建脱离测试设计文档的新编号（SCN 不再增号，版本新增功能只进矩阵文件）；
- 具体用例代码在环境准备完成后再确定。

每条用例必须填写结构化执行环境：`targetProject`、`marketMode`、`oracleMode`、`marketCompatibility`、
`timeMode`、`signingMode`、`mockResourceAlias` 和 `environmentSetup`。

- `dev-readonly`、`base-sepolia` 不初始化 Mock 合约；
- `tx-fork`、`oracle-fork`、`time-fork` 初始化时默认部署一套完整的 Market Bundle：专属 Index Token/Oracle、共享 USDC/Mock Oracle、Synthetic Market 和 Market 参数；
- 默认资源统一登记为 `default-mock`，地址只从 `config/mock-resources.json` 解析；
- `project` 与 Mock 能力是两个维度：例如 SCN-009 是 `tx-fork + default-mock`，SCN-010 是 `oracle-fork + default-mock`；
- 所有交易和链上数据核对默认使用 `mock-market + mock-oracle + default-mock`；
- `marketCompatibility=mock-and-deployed` 才允许在创建运行时切换到已部署 Market + 非 Mock Oracle；
- 依赖价格控制、Market 参数、时间推进、Funding/清算/触发精确边界的用例必须标为 `mock-only`；
- `deployed-only` 用于共享环境页面检查或 `base-sepolia` Service Keeper/标准 Market 专项，不能作为私有 Fork 交易用例的默认值；
- 新 Fork 初始化必须使登记表达到 `market.status=registered`；旧登记若仍为 `unregistered`，应重新运行一体化初始化或显式走兼容绑定流程。

## 2. 分层边界

| 层 | 职责 |
|---|---|
| Page/Component | 定位页面元素并执行单一 UI 动作 |
| Flow | 组合交易员业务流程 |
| Driver | 控制 Fork/Oracle/Keeper，读取协议状态 |
| Model | 独立 BigInt 预期值，不能调用生产 SDK 复制答案 |
| Assertion | 页面、Reader、事件、余额多源核对 |
| Reporter | 按 SCN 汇总证据和状态 |

页面/钱包体验场景必须走页面；协议交易与数据核对场景直接发送 Trader/Keeper 的真实签名交易，不依赖前端加载。Driver 负责恢复 baseline、准备余额、设置 Mock Oracle、推进时间、Inline Keeper 和读取链上状态。

## 3. 标签

计划使用：

```text
@p0 @p1 @p2
@readonly @tx @oracle @time @funding @liquidation
@mobile @wallet @fault @serial
```

## 4. 精度与等待

- USD/Factor 使用 `1e30`；Skew 使用 `1e18`；
- 合约整数用 BigInt 精确比较；
- 只有页面格式化允许明确的小数误差；
- 不使用 JavaScript Number 计算资金；
- 不使用固定 sleep 等交易；
- 每条写状态用例执行前后验证 baseline。

## 5. 结果附件约定

场景需要通过 `testInfo.attach()` 提交结构化证据，Reporter 只记录附件名称、类型和相对路径。现行附件命名（2026-08-11 按实际实现回写，SCN-009/010/070 已统一采用）：

```text
scn-<xxx>-evidence.json            # 全量证据：快照、Δ、断言、事件、覆盖声明；
                                   # execution-evidence.ts 的 EVIDENCE_SOURCES 按此名展开对账行，改名须同步
tx-and-receipt.json                # 业务交易与回执（三条用例通用）
reader-ledger-before-after.json    # 账本快照 before/after/Δ 与守恒观察（SCN-009/010；010 版含 prices）
acceptable-price-boundaries.json   # 可接受价矩阵、边界数值与断言（SCN-070）
page-final.png                     # 页面终态截图（浏览器链路覆盖后启用）
<CaseID>-<env>-r<重试>-<序>-<caseid小写>-evidence.json
                                   # 版本功能用例（CT/XT/FT）全量证据（2026-09-02 起，如
                                   # XT-MKT-OPEN-001-tx-fork-r0-0-xt-mkt-open-001-evidence.json）；
                                   # 由 runMarketFlow v1 产出，核对侧经 market-flow-v1 Adapter 转 Evidence V2 回放
```

Evidence V2（08 §3.2）落地后，附件名不再承担"按用例编号选派生器"的职责，核对包按 `flowType + capabilities` 选择；附件名只用于定位文件。

早期约定的 `reader-before.json` / `reader-after.json` / `market-state.json` / `position-fees.json` / `oracle-state.json` 已合并进上述附件，不再单列；新增用例沿用现行命名，如需新附件名先在此登记再消费。

附件不得包含私钥、Tenderly access token 或带凭证的 RPC URL。看板负责汇总，Playwright 原生报告负责打开 Trace 和步骤级附件。

## 6. 首批框架验证场景

环境准备完成后，优先评审而不是立即编码以下四条：

1. SCN-009：TX_FORK 市价开仓和平仓；
2. SCN-069：ORACLE_FORK 触发价 `±1`；
3. SCN-075：TIME_FORK Funding/EMA 时间；
4. SCN-079：TIME_FORK + Mock Oracle 的 Funding-only 清算。

这四条可以验证页面、钱包、合约、Keeper、Oracle、时间、Reader/Indexer 和证据系统是否闭环。

## 7. 看板运行批次约定

- 用例库负责筛选、单选和多选；“测试运行”页面负责版本、环境、RPC 和最终执行确认；
- 默认 Market 资源按用例配置执行；切换标准 Market 时，服务端必须再次拒绝任何 `mock-only` 用例；
- 未覆盖环境时，每条用例使用自己的 `targetProject`，并按环境串行分组；
- 覆盖环境时必须先核对交易、Oracle、时间能力是否满足所有选中用例；
- 留空 RPC 使用 `.env.local` / `.env` 中现有配置；填写新 RPC 会更新所选环境对应变量并立即用于本次运行；
- 私有 Fork 可让 Admin RPC 与主 RPC 共用同一 Tenderly 端点，也可以单独配置；
- 运行批次保存在 `artifacts/run-batches/<run-id>/run.json`，不得包含完整 RPC、私钥或 access token；
- 运行批次必须记录 `plannedMarketMode`、`resolvedMarketMode`、`resolvedOracleMode`、`resolvedMockResourceAlias` 和 `marketCompatibility`，并通过 `E2E_MARKET_MODE` / `E2E_MARKET_RESOURCE_ALIAS` 传给测试进程；
- 看板服务只允许同源页面创建运行，并且一次只执行一个批次；
- 未实现自动化代码的用例记录为 `NOT_AUTOMATED`，不能因为被选中就视为 PASS、SKIP 或已验证；
- `NOT_AUTOMATED`（还没写，是欠账）与 `MANUAL`（设计上不写，永久人工）严格区分：手工核对用例在用例库的"执行方式"里标记，创建运行时状态直接落 `MANUAL`，不进入 Playwright 执行集合、不要求该环境的 RPC，也不计入自动化覆盖分母；批次里只要还有未回填的手工用例，批次状态最高只能是 `PARTIAL`。
