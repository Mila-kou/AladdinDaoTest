## 版本与变更规则（"后续补充或调整可以有依据"）

1. **新增一批用例 = 新版本目录**（v3/…），README 索引登记设计日期与依据来源（需求清单/缺陷/口径变更）。
2. **版本内修订**：直接改该版本文件，并在文件尾部"变更日志"表追加一行（日期/改了什么/依据——如评审意见、缺陷复现、口径修正、执行回写）。
3. **执行回填**：实际结果不写进用例库，写执行会话（manual-runs/<日期>/）并在状态列引用 `v2/CMB-A-001` 式全名；用例因执行发现需修订时按第 2 条回写并注明来源 LOG 编号。
4. 依赖口径（费率/清算/保护/哨兵等）以 OPERATION-LOG 定案与 `Docs/contract-releases/CURRENT.json` 基线为准；口径变化时受影响用例在变更日志标注。
