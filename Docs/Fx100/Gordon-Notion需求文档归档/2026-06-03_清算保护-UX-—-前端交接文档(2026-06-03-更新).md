## 概述
FX100 核心差异化特性：**每笔新开仓自动获得 15 分钟免费清算保护**。本次前端工作完整实现了该特性的 UX 体验，包括右侧 Protection Card、图表区 Protection Tab 以及完整的 5 状态机。
**分支**: `feat/liquidation-protection-ux`（基于 `feat/gordon1-fork-e2e-testing`，已合并 `develop`）
**GitHub**: [https://github.com/AladdinDAO/fx100-apps/tree/feat/liquidation-protection-ux](https://github.com/AladdinDAO/fx100-apps/tree/feat/liquidation-protection-ux)

保护状态从 `position.graceStart` / `position.graceEnd`（合约写入的 unix timestamp）实时推导，无需单独维护倒计时 atom。
### 2. Protection Card（右侧订单表单底部）
替换原有的静态 `LiquidationProtectionCountdown`：
- **等高设计**：5 状态卡片高度一致，不跳动
- **PnL 为主角**：PnL 区域 `flex:1`，28px 大字，随价格实时更新
- **Promo 态**：盾牌 SVG（15:00 + 辉光动画）+ 概念图
- **Danger 态**：红色脉冲边框，Add Margin CTA
- **Expired 态**：`hadDanger` 判断—节省了 \$X 或干净收尾
### 3. Price / Protection 图表 Tab（左侧图表区）
**Price tab**：原 TradingView widget，零改动
**Protection tab** Canvas 迷你图：
- Y 轴自适应缩放（根据 liqGap 决定范围）
- X 轴右侧 15% 留白
- Polymarket 风格渐变填充
- 价格历史用随机游走播种（避免切换仓位时锯齿）
- HiDPI/Retina 适配
- Shield 徽章（右上角）+ PnL 徽章（跟随绿点移动）
- 5 状态 overlay
- 底部 strip：方向额色（Long 绿/Short 红）+ 真实杠杆倍数
### 4. 多仓位选择
- 点击 Positions 表格行 → 切换显示的保护状态
- 有效保护期内 → 切到 Protection tab
- 已到期 → 切到 Price tab + 右侧卡片回到 Promo
- 默认选中：最近开仓且保护期有效的仓位
### 5. i18n
全量中英文，键下 `trade.protection.*` 和 `trade.chartTab.*`，覆盖 EN/ZH/KO/JA。

## 待完成事项（前端工程师续做）
### 🔴 高优先级
#### 1. Roll 一键续仓
用户点击 Expired 态的「Roll Position · Renew Shield」，期望：
1. 自动提交全仓平仓订单（Market Decrease 100%）
2. 平仓提交后自动填入订单表单（同方向/杠杆/保证金）
3. 用户点 Open Long/Short 开仓（共 **2 次点击**）
实现思路：
- 新增 `rollPresetAtom: { direction, leverage, collateralUsd } | null`
- Roll 按钮 → 调用 `submitDecreaseOrder` 提交全平
- 平仓成功 → 设置 `rollPresetAtom`
- `OrderForm.tsx` 监听该 atom → `useEffect` 自动填入 leverage + size
- 保证金从 `positionsInfoDataAtom[positionId].collateralUsd` 读取
#### 2. Add Margin 按钮接入
Danger 态的 CTA 有 `onAddMarginClick` prop，需要在 `OrderForm.tsx` 打开 `PositionMarginDialog`。
参考 `Positions.tsx` 中的已有实现。
#### 3. Open 100x CTA 接入
Promo 态的按钮有 `onOpenLongClick` prop，需在 `OrderForm.tsx`：
- leverage slider 设为 100x
- 方向设为 Long
- size 输入框聚焦
### 🟡 中优先级
#### 4. Coverage 金额准确化
当前用 `position.sizeUsd`（名义价值）代替保证金。
准确值：`formatUnits(positionsInfoDataAtom[id].collateralUsd, 30)`，参考 `derivePositionDisplayData` 函数。
#### 5. 计时器实际生效
确认合约端 `LIQUIDATION_GRACE_PERIOD_BASE` 已配置非零。若配置为 0，`hasGrace` = false，所有仓位显示 Safe（无保护窗口）且不会倒计时。
#### 6. 移动端适配
条件：`width < 768px`。需验证：
- Protection Tab canvas 高度（当前硬编码 `min-h-[470px]`）
- ResizeObserver 在移动端的表现
- 卡片布局在小屏上的阁读性
### 🔵 低优先级
#### 7. 去重 `fmt()` 函数
`ProtectionCard.tsx` 和 `ProtectionChartTab.tsx` 各自有一个 `fmt(sec)` 函数，可提取到 `src/lib/formatTime.ts`。

## 调试与测试（开发环境）
### 模拟保护状态
由于测试网价格真实波动，无法人为让价格击穿清算线。在浏览器 Console（`yarn dev` 模式）中调用以下函数，**立即切换状态**（无需等待）：
```javascript
// 模拟价格击穿清算线（Danger — 协议扛住中，红色脉冲）
window.__setProtectionDebug('danger')

// 模拟价格回升（Recovered — 胜利态，显示节省金额）
window.__setProtectionDebug('recovered')

// 模拟保护到期 + 曾击穿（Expired saved — 节省了 $X）
window.__setProtectionDebug('expired')

// 模拟正常保护中
window.__setProtectionDebug('safe')

// 恢复真实状态
window.__setProtectionDebug(null)
```
**注意**：
- 只在 `NODE_ENV=development` 下生效，生产构建完全剥除
- 需要先有持仓（非 Promo 态）才能看到 Danger/Recovered/Expired 效果
- 切换到 Protection tab 后再调用，效果最直观
- 直接赋值 `window.__protectionDebug = 'danger'` **不会立即生效**，请使用 `__setProtectionDebug()`
### Canvas 图表常见问题
**齿状/重叠线条**：由两个原因导致，均已修复：
1. `ctx.clearRect` 必须在 `ctx.scale(dpr, dpr)` **之后**调用，否则在 2× Retina 屏上只清除 1/4 画布，导致旧帧叠加
2. 画图时对历史数组最多取 100 个均匀采样点，避免 oracle 数据密度过高产生密齿
