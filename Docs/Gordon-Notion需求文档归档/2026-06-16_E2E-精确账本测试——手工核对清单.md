## 精度规则速查
```plain text
sizeInTokens = SIZE / (normalizedPrice)
  ETH: SIZE / 2_000e12  (e.g. 50_000e30 / 2_000e12 = 25e18)
  WBTC: SIZE / 60_000e12 (oracle 乘数 1e12，与 ETH 相同)

pnl = sizeInTokens × priceDiff / 1e24
  e.g. 25e18 × 100e12 / 1e24 = 2_500e6 = 2500 USDC

funding fee = sizeInTokens × Δ(negFundingPerSize) / FLOAT_PRECISION / USDC_PRICE
  其中 USDC_PRICE = 1e24

spread: 用 WEI_PRECISION(1e18)，1% = 1e16

fee = mulDiv(SIZE, feeFactor, FLOAT_PRECISION) / USDC_PRICE

清算方向：trader 收剩余保证金，LP 承担 PnL 损失（非直觉，已实测验证）
风控超限：订单静默取消+退款，非 revert（OrderHandler try/catch）
```

### 核心业务规则
\*\*完整费用路径（3步，后2步均为手动）\*\*：
```plain text
① 交易执行时（自动）：
   FeeUtils.incrementClaimableFeeAmount()  → 只写 DataStore 计数器
   USDC 不动，仍在 posVault

② 手动触发（任何人，per market）：
   feeHandler.claimFees(marketIndex, token) → posVault → feeHandler 合约
   availableFeeAmountKey(token) 累加（跨 market 聚合，per-TOKEN）

③ 手动触发（FEE_KEEPER only，per token）：
   feeHandler.withdrawFees(token)           → feeHandler → admin(FEE_RECEIVER)
   一次取走所有 market 的累积费用
```
\*\*多 market 规则\*\*：N 个 market → N 次 \`claimFees\` + 1 次 \`withdrawFees\`（aggregated by token）
\*\*权限说明\*\*：
\| 函数 \| 权限 \| 备注 \|
\| \`feeHandler.claimFees(mi, token)\` \| 无（任何人） \| 只移 USDC 到 feeHandler，无安全风险 \|
\| \`feeHandler.withdrawFees(token)\` \| FEE_KEEPER \| 未授权 → \`FxErrors.Unauthorized(caller, Role.FEE_KEEPER)\` \|
\| \`exchangeRouter.claimUiFees(...)\` \| 无（任何人） \| \`msg.sender\` = uiFeeReceiver，随机调用只拿自己桶（=0） \|
\| 授权方式 \| admin only \| \`dataStore.grantRole(Role.FEE_KEEPER, address)\` \|
\*\*UI fee vs position fee\*\*：同源（trader collateral），路由到不同桶：
- position fee → \`claimableFeeAmountKey(mi, token)\` → claimFees
- UI fee → \`claimableUiFeeAmountKey(mi, token, receiver)\` → claimUiFees

\`cancelled\`，\`cancelReasonCode: Panic\`，\`cancelReasonArgs: \['0x11'\]\`（算术下溢/溢出）。仓位未变、全额退款（watch 已验证 cancel+refund 路径正确）。
\*\*覆盖盲区\*\*：原 Foundry 部分平仓测试（G1-S7/S8）\*\*只测 LONG\*\*，从未测过 SHORT 部分平仓。
\*\*复现测试\*\*：\`test/e2e/accounting/phase1/P1_ShortPartialClose.t.sol\`

- SPC-3（SHORT 50x + 3天资金费）✅ PASS
- control（LONG 部分平仓）✅ PASS
\*\*结论\*\*：clean 参数（\`_setupCleanParams\` 把 spread/impact/skew/费率都清零）下 \*\*无法复现\*\* —— 核心 short 部分平仓逻辑本身是对的。Panic 由\*\*线上 v0.2.0 部署的真实市场参数\*\*触发，最可能是 \*\*price impact / skew impact\*\* 或部署的 \*\*funding factor 量级\*\*与 50x 薄保证金 short 在部分减仓时的交互。
