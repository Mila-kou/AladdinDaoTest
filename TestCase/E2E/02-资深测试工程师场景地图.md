# 资深测试工程师风险场景地图

## 1. 测试工程师不会只验证 Happy Path

资深测试工程师会先建立状态机、资金语义和数据源，再沿用户旅程施加边界和故障。

| 测试模型 | 关键问题 | 对应场景 |
|---|---|---|
| 订单状态机 | 创建、等待、执行、取消、冻结、重试是否只有合法迁移 | SCN-009～020、059～062、065～072 |
| 仓位状态机 | 新开、加仓、部分平、全平、Funding 结算、清算、ADL 是否一致 | SCN-021～044、065～068、072、073～080 |
| 边界值 | 100x、最小抵押/仓位、触发/可接受价、Funding Factor/EMA/Clamp、保护期 | SCN-033～042、068～070、073～079 |
| 资金语义 | 退款、不退款、到账、费用、Funding 是否可解释 | SCN-018～020、021～032、045～049、070～080 |
| 时间 | validFrom、keeper 超时、graceEnd、Funding 按秒累积/EMA、授权到期 | SCN-013、039～042、045～047、058～061、073～075、077、079 |
| 故障注入 | RPC、oracle、keeper、indexer、钱包拒签后能否恢复 | SCN-059～062 |
| 多源一致性 | UI、Reader、tx、indexer 是否同一业务事实 | 全部 P0/P1 交易场景 |
| 幂等并发 | 双击、刷新、重复执行、Cancel All 是否造成重复状态 | SCN-017～020、056、059～062 |
| 安全与隐私 | Flash consent、授权、账户/设备切换、撤销是否隔离 | SCN-053～058、064 |
| 精度兼容 | BTC 8 位输入 vs 内部 18 位、USDC 非 1 美元 | SCN-032、043、052 |

## 2. 重点决策表

### 2.1 订单失败语义

| 触发原因 | 期望订单 | 期望资金 | 用户动作 |
|---|---|---|---|
| 风控/OI/储备/最低抵押拦截 | Cancelled/删除 | 全额退款 | 修正参数后新建 |
| 市价滑点不达 | Cancelled/删除 | 退款 | 更新行情后新建 |
| 触发单执行价格保护失败 | Frozen/保留 | 不退款 | 调整或重试 |
| Oracle 过期/偏离/Sequencer 故障 | 原状态保持 | 不变化 | 等价格源恢复后重试 |
| Keeper 暂停 | Pending/Waiting | 不变化 | 等待，不重复下单 |
| 用户主动撤单 | Cancelled/删除 | 退款 | 无 |

### 2.2 四象限执行价

| 操作 | 取价方向 | 测试重点 |
|---|---|---|
| 开多 | ask、向上取整 | 成交价对用户不利；市价滑点上界 |
| 平空 | ask、向上取整 | 平仓到账和可接受价方向 |
| 开空 | bid、向下取整 | 成交价对用户不利；市价滑点下界 |
| 平多 | bid、向下取整 | 平仓到账和 Price Impact |

### 2.3 触发订单矩阵

| 订单 | 多头条件 | 空头条件 |
|---|---|---|
| 限价开仓 | oracle ≤ trigger | oracle ≥ trigger |
| 突破开仓 | oracle ≥ trigger | oracle ≤ trigger |
| 止盈 | oracle ≥ trigger | oracle ≤ trigger |
| 止损 | oracle ≤ trigger | oracle ≥ trigger |

每个条件至少覆盖：未到、恰好等于、越过最小价格单位；并验证触发价不是最终成交价上限。

完整 8 个方向 × 3 个边界的必做数据集见 SCN-069；市价开平四象限的 `acceptablePrice` 边界见 SCN-070。

## 3. 组合风险优先级

单因子通过不代表组合安全。以下组合必须优先：

1. 高杠杆 + 开平仓费 + Dynamic Spread + 浅流动性。
2. 价格下跌 + Funding 侵蚀 + USDC 脱锚 + 保护期临近到期。
3. 限价触发 + keeper 延迟 + oracle 更新 + 用户同时撤单。
4. 全平 + 多条 TP/SL autoCancel + indexer 延迟。
5. Flash 连续下单 + relay 超时 + 页面刷新 + 重复点击。
6. BTC 市场 + Token Mode + 触发单 + 部分平仓。
7. 多账户/多设备 + 保持连接 + consent 版本升级 + 撤销。

## 4. 当前已知风险进入 E2E 的方式

| 风险 | E2E 处理 |
|---|---|
| Dynamic Spread 负值尚未合入 | 当前行为回归 + 目标行为 `PENDING` 双轨记录 |
| R5-B02 低深度下指数可能阻断清算 | SCN-049/044/068 组合，并明确执行多空两个清算方向，作为 P0 安全回归 |
| Flash 文档存在旧/新生命周期冲突 | SCN-053～058 先读取部署版本，再按权威目标判基线差异 |
| Relay cancel/慢签过期历史问题 | SCN-056、059～061 回归 |
| Oracle 与 K 线更新不同步 | SCN-001、009、060，分别标注用途而非要求瞬时相等 |
| BTC 精度历史回归 | SCN-052 覆盖下单、触发、持仓、PnL 和平仓全链路 |
| Short 部分平仓 + 正 Funding 历史 Panic | SCN-030、047、077～078 组合回归 |

## 5. 自动化建议

- 真实环境 smoke：SCN-001、005、009、021、024、037、053、059、065、080。
- 可控价格环境：SCN-010～016、033～052、066～072、079。
- 可控 Funding/OI/EMA 环境：SCN-073～079；SCN-078 必须使用可独立读账本的 fork/fixture。
- Mock UI 自动化：输入边界、状态可见性、弹窗、i18n、移动端。
- 合约/账本引用：所有精确资金、Funding、费用、清算和 ADL 断言；页面层只做双源回显，不重复发明精确公式。

## 6. 缺陷判定原则

- 页面显示错、状态迁移错、资金语义错、重复下单或跨账户泄露：`FAIL`。
- 外部依赖不可用且页面正确降级：执行 `BLOCKED`，产品降级行为可单独判 PASS。
- 需求未定或目标方案未合入：`PENDING/EXPECTED-FAIL`，不得伪装成普通通过。
- 只有截图、没有 tx/Reader 证据的资金类结论，不具备通过资格。
