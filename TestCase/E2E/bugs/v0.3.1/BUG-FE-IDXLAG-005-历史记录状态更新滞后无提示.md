# BUG-FE-IDXLAG-005 · 历史记录状态更新滞后无提示

## 现象与时间线（2026-08-28 实测）

链上/keeper 侧 16:47-16:50 连续发生三笔执行：LINK 开仓执行（16:47:16）、ETH SL 触发执行（16:48:22）、BTC 清算（16:49:50）。但前端：

- ~17:02-17:08 读取时：Trade History 最新仍停在 16:14:12（三笔执行均无记录）；Orders History 中 TP/SL/LINK 三条订单状态停留 **Created**；
- ~17:1x 后记录才回填（TP→Cancelled、SL→Executed、LINK→Executed、BTC Liquidation 出现）；
- 滞后期间页面**无任何"同步中/数据延迟"提示**，历史与订单列表以"当前完整数据"的姿态展示陈旧状态。

## 影响

- **主要用户感知面 = TP/SL 订单状态流转滞后**：SL 已在链上触发执行、TP 已同 tx 自动取消（16:48:22 落块），但订单历史里两条订单在其后 15-25 分钟内始终显示 "Created"——执行人在仓位消失后无法从页面得知"仓位为何消失、哪条订单执行了"（本次实际遭遇，用户明确困惑）；
- 与 E2E-TRD-052 的期望结果冲突："页面不把索引延迟说成链上失败；**有加载/同步提示**；索引恢复后与链上终态一致"。终态一致 ✓ 满足，同步提示 ✗ 缺失。

## 期望

历史/订单列表存在索引滞后时给出可见的同步状态提示（如"数据同步中，最新交易可能延迟显示"），或缩短索引延迟。

- 对照：当日早间记录（15:42 平仓）近实时出现；2026-08-04 历史 TP/SL 成对流转正常——说明链路正常时延迟很小，本次为明显退化窗口。
